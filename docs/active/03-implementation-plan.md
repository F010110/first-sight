# 空间记忆实施计划与未决能力

更新：2026-11-02。状态：**计划，未全部实现**。当前进度与运行结果看 [TODO.md](../../TODO.md)；架构契约看 [01](01-spatial-memory-architecture.md)，设计理由看 [02](02-design-rationale.md)。本文只记录已确认的实施方向、明确不采用的做法和实施顺序，不因代码现状降低要求。

## 0. 运行框架：Pi agent core、Session 与 Skill

**确认结果：不是全部满足。** 现有用户问题 harness 使用 Pi `AgentHarness`、`JsonlSessionRepo` 会话和 skill 加载；但新空间记忆主链目前是直接模型调用＋应用自有动作循环，没有 Pi Session，也没有把空间行为封装成 skill。这个缺口补为全量前 P0。

要求：

- 空间Agent基于 Pi agent core 运行，拥有自己的持久 Session（短期间隔的工具调用/观察轨迹），而不是每帧独立无状态请求。
- 空间行为放在 `skills/first-sight/<name>/SKILL.md`，通过 `loadSkills` 加载，记录内容 hash 到检查点；skill 可新增、编辑、删除，但只影响之后的会话，不重写历史检查点。
- 角色白名单必须显式允许新 skill：当前问题Agent只允许固定几个 skill，新增文件不会被自动暴露给所有 Agent；增删改 skill 时同步调整白名单与测试。
- Pi Session 只承担执行轨迹与短期Context压缩；长期空间库仍由应用 SQLite 持有并事务提交，不能把 Pi 会话当作长期记忆。
- Session 达到预算时按默认规则 compact，保留最近尾部、当前观察、来源与未决点；长期证据不进入摘要替代品。
- 应用自有 WorkingContext 仍作为空间判断的显式输入，避免旧版“全历史会话压过当前观察”的回归；Pi Session 与 WorkingContext 的职责必须写入测试。

## 1. 经历片段、事件、实体索引

**结论：此前没有真正可用的实现，不能算已恢复。** 旧组织库有契约与文字启发式，但没有接入实时空间链，也没有可靠证据门禁。

原则：**Agent 提出语义，程序只做机械存储、来源校验和版本化。** 不使用固定秒数、词项或相似度自动切片段、造事件或合并实体。

### 1.1 经历片段

- 片段表示一段连续经历，可跨越多个区域，不等于地点。同一地点多次到访必须是多个片段/访问。
- 机械默认：录制连续且无时间断档时，新观察延续当前开放片段。
- 片段开始、结束、合并、拆分由 Agent 附证据提交；缺证据时保持开放或未知。
- 保存起止、成员、摘要、开放/关闭状态、修订与来源；片段序号不得当作进入次数。

### 1.2 事件

- 只记录有来源的候选：进入/离开区域、区域变化、物品出现/消失、门态变化等。
- 每条事件含类型、发生观察、涉及区域/实体、证据来源、确认程度。
- Agent 提交，程序验证来源属于当时可用证据；不能把“看见店面”自动升级为“进入店铺”。
- 事件可修订或撤回，保留原记录。

### 1.3 实体

- 实体是 Agent 提出的具名对象或设施，例如某家店、柜台、设备。
- 保存实体提及、别名、关联区域、首次/最近来源与证据。
- 程序只合并完全相同的规范化名称＋类型＋区域；相似外观或类别词不能自动合并。
- 实体链接可修订、可撤回。

### 1.4 索引与查询

- 新增机械表：`episodes / episode_members / episode_revisions`、`events / event_revisions`、`entities / entity_mentions / entity_links / entity_revisions`。
- 查询只提供按时间、片段、事件、实体列出来源；语义判断仍由 Agent 做。
- 所有派生索引可重建，原始观察与空间判断不可被索引覆盖。

## 2. 地点合并、拆分、层级

**结论：已有地点判断，合并/拆分可参考早期 `spatial-topology-service.ts` 的 merge/split/confirm/undo；但实时版本曾出现自动相似合并、窗口别名重绑和旧判断被新窗口覆盖，不能原样搬运。**

### 2.1 合并

- Agent 提出两个已有地点为同一区域，附实际检查过的双方来源。
- 程序验证证据、版本、因果时间后追加合并记录。
- 合并从指定版本起生效；旧时刻快照保留原归属，不重写历史。
- 查询区分“原始归属”和“按合并记录投影后的身份”。

### 2.2 拆分

- Agent 明确列出要拆出的观察/访问集合及依据。
- 程序创建新地点，追加这些观察的重新归属修订，并记录拆分来源。
- 不按时间阈值或描述差异自动拆；旧时刻、旧证据不变。

### 2.3 层级

- 增加设施/上层场所实体，地点可声明所属设施。
- “同设施不同区域”“相邻”“连通”分开记录；同楼不合并地点，不同区域不写“关系未知”。
- 层级断言版本化、可撤回。

### 2.4 明确禁止

- 相似装修、相同类别词、共用一帧不能自动合并。
- 新窗口不能反向改写旧时刻归属；只能追加修订。
- 合并不删除旧地点和旧访问，撤回是追加记录。
- 任何自动相似度只能作为候选提示，不能直接提交身份。

## 3. 关系撤回与修订历史查询

**结论：此前没有实现。**

- 关系有稳定 `relationId`、版本、状态；撤回追加 `relation_retractions`，不删除原关系。
- `relationsAt(version)` 返回当时仍有效的关系；`historyOf(kind,id)` 返回某地点/关系/观察的修订链及每次依据。
- 查询结果区分原始断言、后续合并投影、撤回状态。
- 评测和网页可展示“当时判断 → 修订 → 当前判断”，不只给最终结果。

## 4. 语义检索与候选召回

**结论：不做固定 `locate` 智能函数；让 Agent 自主翻阅经历。** 旧版失败点是词项命中被当目标已找到、预览被当读过、一次空搜索被当不存在。

保留并扩展机械能力：

| 操作 | 作用 | 边界 |
|---|---|---|
| `timeline` | 按时间分页遍历全部已提交记录 | 必须可翻完；预览只用于导航 |
| `read` | 读取指定范围完整文本 | 预览不能替代完整读取 |
| `around` | 查看某条记录前后邻居 | 只扩大上下文，不认证身份 |
| `episodes/events/entities` | 按片段、事件、实体列出来源 | 机械索引，不做语义判断 |
| `inspect` | 查看已交付记录的原图 | 必须先交付，有张数上限 |
| `coverage` | 报告已读文本、已看原图、未读范围 | 明确语义不完整 |

可选语义召回只能作为候选提示：返回多个时间分散候选，明确不保证穷尽，必须继续读文本/看图确认，不能直接成为身份或答案。

评测重点：Agent 是否在有限页数内自主找到目标、是否误停、是否把预览当证据；不以“函数命中”代替自主检索。

## 5. 压缩

**结论：压缩不只属于用户问题会话。短期Context总是要压缩；长期记忆不压缩。**

- 用户问题会话由**空间记忆模块＋用户问题模块**两个 Context 模块组合；两者分别达到预算/长度时按固定规则压缩，分别保留尾部、来源与未决点，不能互相覆盖。
- 空间短期Context也必须压缩：按容量与长度规则保留当前观察、当前位置、近期判断、锚点、本轮实际读回证据、活跃未决点和可恢复线索。
- 长期原图、观察、空间判断、地点/访问/经历/事件/实体、修订与来源不压缩，只按需检索。
- 压缩是工作摘要，不是新事实；压缩失败保留原上下文，不提交半份摘要。
- 压缩门槛、保留尾部长度、摘要长度是可版本化配置；不按题号或私有答案调整。

## 6. 正式用户问题 Agent 接入

**结论：先做通空间记忆，再接问答。**

- 独立问答会话；只读空间模块；不写空间库、不承担空间判断。
- 请求边界组合空间模块与私有问答历史；空间模块随提交推进，问答历史独立压缩。
- 检索、读文本、看原图分别记账；引用必须对应实际交付来源。
- 线上可读取最新可用版本；离线评测固定版本和知识截止，分支间不泄漏答案。
- Pi若保留，仅作为问答执行层与会话设施，不再定义空间记忆。

## 7. 并发、背压与 429

**结论：空间状态提交必须有序，不能靠无限加并发解决。**

- 原逐观察路径曾参考2路提取＋1路空间，不是账号配额或系统必需的最小并发。用户批准的窗口路径使用**1个整窗独立提取者＋1个空间推理者**；保留有用的跨职责流水，不同时运行两批空间判断。
- 问答独立串行、只读共享空间；不得因问答阻塞生产或让其结论写回观察。其并发额度单独配置，不恢复旧4路逐观察提取来堆并发。
- 旧实测参考：单次三摄提取 p50≈1.69s、p95≈3.04s；输入约1观察/秒。2路提取在p50够用、p95会积压；3–4路提取才有余量。
- 813帧30分钟目标要求空间推理平均≤约2.2秒/观察。若平均超过1次调用/观察，优先窗口化空间判断（连续2–4帧一次请求、逐帧assessment），而不是加并发。
- **2026-11-03用户批准的窗口模式覆盖上述逐帧assessment粒度**：2秒一次观察，固定8秒桶、最多4次输入，由持续Pi Agent给整窗一个区域或边界判断；不要求4份assessment。每次工具续轮仍带整窗当前assessment，保留原事实、历史检索、未决及事务检查点。窗口大小不限制续轮次数，不把局部分类速度当完整处理速度。原逐观察模式作为独立可选模式保留。
- **同日批准的非阻塞调整进一步覆盖窗口调度**：窗口路径为一个整窗独立提取者＋一个持续空间Agent，不再逐观察双路提取；两个职责可流水重叠，空间状态保持单写入。有界证据等待后提交显式不完整状态，迟到追加修订及最新状态重评；尾证据缺失保持未知。容量门禁同时覆盖迟到提取和修订，完整验收仍要求缺口清零，具体契约见01。
- 服务内部设待处理上限，满了暂停接收而非丢帧；提交保持连续前缀。
- 429：提取路数自适应降为1并冷却约30秒；空间单路继续；只重试可识别网络错误，不重试语义错误；未知计费预留保留。
- 窗口提取/空间请求可重叠，但持续吞吐、尾延迟与完整覆盖必须实测，不以短窗口速度或暂停回放认证实时。

## 8. 真实协议、性能与评测（最后阶段）

- 全量前先做少量帧的真实模型协议预检，确认能稳定输出“assessment＋一个动作”；失败保留。
- 全量完成标准必须同时满足：原图归档、独立事实、空间状态、长期提交、Context检查点完整；不能只看观察数。
- 分别统计提取、空间推理、提交、问答和总耗时；没有完整空间状态就不叫完整空间记忆完成。
- 网页与裁判改为读取新空间状态；位置标注只在评测侧使用。
- 语义评分、人工审核和原15题/37分支在空间质量通过后再进行；未通过不扩90题。

## 9. 全量测试前的最小集合与后续迭代

**原则（2026-11-03用户进一步澄清）**：移动经历先由已有空间分组、连续访问与重访复用组织，不另建尚未定型的经历结构。复用旧地点ID本身就是同地合并，不要求先另造merge流程；两个误建ID的处理属于后续修正。当前先做好连续性、正面换区与重访复用，再跑813；其他事件暂不做，拆分和层级暂不作为阻断。首轮仍是基线诊断，不是全部架构能力认证。

### 9.1 全量前必做（P0）

1. **Pi Session 与 Skill 接入**：空间Agent基于 Pi agent core＋持久 Session 运行；空间行为放入 skill；默认 compact；应用 WorkingContext 与长期 SQLite 职责不变。
2. **协议健壮性**：模型输出非法 JSON / 缺少 assessment / 非法动作时，有界反馈重试并记录每次失败；不能因为一帧协议错误让整轮停在半途。语义错误不自动修复、不伪造状态，超预算则该观察失败并停止后续空间提交。
3. **并发、背压与 429**：服务内部待处理上限、提取路数自适应、429 冷却；提交保持连续前缀；不丢帧。
4. **可恢复运行器与完整性收据**：显式同会话恢复；原逐观察813运行须校验813观察、813空间状态。获批8秒窗口模式则校验计划观察全部覆盖、计划窗口状态/Context/Pi检查点一一对应、无待处理；采样运行必须显式声明源数量/间隔/选中数量，不算原813全覆盖。分别汇总提取/推理/提交耗时和用量。
5. **少量帧真实协议预检**：确认模型稳定输出后，才允许全量。
6. **连续空间分组**：同一持久空间Agent结合当前证据与上一窗口优先判断延续；不因视角/小幅移动/出现新物体不断建立地点。新建需正面换区证据，身份不足可暂定延续但仍明确未知；来源与暂定访问引用独立保存，不把暂定当确认。同地重访复用旧ID并保留不同访问；不因“重访”再建一层合并流程。

### 9.2 首轮全量可以暂缓（后续迭代）

- 独立语义事件、通用物体实体索引及相应查询（本阶段不引入事件体系）；
- 独立经历结构（尚待定型）、误建地点ID的通用修正、地点拆分及设施层级；
- 关系撤回与修订历史查询；
- 可翻完的丰富检索/可选语义召回；
- 正式用户问题Agent接入；
- 网页与评测适配、人工审核、原15/37题。

暂缓的后果必须如实记录：首轮仍可能有误建ID未修正、未撤回的一般关系、无语义事件/通用实体索引等缺陷，不能说架构已通过。但已有连续性与重访复用必须真正工作，不能以“以后合并”放任无依据的新建。用户问题测试和任何“空间记忆通过”结论仍须等对应模块完成。

## 10. 待确认

- Pi Session 与 WorkingContext 的具体边界：Session 保存工具轨迹、WorkingContext 作为每轮显式输入；需冻结投影规则。
- 窗口化已于2026-11-03批准：2秒采样、8秒桶、整窗判断；来源/知识截止按01窗口契约，运行配置必须版本化。
- 经历片段默认延续规则的具体断档阈值；不得据此自动做语义切分。
- 实体/设施建模深度：仅具名实体与所属设施，还是需要更细的对象属性索引。
- 压缩默认阈值与保留尾部长度。
