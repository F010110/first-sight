# 不可改动设计与易错点（重访/地点身份/Harness）

追加于 2026-11-08。本文不替代 `01`–`03`，只记录本次 813/349 帧试验后确认的边界和踩过的坑。若与 `01` 冲突，以 `01` 及用户最新明确确认的架构变更为准；要改本文列出的不可改动项，按根 `AGENTS.md` 的架构变更流程先取得用户确认。

## 1. 不可改动设计

> 2026-11-08重构澄清：调度以01新增分层契约为准，4–8秒快速感知＋约40秒多片段空间巩固，不减少重访及其他功能；空间严格串行且耐久待办有界，问答在空间无结果时亦可启动。以下历史实验中的“N=5下限/20足够、rank4证明生产漏召回原因”不构成保证：参考归组和生产采样/截断不同。不同可见招牌或新设施不是自动硬冲突，须核实对象身份、占据范围和视角，不能把未见过当矛盾。加油站街段/外廊的旧FP及precision为历史暂定口径。代表图仅绑定首次访问是未批准的实现建议，不是禁止后续有来源代表图更新的架构要求。

1. **主 Agent 独立承担空间判断与重访，不拆独立重访 Agent。**
   理由：为单一功能再拆 Agent 违背“给 Agent 写 harness、让其自由发挥”的初衷，也会引入第二个记忆写入者/上下文。重访应通过主 Agent 的持久 Session、长期记忆和工具完成，不另设 Agent。
   禁止：独立重访 Agent 拥有记忆写权限；并行空间写入者；把重访判断从主 Session 静态 fork 出去。

2. **matcher 是候选生成器，不是分类器，也没有“正确率/top-1”指标。**
   matcher 的职责只是把可能的地点放进候选集；候选可以很多（默认 20，允许到 200）。评价 matcher 只看 **candidate recall@N**（正确地点是否在候选集里），不看排名。
   本次参考回访实测：N=1 7/9、N=2 8/9、**N=5 9/9**；需要 N=5 的是 `hardware-interior`（rank 4），正是旧 `revisitLimit=2` 漏掉五金店返回的原因。
   禁止：只取 top-2；把 inliers/相似度排名当身份；把分数交给模型当答案；自动接受候选；自动补 citation。

3. **每一窗都必须做重访检查，包括看起来连续运动的窗口。**
   每窗都要查看候选清单，对有希望的候选 inspect 旧图，再决定 continuity / known 复用 / new。候选多不是忽略的理由；候选只是范围。
   当前实现：service 每窗执行 recall 并把广候选注入 `runtimeContext.revisit`；skill 写明“每窗必须先做重访检查”。**尚未实现**硬 `revisitReview` 字段（用户明确本次不做严格校验），重构时再决定。
   禁止：把检索写成“可以”而非必须；只在场景变化时检查；因为没有候选/候选太多而跳过。

4. **地点身份采用两侧证据规则。**
   - **正面锚点**（复用旧地点至少需要一个）：店名/招牌、地址/路牌、入口/出口方向、独特固定布局、房间拓扑、固定设备/独特固定物。
   - **硬冲突**（出现即判不同）：不同店名/招牌、不同地址、入口/出口方向或房间拓扑不相容、固定设施冲突。
   - **弱证据**（不作同地依据）：材质、颜色、家具风格、光线、相似货架/柜台、类别词。
   - **同地不同视角**：旧图不重合、旧锚点暂时看不见，**不构成“不同”证据**；不要据此新建。
   本次两个 FP 都违反了这条：砖墙店内部被解释成当铺“后室”（忽略砖墙/水槽/涂鸦门/后巷出口 vs 当铺收银机/白色后门/街道出口），加油站街段继续沿用 bar porch（已看到 `USA GAS`/South Side/CAFE 仍未切换）。
   **该规则目前只是本文的约束，尚未完整写入 skill**；重构时应以通用措辞补上，禁止写死数据集店名。

5. **当前占据区域优先于远处可见对象。**
   看见店招、入口、路牌、旧楼不等于站在店内/入口/原人行道。用近处地面、路沿、门槛、墙体包围判断当前占据区域。店外人行道可以合理地归入街道；不要因为看见店内就把整窗算作室内。
   禁止：用远处地标替代当前占据区域；把店外街面强行并入店内。

6. **观察与解释隔离。**
   独立当前观察只看当前窗/窗口原图；历史不得改写当前事实。解释可修订，观察原图/来源不变。历史匹配只说明“曾见过这些表面”，不认证当前占据位置。
   禁止：把历史猜测/摘要当当前事实；用候选分数替代原图检查；把旧描述复制成新观察。

7. **短期 Context 与长期记忆分离。**
   短期 Context（空间 Agent Session）有界、可压缩、会过期；长期空间记忆（原图、观察、判断、地点/访问/经历、修订、来源）不压缩，只按需检索。新会话冷启动，不自动回灌历史；恢复只能显式用耐久检查点。
   禁止：把全历史常驻 prompt；把最近几条描述叫完整空间记忆；压缩/删除长期证据。

8. **单写入者、有序提交、追加修订。**
   空间状态只有一个有序写入者；merge/rename/split 都以追加修订记录，保留旧快照、旧名和旧归属；读取按版本/知识截止返回当时状态。
   禁止：第二个并发写入者；重写旧快照；删除冲突/失败/旧地点；把合并后的新名覆盖旧历史。

9. **地点名称/描述必须能更新。**
   连续运动或重访确认同一地点后，如果新证据使名称/描述更准确/更完整，必须用 `rename` 或 `notes`（属性变化用 `placeUpdates`）追加更新，保留旧版本；不能只改 `location.name` 而档案名不变，也不能为改名新建地点。
   本次 349 帧中硬件/街道地点确实新增了 notes，但并非所有 seed 都更新；diner/bar seed 没有。名称更新不是本次唯一指标，但机制必须保留。
   禁止：只改 `location.name`；用新地点代替改名；覆盖旧名历史。

10. **实时性只约束输入投递/落盘，不约束 Agent 判断速度。**
    强制实时是“输入不被 Agent 拖慢”，不是“Agent 必须在 32 秒内判断”。质量基线应使用 queue/全覆盖，不 skip；Agent 可以落后，输入先耐久归档。要上实时再做 ingest 与处理解耦，不能为了实时删掉空间推理、跳过窗口或降低证据要求。
    禁止：用 skip/32s deadline 跑质量测试；把跳过窗算作已处理；把背压等待算作实时通过。

11. **评测口径分开。**
    - matcher：candidate recall@N（正确地点是否进候选），不是 top-1 准确率。
    - Agent：重访 precision/recall、over-revisit/false merge、真实回访召回；错误合并的代价高于漏回访。
    - 片段回放可以用于能力测试，但必须声明 selection/gaps，不能声称全 813 覆盖。
    禁止：用 matcher top-1 代替 Agent 能力；把 0/9（候选超时）当 Agent 回访能力；用同一 ID 两次就认证回访；把评分器的名称启发式当成真实空间错误。

12. **不泄露答案、不过拟合提示词。**
    校验/提示不得读参考 `placeId`/人工答案；不能用大写店名 token 硬判；不能写死 `Pawnbrokers`/`USA GAS`/`brick-shop` 等数据集词；不能用“必须引用某个 ID”代替图像对比。应使用独立 facts + Agent 自己的记忆/图像，以通用证据类别判断。
    禁止：`validatePlaceDescription` 这类答案式 token 校验；确认式小请求（只给 claimed place 旧图问“是否支持”）；`if(!chosen.length)chosen=[target]` 强制引用；自动 citation。

13. **保留失败、旧库、参考和未知费用。**
    不删除旧运行/DB/失败请求/冻结参考；不自动付费重跑、扩大题集、改门槛、推送、发布或移动 tag。active 文档的架构变更需用户确认；本文只追加，不改 01–03。

## 2. 易错点清单

| 易错点 | 症状 | 正确处理 |
|---|---|---|
| 回退时把 matcher 一起删掉 | 长断档五金店返回没有候选、Agent 不检索、新建重复地点 | 删除的只能是“排名/自动接受”，候选召回必须保留或替换 |
| 只给 top-2 候选 | `hardware-interior` 在 rank 4，五金店返回永远漏 | 广候选：N=5 是参考下限，默认 20 |
| 把候选按 inliers 排名给模型 | 5/5 复用都选 top-1，过度回访 | 候选无序、分数只进日志；模型只看名称/ID/来源 |
| `memory_inspect` 也要 known 身份校验 | 想看图却被“Known identity requires”拒绝，主 Agent 根本没看过旧图 | 只读工具不校验身份；身份只在最终 `memory_add` 校验 |
| 确认式 known-support 修复 | 只给 claimed place 旧图，问“是否支持”，必然通过；主 Agent 没看到图 | 把旧图交给同一个 Agent，让它对比当前窗；不自动引用 |
| 答案式描述硬校验 | 看到大写店名就要求写 note；可把错误地点名字补进去，且可能误伤 | 删掉；改成“正面锚点/硬冲突/视角限制”的通用推理要求 |
| 只用通用相似度判断同地 | 砖墙店→当铺、加油站→bar porch | 正面锚点 + 硬冲突；材质/家具/光线不作同地依据 |
| 旧图不重合就判不同 | 同店不同角度被新建 | 视角不重合/旧锚点不可见不是不同证据；保留延续或标不确定 |
| 只在场景变化时检索 | 连续运动/长断档没有触发，五金店返回不搜 | 每窗都检查候选，包括连续窗 |
| 地点档案被错误复用污染 | 错误复用的图像进入地点代表图，后续匹配更自信（Choke 133/108 inliers） | 代表图/索引与首次确认访问绑定；不让错误复用污染索引 |
| 只改 `location.name` | 状态里的名字变了，地点档案/旧名历史没变 | 用 `rename`/`notes` 追加版本，保留旧名 |
| 用实时 skip/deadline 跑质量 | 跳过窗丢覆盖，Agent 被 deadline 杀 | 质量模式 queue/全覆盖；实时只约束输入 |
| 片段运行 `plannedStates` 与实际状态数不等 | `completed=false`，但观察实际全处理 | 片段按观察覆盖判定，不按桶计数硬判 |
| 评分器名称启发式 | `走廊`→apartment、含“店”→street，造成假降分 | 人工区分指标假象与真实空间错误 |
| 把 349 帧当 813 | 覆盖/结论被夸大 | 明确 selection/gaps；全量需另跑 |
| 拆独立重访 Agent | 第二个写入者/上下文，违背 Agent 自由 | 主 Agent + 工具 + 广候选；不拆 |

## 3. 本次能力测试结论（仅作证据）

- matcher 候选召回（9 个参考回访，reference-segmented）：N=1 7/9、N=2 8/9、N=5 9/9；`hardware-interior` rank 4。
- 349/813 片段（默认 20 候选，`run/unioncity-revisit-segments-v3-run`）：349/349、54 窗、0 跳过、8 地点/15 访问；总耗时 **670s（11.2min）**；matcher p50 **995ms**/p95 **2.23s**；Pi 102 请求 $0.356 + perception $0.060 = **$0.416**。
- 重访：TP 2（五金店返回复用 `523e4aa2`/`1dcb61da`；公园街角返回复用 `aec62dc3`），FP 2（砖墙店→当铺 `a85c34c4`；加油站街段→bar porch `829b8c76`），FN 0，TN 1（当铺新建）。**segment-level precision 50%、recall 100%、accuracy 60%**；state-level 8 TP / 10 FP / 0 FN。
- 结论：主 Agent **能完成真实回访**（广候选修复了五金店返回），但仍会把相似的不同地点复用成旧地点；下一步是正锚点/硬冲突规则或重构，不是继续加答案式校验。
- 按状态外推 813 约 **21–26 分钟**；未在本轮重跑全 813。
