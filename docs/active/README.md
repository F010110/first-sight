1. [空间记忆架构](01-spatial-memory-architecture.md)：短期Context、长期空间记忆、持续空间Agent、来源隔离与独立问答的设计契约。
2. [设计理由与变更约束](02-design-rationale.md)：为什么这样设计、曾出现什么问题、哪些捷径不能采用。
3. [实施计划与未决能力](03-implementation-plan.md)：经历/事件/实体、合并拆分层级、关系撤回、自主检索、压缩、并发与最后评测的阶段计划；是计划，不代表已完成。

## 工作信息在哪里

**当前状态、待办、阶段决策、维护和验证记录统一看 [TODO.md](../../TODO.md)。** 先读架构再读TODO：前者规定不能丢掉什么，后者说明实际做到哪一步。代码/原始报告验证实现事实，不能反向替代架构要求。

原先放在active的状态、代码地图、工件、评测和操作说明已移到 [历史快照](../archive/active-knowledge-2026-11-02/)，作为知识线索保留，不自动加载、不再维护为第二套当前状态。其他旧设计仅作历史溯源。

变更架构必须先说明原因与影响，取得用户明确确认，再同步修改架构和理由文件；未批准的提案写TODO，不能先落地再追认。具体执行规则见根 [AGENTS.md](../../AGENTS.md)。
