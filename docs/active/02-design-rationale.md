# 设计理由与不可擅改的边界

本文件解释01架构中的要求，不是新增一套方案，也不表示功能已经实现。阶段结果及待办记入TODO；只有用户明确认可的架构变更才修改这里。

|设计要求|为什么需要|不能采用的替代方式|
|---|---|---|
|短期Context与长期记忆分离|工作上下文必须有界；长期经历不能因窗口过期丢失。长期能力需实际访问持久记忆才能检验|无限堆聊天；自动把全历史概览常驻prompt；把最近几条描述叫完整空间记忆|
|新观察先待判断，再维护当前位置|移动/转场后旧地点不能默认成立；用户需要真实的位置判断，不只是环境词句|沿用上一地点；从人工位置标签或裁判填位置；描述中抽一个地名冒充新推理|
|独立当前感知与历史解释隔离|历史实验出现旧柜台替代街道、站台疑问跨场景残留；历史可能影响模型观察|把全历史猜测与当前原图混合生成直接事实；为了防污染删掉整个空间推理阶段|
|持续空间Agent维护状态|环境、空间关系、变化、关联与未决点需要随经历更新；单帧描述不会自动产生空间结构|只提取事实入库就标记空间处理完成；只在用户提问时临时补空间建模|
|地点、访问、经历、上层场所分开|回到同地仍是另一访问；同店吧台/台球区不能当不同商店，同楼不同区域也不能合成一个区域|把片段数当进店次数；相似用途当同一地点；同场所异区一律叫关系未知|
|来源观察不变，解释可修订|后续证据可推翻判断，但不能抹掉发生过的观察与当时错误，否则无法审计|用摘要覆盖原事实；删除冲突；合并/拆分后偷偷重绑旧引用|
|检索是取证，不是智能函数代答|词项/向量/时间索引只能发现候选，不能证明“第二家”“同地重访”等语义关系|把locate命中当目标已确认；按题号/计数协议硬编码；一次空搜索认证不存在|
|已交付证据与历史看过分开|旧读回结果会污染下一场景；引用必须能对应本轮实际可用来源|永久保留旧检索权限；输出引用就当实际读取；调查Agent看图等同回答Agent看图|
|长期提交成功后才发布Context|下游必须读取耐久、一致的空间状态；独立提取乱序完成不能使空间状态越过失败前缀|数据库写失败仍发布位置；伪造Session/检查点；吞掉回调错误后声称全部完成|
|用户问答与空间生产分离|问题、猜测和答案不能变成下一次视觉事实；可重复问答不应重建空间记忆|问答写回空间库；静态fork代替持续空间模块；前题答案泄漏独立评测|
|压缩与遗忘区分|模型输入受限，但旧证据仍要可查；过期猜测应退出当前状态而非删除历史|把压缩摘要当认证事实；摘要失败静默切默认提示；重建新会话伪称短期仍记得|
|优化不能删掉语义职责|事实提取吞吐不等于完整空间处理速度；有依赖的状态不能随意逐帧并行|用两槽短描述回放时间证明完整空间算法实时；为追吞吐跳过位置判断|
|8秒整体窗口降低重复调用，不替代持续空间Agent|相邻2秒观察可共同支持一个区域或边界判断，避免重复输出与强行逐帧定位；用户于2026-11-03批准|把窗口分类器当完整记忆；整窗身份复制给每帧；把8秒桶当经历；早帧偷看未来；用采样数量冒充813全覆盖|
|评测与真值不写回生产|裁判可以多知道位置标注，但Agent不能借此得答案；描述分数不等于空间能力|让裁判补模型缺失位置；用有效子集均分认证完整能力；未执行核心操作全标N/A后放行|

## 原因的历史来源

- `docs/application/spatial-context-refactor.md`：有界短期/长期、每轮空间判断、持久写入、过期身份取证；顶部新规则覆盖文中早期自动恢复方案。
- `docs/product/separate-memory-and-question-runs.md`：独立空间生产与只读问答，避免问题干扰建模。
- 历史同步47–49：经历/地点/事件区分与组织的必要性；52之后56取消专用计数协议，保留通用调查。
- 历史同步59覆盖58的静态fork，规定动态空间模块与私有问答组合。
- 历史同步60–65：压缩回退、旧状态污染、来源投影仅诊断与长期召回失败；不能把局部修复误当完整设计。
- 最近描述回放缺最终位置：再次证明证据层不能替代空间判断；运行数字与后续处理见TODO及历史快照。

## 架构变更流程

1. 在TODO记录问题：原设计、原理由、真实证据和影响，区分实现缺陷与设计缺陷。
2. 提出替代方案及对短期、长期、因果、恢复、问答和评测的影响；说明如何验证。
3. 取得用户明确确认。没有确认不得因为“重构”“提速”“简化”“更新文档”改变语义职责。
4. 同步更新01与本文件，TODO登记批准范围、实现状态和验证结果；旧实验/冻结输入/失败原样保留。

补充已经存在但遗漏的设计原因可以维护；遇到原设计冲突或不确定处先报告，不以补理由之名擅自作新决定。
