# 设计理由与工程边界（课内版）

| 设计决策 | 原因 | 明确不采用的替代方式 |
|---|---|---|
| 剥离复杂持续空间建模 | 原科研线（Pi Session、地点 ID 合并/拆分/重访、ULVN 几何门禁）存在未收敛的跨地点身份歧义，且高延迟、高开销，会拖垮课堂演示体验 | 在课内演示里硬留半残地点聚类或 40 秒重型批处理 |
| 保留历史科研文件于 `docs/archive/` 与独立 Git 备份分支 | 遵循用户要求不直接销毁 `docs/active/` 与历史积累，保留完整可追溯性 | 直接 `rm` 删光文档或强推覆盖旧历史 |
| 前端拆分为展示舞台 + 可折叠配置抽屉 + 一键“演示模式” | 课堂投影展示需要突出“硬件画面 + 电脑计算输出 + 手机语音”，不能让 IP 表单、二维码、测试注入控件长期抢占主画面；通过 `web/shared.js` 复用卡片渲染逻辑并支持一键进入演示模式 | 把所有科研/调试控件和业务配置混在同一页铺满屏幕 |
| 4 级自动 IP 定位并写回 `run/course-demo/camera-hosts.json` | 课内换教室或换热点后三台 ESP32 IP 会变化；只读 `cam/local/` 而把运行时 IP 独立落盘，免重刷固件且不污染私有配对文件 | 硬编码校园网 IP、要求现场用串口重烧固件，或自动修改 `cam/local/` |
| 私有局域网 IP 守卫 | 相机通过明文 HTTP Bearer Token 鉴权，必须阻止向任何公网 IP 发探测或请求，避免配对密钥外泄 | 允许任意用户输入公网 IP 或 URL 触发采集端发请求 |
| 回环免密 + 手机端随机配对 Token + 常量时间比较 | 电脑本机演示零配置直连，同时防止同网段其他主机或公网隧道匿名查看相机画面或触发付费 API | 对局域网/隧道完全裸奔开放控制与提问接口 |
| Watch 帧指纹去重 + 取消/过期代次校验 | 相机未更新新帧时不重复调用 VLM 省费降噪；任务被取消或超时后丢弃在途异步响应，防止迟到误报警 | 无脑固定间隔调模型或任由过期回调触发手机语音 |
| 显式标注“测试图”与“非安全导航承诺” | 本机摄像头或本地上传 JPEG 仅作演示兜底，不可冒充 ESP32 真机；单目/三目快照不具备避障通行安全保证 | 拿本地照片伪装硬件在线，或让模型承诺“可以安全通过” |
| 手机端首击解锁 + 句子切分 + iOS 黄色兜底按钮 | iOS Safari 与 Android Chrome 均限制非用户手势触发的异步 `speechSynthesis`，必须提供可靠解锁、屏幕常亮及被系统挂起时的单点恢复通道 | 假设收到 SSE 后 `speechSynthesis.speak()` 在所有手机后台永远自动发声 |
