# 空间记忆架构：有效设计契约

更新：2026-11-02。**用户已确认的目标设计，不是当前实现完成声明。** 本文归并早期短期Context/长期空间库、经历组织、独立观察、持续空间Agent及双模块问答要求。不以某个失败版本倒推需求。

## 1. 职责与数据流

```text
三摄原始观察（时间、方向、来源）
  → 先耐久归档原图/元数据
  → 无历史的当前观察提取（可整窗一次，不做历史身份定论）
  → 按时间有序的持续空间Agent
      ↔ 独立、有界、可过期的短期空间Context
      ↔ 检索/读取/检查长期空间记忆与原始来源
      → 当前空间判断、状态变化、历史关联及未决事项
      → 长期事务提交：观察归属/地点/访问/经历/修订/来源
      → 发布该时刻的短期Context与不可变版本检查点
  → 持续更新的共享空间模块 ─┐
                              ├→ 独立用户问题Agent（只读空间）
     私有问题/调查/回答会话 ─┘
```

**空间Agent在没有用户问题时仍要进行空间判断。** 关系按需进一步取证不代表可以取消当前空间状态维护。独立提取仅是前端证据生产，不可直接标记整次空间更新完成。

### 窗口化更新（2026-11-03用户批准）

- 可采用2秒一次独立观察、固定8秒时间桶（左闭右开），最多4次观察作为一次空间更新；流结束或录制切换时允许不足4次的尾窗。8秒是调度单位，不是经历切分或永久地点。
- VLM给整窗一个区域身份（已有/新候选/未知），或两个区域之间的边界/过渡判断。边界保存两侧候选与依据，当前位置保持未确定，不认证连通或进入。不能强行给复杂窗口一个确定区域。
- 原图和独立观察事实逐次保留；窗口成员、时间范围、来源及实际可用时间耐久绑定。不得把整窗判断复制成4次独立定位，也不伪造批内转场时间。早观察被整窗解释覆盖，不表示当时已有该知识。
- 窗口仍进入持续Pi空间Agent，维护工作Context、持久地点/访问、历史关联及未决；必要时自主检索、检查原图、续轮和修订。短输出/低频更新不取消这些职责，也不限制每窗口只能调用模型一次。
- 先提交整窗状态、成员覆盖与Context检查点，再发布版本。检查完整性按输入计划中的观察覆盖和窗口状态/检查点逐一核验，不再把窗口成员数当判断数。若对原始输入采样，必须在运行清单明确源数量、采样间隔和选中数量，不能将采样运行声称为原813次全覆盖。

### 非阻塞证据与流水（2026-11-03用户批准）

- 窗口生产采用一个无历史整窗提取者、一个持续空间Agent；取消窗口模式逐观察双路VLM提取，不并发运行两个空间状态推理。不同职责允许流水重叠：下一窗提取可以与当前窗空间推理/长期提交并行，不把相互依赖的空间判断拆成多写入者。
- 提取一次接收当前窗最多4组三摄，按原始观察ID分别绑定简短事实；不接收跨窗口历史/身份，不把后帧物体补成早帧可见事实。该批事实仅在批提取实际完成后可用，不伪装成各早帧时刻已知。
- 已归档窗口不再以“所有提取成功”作为发布前置条件。有界等待截止后，将已就绪事实与显式缺失项交给空间Agent；null事实是未拿到证据，不是“观察为空”。尾部事实缺失时当前位置必须未知，不能默认沿用；空间语义错误/提交失败仍不得伪造成功或越过失败前缀。
- 原图归档、事实就绪、空间首次解释、证据完整与修订完成分开记账。初始窗口按输入顺序提交，允许显式不完整；“状态已更新”不等于“观察已完整处理”。迟到事实耐久保存后，在同一单写入队列追加新判断版本；不重写旧快照，不把历史修订当新访问或当前回到旧处。修订旧窗口后重新核对最新窗口，当前状态不随历史修订倒退。
- 在途提取、窗口、迟到修订共同受容量门禁约束；缺失任务未真正结束或修订未完成前不释放相应名额。请求有超时与有限重试，满载背压，不能把无限后台补偿队列叫非阻塞。完成收据还必须校验无缺失事实、无未解决的不完整窗口、所有追加版本均有真实Context/Pi检查点。

### 强制实时投递（2026-11-04用户批准）

- **实时性针对输入投递，不针对Agent速度。** 观察必须按源节拍投递（本轮2秒一帧）；不得为了让空间Agent跟上而延迟下一次投递。此前用`queue`等容量再投递会把866秒之外的背压等待计入总时长，等于把实时系统做成批处理，不能算实时运行。
- 空间Agent忙（已有窗口在排队）时，**跳过当次空间判断**，把该窗原图与独立事实耐久保留，作为`skippedBefore`交给下一次判断一并结合处理；跳过窗不单独产出位置判断、不写入地点成员，并单独记账，不能算作逐窗空间覆盖。
- 强制实时运行必须：输入节拍与计划一致；投递滞后超过一个节拍即记为违规并在收据中`completed=false`；收据给出`realtime{enforced,maxDeliveryLagMs,deliveryViolations,satisfied}`；覆盖义务按“已判断窗＋跳过窗＝计划窗”核验，而不是要求所有窗口都被判断后再声称完成。
- 跳过是调度策略，不是降低证据要求：跳过窗的事实缺失仍按缺失处理，不得伪造位置；恢复时保留跳过证据与容量直到后继提交。

## 2. 短期空间Context：真正的工作记忆

### 持续会话主体（2026-11-03用户批准）

- 空间Agent持续Session是短期工作记忆主体，自动记录原始观察输入、可见输出、工具调用/结果和失败；无需Agent另调用写Context工具。完整耐久轨迹与有界模型输入分开，超预算由模型按规则压缩并保留尾部、来源、当前任务和未决，不记录隐式思维链。
- 应用保留小型结构化状态头（当前位置、观察范围、地点/访问、来源、提交版本），用于一致发布和恢复；不是另一套替代会话的历史记忆。过去工具结果是历史记录，不自动恢复本轮引用/原图权限。
- 长期地点档案由Agent主动维护，程序负责来源校验、事务及追加版本；会话压缩摘要不是长期事实。
- 调度优先单空间Agent：忙时可跳过调用机会，但原图和事实保留，作为skippedBefore交给后续判断结合处理，不伪造早窗位置；跳过窗口单独记账，不算逐窗空间语义覆盖，仍可选择queue模式作全覆盖基线。暂不采用跨版本并行分支汇合。独立观察事实缺失时等待或跳过该次判断，不以缺证unknown冒充完成；此项覆盖前述缺失证据降级规则的生产调度选择，旧实验及不完整快照保留。

- 独立维护，不是每个问题临时搜库拼背景；包含当前观察、当前位置判断、近期空间判断、地点锚点、本轮实际读回证据、必要工作输出及活跃未决点。
- 新观察到来先将当前位置置为待判断，不能默认继承上个地点。历史判断描述历史，不冒充当前可见。
- **连续性与重访（2026-11-03用户澄清）**：优先检查上一相接窗口的区域是否延续；当前证据支持时复用旧地点ID，转头/光照/新出现物体不自动新建，重访也直接复用已取证的旧ID。相接窗口要新建需有正面区域变化证据，而非“没匹配上”。参考早期V1.1的provisional语义：当前身份不足、无明确换区时，Agent可保留上一场景的暂定关联，但主位置仍未知，暂定地点/访问引用与确认身份分开保存。不能把候选当下一轮的确认事实；断档、录制切换、边界及尾证据缺失不默认延续。不因此新增独立合并步骤，也不要求立即另建经历结构。
- 有界并过期；移出工作视图不删除长期记录。旧实现基线：recent6 / anchors4 / retrieved4 / outputs4、60秒过期、理由400字符、近期输出2400字符摘录；这些是**可追溯旧配置，不是新性能目标或不可改常数**。修改须先版本化。
- **短期Context必须压缩。** 空间短期Context和用户问题模块是两个独立Context模块；各自达到预算/长度时按固定规则压缩，保留最近尾部、当前任务/当前观察、来源引用、未决点和可恢复线索。压缩是工作摘要，不是新事实。
- **长期记忆不压缩。** 原图、观察、空间判断、地点/访问/经历/事件/实体、修订和来源保留在长期层，只按需检索；不能因为短期Context压缩或过期就把长期证据摘要化或删除。
- 新会话从空Context开始，不自动从长期库重建近期判断。故障恢复可显式恢复耐久提交的同一会话检查点，需标明版本、时间及压缩边界；不能把新会话冷启动偷换成历史自动回灌。
- 原图可移出模型输入；来源索引仍能找回。曾经读过不代表本轮仍已交付/可引用。

## 3. 长期空间记忆：不能只存描述

长期层至少区分：

|对象|保存内容/约束|
|---|---|
|原始观察|三摄原图/hash/方向、录制与发生时间、接收时间；不被摘要改写|
|观察事实|独立提取原文、来源、版本、实际可用时间；模型描述不冒充人工真值|
|空间判断/归属|当前区域身份或明确未知、判断理由与来源、状态及修订版本；不凭程序默认新地点|
|地点/区域|可追溯持久身份、暂名/特征/证据/不确定性；类别词“走廊”不等于具体身份|
|访问/经历段|同地多次到访分别保留；片段≠永久地点，片段序号≠进入次数|
|事件/关系/实体索引|有来源的进入/离开/变化候选、物品与场所交叉索引；同区域/同场所/相邻/连通分开|
|修订与交互|合并/拆分/重新归属/撤回记录、原始输出/失败/检索轨迹；模型陈述不是视觉证据|

经历按时间组织，实体/场所/事件交叉索引，任何总结可下钻来源。不能读42段标注预先搭目录，不能用相似装修自动合并身份。允许不确定与候选，但持续全unknown不等于完成建模。

### 地点名称与本轮范围澄清（2026-11-04用户批准）

- 本次连续地铁站内部经历允许作为一个地点，不以站台、闸机厅、出口楼梯未分别建ID自动判错；但名称须覆盖已确认范围，例如由“Midtown地铁站台”修正为“Midtown地铁站内部”。这不授权把街外人行道、车道和对侧街角仅因同地标可见就认证同一区域。
- 地点名是可修订的描述，不是持久身份。Agent确认同一地点后，可根据当前图片与已交付历史来源主动修改名称，附理由和来源；程序在同一提交事务追加名称版本，不另建地点/访问，不重写历史判断、旧名或旧检查点。读取档案必须按版本/知识截止返回当时名称。

### 本轮取消unknown输出（2026-11-04用户批准，仅限本数据集）

- **本数据集的每一窗都必须归属一个地点（known复用或new建立），unknown与boundary不再作为可提交状态。** 依据是用户判断：本样本没有真正"位置不明"的窗口，持续弃权会掩盖应当完成的建模。工具schema与skill只暴露known/new；程序对提交层的unknown仍保留兼容（旧库、历史修订、问答视图可读），但新判断一律拒绝。
- 代价必须如实记录：门口/街角这类真实跨区窗，现在要按"本窗主要占据的一侧"归属，并在reason写明跨越；这放弃了2026-11-03批准的boundary中间态，已知会在这类窗上产生单侧归属错误，后续若换用确有模糊帧的数据集，需要重新讨论是否恢复。未决与限制改写进`unresolved`/`reason`，不得因为不能弃权就伪造确定性。
- 该决定不改变"先核对窗头窗尾再归属"和"当前占据区域优先于远处可见地标"的要求；也不把连续站内部拆ID设为必需。

## 4. 每次更新的最低语义输出

必须能从耐久记录直接得到：**当前所在位置/区域（已有、新候选或未知）、当时观察细节、判断依据及其来源**，以及当前适用的历史关联、未决事项和版本。不是事后由裁判/网页抽取地名补齐。

已有 `ContextJudgment` 为 observationId / atMs / placeId|null / reason / sourceIds；可作为恢复对照，但**本文不强制所有未来实现采用同一JSON字段**。持续Session亦可表达状态，但必须有可审查、可持久化的明确当前位置判断，不能只有散落描述和假设。

模型每次空间操作/检索续轮都重新评估当前状态；不机械复制过期hypotheses/unresolved。无适用关联可以为空，但当前判断不能被省略。输出不要求展示隐式思维链，只保存可核查结论与依据。

## 5. 观察与解释隔离

独立观察阶段只看当前三摄或当前窗口原图，不读跨窗口历史；历史不能重写当前事实。空间阶段接收已固定的就绪观察、显式缺失项、工作Context和经工具交付的历史证据。解释可修订，观察不变；不能把“猜同楼”变成下一帧的观察事实。方向标签与图内左右分开，三摄是同一时刻不同朝向，不是三个时刻。

持续空间Session是真实状态维护，不是将最近4/5条事实贴进消息即可替代。诊断用来源投影只验证污染控制，不可未经长期能力测试升级为完整记忆方案。

## 6. 检索与证据

自主决定是否需要历史来源。搜索/概览/浏览产生候选，不等于原图已检查；读回来源、inspect实际原图和引用资格分别记录。可通过已交付的可追溯来源直接取证，不强制搜索仪式。

按经历/目标定位，再查属性与跨访问比较；词项、向量、图或时间索引只是候选机制，不是身份认证。不能按题号、绿色桌子等私有目标强制路由；局部无命中不证明全历史不存在。长期概览/前题答案不能暗藏在初始Context后再宣称长期检索成功。

这里的“定位经历”是Agent的语义职责，不能把一个名为locate的词项函数当智能定位器。历史52曾拆出调查Agent、56进一步取消专用计数协议/序数路由，保留通用timeline/read/find/around/recall/coverage/inspect。若复用独立调查机制，其报告是本次解释，不写成长期已认证事实；不强制每次问题都委托，也不能用规则替Agent决定检索。

## 7. 提交、因果与恢复

原始观察先归档；空间判断校验后长期提交成功，才更新工作Context及发布版本。故障保留原观察、失败和未知计费，不能发布半份事务。初始窗口提交有序；获批非阻塞模式允许明确缺失证据的完整事务，不把事实缺失冒充成功。迟到修订追加新版本；空间语义/提交故障仍停止初始前缀。

每时刻检查点绑定输入、来源时间、知识/提交截止、上下文hash、真实状态/session元数据、压缩范围。无Pi Session就不伪造Session。事件时间和主机可用时间不能混为一谈；加速回放的逻辑投影须单独注明，原始主机时间保留。

## 8. 用户问题Agent

独立Session只积累自己的问题、调查、回答。请求前组合最新共享空间模块与私有会话，不从空间Session静态fork，不把空间消息复制进私有持久历史。空间Agent不读问答结论；问答不写空间库。离线独立评测固定对应时刻，分支间不泄漏答案。

用户问题会话由**空间记忆模块＋用户问题模块**两个Context模块组合而成；两者分别压缩、分别保留尾部与来源，不是用一个模块的摘要覆盖另一个模块。压缩门槛与保留尾部长度属于可版本化运行配置，不能改变长期证据或把摘要升级为事实。

早期“每个问答调用也建空间”的控制循环是历史实现资产，**不能原样恢复这个耦合职责**；保留空间assessment机制，将用户问答职责按后续决定分离。

## 9. 图与实时性

地点/访问/关系可以结构化，**不强制虚构复杂图或精确坐标**。观察到先后经过不证明连通或安全，同场所不同区域不等于未知。已有位姿路线图是独立历史实验，不默认引入本主线。

实时优化优先复用无历史三摄提取的并发调度、短输出和有序提交，但不能删掉空间推理来换速度。并行不能把相互依赖的空间状态当独立帧随便计算。813次完整处理、回答、评分分别计时；10分42秒描述回放不是完整架构速度证明。
