# 活跃文档制度、提取范围与维护记录

更新：2026-11-02。此制度是本批文件持续有效的组成部分，不是一次性整理建议。

## 1. 权威与归档

优先级：用户明确最新决定 → 活跃架构契约/决定 → 活跃状态（必须与实际证据相符）。源代码/冻结输入/原始报告决定事实，不由摘要“投票”覆盖。发现冲突同时保留**应当怎样、实际怎样、证据路径**，而不是选最乐观一句。

活跃白名单：本目录README及01–08。`source-catalog.json` 是辅助索引。根AGENTS是执行维护规则。除此以外所有说明性文件定义为**旧/历史参考**，即便标题写“当前”。不删、不批量移动、不修改旧实验规则；引用历史时给路径/日期/适用范围，不恢复第二套“当前知识”。

源码、测试、脚本、运行Skill、原图、数据库、报告、许可与安全约束不是废弃物。法规/许可/秘密保护不因归档失效；可执行文件是否启用要按入口核查。新功能设计应更新本批文件，不另开一个同级“最新方案”长期游离。

## 5. 目录与自动检查

`scripts/maintenance/catalog-active-knowledge.py` 只枚举仓库自有文档/源码/测试/脚本及少量根说明，保留路径、大小、hash与角色；忽略run/data/datasets/node_modules/Git/私有cam/local/独立research，避免读取原始影像与秘密。角色区分活跃知识、历史说明、实现、原始支持材料。索引不是全文审阅凭据。

脚本校验活跃白名单存在、相对Markdown链接可解析；新文档若没有进入白名单自动算历史。活跃条目增减必须先更新本README/脚本/本制度，不能仅造文件名“latest”就升级。

目录hash对应生成时的工作区，含尚未提交的其他工作，不能当某次Git提交的源码冻结。检查脚本自身回归：`.venv/Scripts/python.exe -m unittest tests.python.test_active_knowledge`，验证目录可重复、旧文档分类、私有/原始数据树排除和断链拒绝。
