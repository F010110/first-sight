# ULVN相关视觉前端：适用范围的有限验证

用户要求先测试，再判断ULVN与VLM的互补范围。此次不是恢复纯VLM提示词调参，也不修改主架构。**测试对象是已接入MegaLoc＋SuperPoint/LightGlue前端，不是完整RAVEL/BPL导航系统。**

结果已完成，见[范围实测与混合路线提案](ulvn-operating-range-results-2026-11-10.md)。

## 固定任务与公平性

- 10组图对：4个近位置返回/转向正例，3个此前混淆的不同路口/街段，3个同建筑室内外或上下沉通道边界。
- 8个查询：220/360/378/388/660/680/780/813，在同一冻结历史参考档案中检索。档案固定每20观察取1＋65/68/108/138锚点；两后端完全相同，历史至少早60观察，不建未来地图。
- 图对任务每端完整比较3×3=9方向组合，显式检查工作量；检索任务保留各后端原有有界验证调度，分别记几何数/耗时，不假称等算力。
- 每后端每任务重复2遍，第二遍只用于缓存/耗时，不能当独立准确率样本。总72本地请求、0付费VLM调用。不调阈值，不自动换默认。
- 真实姿态/地图仅在评测侧做近位置半径100/200/400 source单位、垂直差≤48的敏感性分析，**不是语义区域定义**。无合格参考时记“档案无近位置来源”，不硬算召回失败或“从未到过”。
- 同一可见表面和同一占据区域分开。边界组不能用几何成功直接认证语义同地；高inlier不自动算错误或正确。
- 向后端只交原图及匿名reference ID，无Agent身份、历史VLM答案、地图、位置或参考标签。核验原图hash和参考文件与冻结bundle绑定。

## 要回答的问题

1. 精确/近位置重访与跨方向，哪一端能把真实历史图排前？分别报告全局与几何rank@1/3/5。
2. 不同路口假相似的匹配强度与正例是否分开？不以两算法分数或inlier大小直接比较准确率。
3. 共享建筑/不同占据区域是否也出现强几何？若出现，必须保留语义边界审核，不能直接同地提交。
4. 冷启动/暖调用和历史档案增长的实际代价是多少？本机GPU与CPU差异单列。

既有失败案例属于开发诊断，新增案例也来自同一数据集，不称独立外部验证。结果只支持范围提案：视觉锚点/定位证据与VLM语义解释如何分工；任何自动身份提交或改架构均须另获批准。
