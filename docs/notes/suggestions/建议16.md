
我查了空间记忆、具身智能、场景分段和长期视频记忆的相关评测工作。一个比较明确的结论是：

你们不应该给空间记忆库预先规定唯一的标准分组，然后要求 Agent 尽可能复现它。

这不仅因为分组存在主观性，更因为 First-Sight 的目标不是把每一帧准确分类，而是构建一套能够支持后续定位、回忆和空间推理的长期记忆。

你提出的例子特别重要：

> 8张图中，7张是站台，1张是楼梯。Agent 把这个窗口归入站台，而不是单独建立「站台与楼梯的过渡区」，算不算错误？

我的判断是：通常不算错误，但取决于这个决定有没有破坏未来需要使用的空间信息。

如果这个窗口仍然归入站台，Agent 记录了附近存在楼梯，之后也能够正确识别进入楼梯间的位置，那么这种粗粒度分组完全合理。

反过来，如果系统因为把整组判为站台，就丢掉了楼梯存在的证据，之后也无法回答楼梯在哪里，那么即使分组本身可以接受，记忆仍然存在缺陷。

这启发了一个更合适的评测原则：

允许多种正确的记忆结构，但要求它们保留关键事实，并支持正确的空间判断。

## 一、相关研究实际上怎么评测？

我认为下面五类工作最值得参考，它们解决的是不同层面的评测问题。

| 研究                  | 实际评测什么                                         | 对你们的价值                 |
| --------------------- | ---------------------------------------------------- | ---------------------------- |
| UCS-Bench / DirectMe  | 基于时间戳的空间问答、对象位置、视角变化和长期记忆   | 高：避免直接比较记忆结构     |
| Hydra                 | 地点、房间层级及场景图，与人工标注空间区域匹配       | 高：为分组质量提供参考       |
| Ego4D Episodic Memory | 通过自然语言或图像查询，定位过去观测中支持答案的证据 | 高：能评测证据保留与回溯     |
| SpaMEM                | 将单帧感知、给定历史的推理、完整视觉记忆维护分层测试 | 很高：便于定位记忆错误来源   |
| EmbodiedMemory-Bench  | 用记忆完成后续交互任务，考察状态更新与任务成功率     | 中高：作为未来产品级评测参考 |

### 1. UCS-Bench：不要求内部记忆结构一致

UCS-Bench 包含170多小时第一视角观测与8100多个带时间戳的问题，评测的是系统是否能依靠持续维护的空间记忆，回答与用户位置、历史观测和物体有关的问题。

[image](https://www.google.com/s2/favicons?domain=https://proceedings.mlr.press\&sz=32)

Proceedings of Machine Learning Research

它最值得借鉴的是：评测输出，而不直接要求 Agent 的地点划分和参考系统一模一样。

对 First-Sight 来说，可以问：

- 我现在是否回到了之前经过的站台？
- 楼梯位于刚才经过的什么区域附近？
- 当前区域与之前的候车大厅是否相连？
- 我上一次看到某个设施是什么时候？

但要注意：UCS-Bench 以空间问答为主要目标，而你们目前首先需要验证长期记忆写入阶段本身。仅靠最终问答，可能无法定位中间究竟哪里出了问题。

### 2. Hydra：分组可以比较，但不能只看重合率

Hydra 是一个面向机器人空间感知的层级3D场景图系统。它会把底层空间地点节点组织为房间等更高层实体。

它的评价中包含预测房间与真实房间的匹配，例如根据预测房间包含的地点节点与真实房间的重合情况建立对应关系，再评估房间语义分类。

[image](https://www.google.com/s2/favicons?domain=https://journals.sagepub.com\&sz=32)

Sage Journals

这给 First-Sight 一个可借鉴的思路：不要求地点 ID 和参考答案一致，而是寻找预测分组与真实区域之间的对应关系。

不过，如果你们机械采用房间重合率，就会对合理的合并或细分产生惩罚。

例如，同一个长站台被分成两个区域，未必比把它作为一个区域差；要看是否影响地点重识别和空间关系。

### 3. SpaMEM：最值得借鉴的是分层诊断

SpaMEM 将空间记忆评测拆成三个层次：

- Level 1：只看当前观测，测试基本空间感知。
- Level 2：给出理想化的文本状态历史，测试时序和空间推理。
- Level 3：只给连续视觉观测，测试端到端空间记忆维护。

它还区分短期状态更新与长期记忆重建。

[image](https://www.google.com/s2/favicons?domain=https://arxiv.org\&sz=32)

arXiv

这很适合你们，因为 First-Sight 已经明确拆开 Perception 与 Pi 空间推断。

如果最终记忆错误，你们应该知道：

是视觉理解遗漏了楼梯？还是 Perception 已识别出楼梯，但 Pi 错误归属？还是 Pi 判断正确，长期库提交或检索出了问题？

SpaMEM 的分层诊断思想，可以让你们避免把所有错误都归因于「空间记忆质量不好」。

### 4. Ego4D：记忆不仅需要回答，还需要证据

Ego4D Episodic Memory 不只是测试问答，还要求定位能够支持答案的历史视频片段，部分任务需要定位物体边界框。

[image](https://www.google.com/s2/favicons?domain=https://ego4d-data.org\&sz=32)

Ego4D

这与你们现有的来源证据机制非常契合。

你们的长期数据库已经保存原始图像、观察记录、笔记来源和追加式修订，因此可以评测：

Agent 在正确回答的同时，能否指出它究竟依据哪些真实观测？

这比让一个 LLM 裁判笼统地说「空间记忆基本合理」更有说服力。

### 5. EmbodiedMemory-Bench：最终看记忆是否对任务有用

2026年的 EmbodiedMemory-Bench 有2554个交互 episode，测试 Agent 能否利用历史记忆完成后续任务，涵盖被动观测、动态状态追踪、交互失败和经验泛化，主要使用任务成功率及错误复发等指标。

[image](https://www.google.com/s2/favicons?domain=https://zju-omniai.github.io\&sz=32)

zju-omniai.github.io+1

它与 First-Sight 的当前写入测试并不直接一致，但支持一个重要原则：

记忆的最终价值可以通过任务结果衡量，而不必通过记忆表示本身衡量。

## 二、我推荐采用「约束式分组评测」，而不是标准答案式分组评测

这是综合前面研究后，我认为最适合 First-Sight 当前阶段的方案。它是我提出的组合设计，不是某篇论文直接使用的现成指标。

核心想法是：

不规定唯一正确分组，只规定哪些观察绝对不能混淆、哪些应该能被关联，以及哪些分组差异可以容忍。

例如，下面这段假设轨迹：

8张连续观察的示例

1

2

3

4

5

6

7

8

前7帧以站台为主，第8帧开始出现楼梯。仅为说明评测逻辑，不代表真实样本标注。

选择 Agent 的分组结果

全部归入站台

站台 + 过渡区

末帧单独建立楼梯区域

可能合理的粗分组

只凭这8帧的分组方式，不能直接判定优劣。还需要检查楼梯事实是否保留、后续进入楼梯时能否正确更新位置，以及回访时是否保持一致。

你真正应该标注的不是：

> 第8帧必须属于一个叫「站台与楼梯过渡区」的地点。

而是：

- 第1–7帧主要观察到了同一站台。
- 第8帧出现楼梯相关证据。
- 站台与楼梯存在某种空间连接关系。
- 后续若持续进入楼梯区域，系统应能够形成对应的区域变化判断。
- 只要不造成严重空间误认，边界在哪里划分可以具有一定自由度。

这个评测能容忍不同的空间抽象层级。

但也不意味着允许任何分组。假如 Agent 把两个相距很远、没有连通或同一地点证据的区域合并，那就是需要检出的错误。

## 三、具体怎么量化？我建议分成四个指标

### 1. 区域关联正确性

这是最直接的自动化指标。

不比较地点名字，而是随机选取两段观测，询问：

它们是否属于同一个物理区域或同一个可识别地点？

例如：

| 观测对               | 真值关系 | Agent 应有表现 |
| -------------------- | -------- | -------------- |
| 同一站台的两次回访   | 同一地点 | 能建立身份关联 |
| 两个相似但不同的站台 | 不同地点 | 不应错误合并   |
| 站台边缘与楼梯入口   | 边界模糊 | 允许不同抽象   |
| 两段相距很远的区域   | 不同地点 | 应明确区分     |

可以计算：

\\[ P=\frac{TP}{TP+FP},\qquad R=\frac{TP}{TP+FN} \\]

其中 TP 是正确建立的同地点关联，FP 是把不同地点错误合并，FN 是没有识别出同一地点的回访。

地点识别文献本身也使用 Precision、Recall 等指标。

[image](https://www.google.com/s2/favicons?domain=https://link.springer.com\&sz=32)

春风出版社

但我建议你们加入第三种标签：`ambiguous`，表示允许不同抽象的边界观测。

评测时可以：

- 主要指标只使用明确的同地点和不同地点观测对；
- 模糊对单独报告，不强制算错；
- 分别报告错误合并率与错误拆分率，不仅给一个 F1。

还有一点非常关键：抽样不能让大量相距很远的明显负例占据绝大多数，否则系统只要不断建立新地点也可能获得看似不错的成绩。

应该对回访、相似地点、相邻边界和远距离区域分别采样，再给出分组结果。

### 2. 关键空间事实保留率

这比区域关联更适合你提出的楼梯例子。

例如，每段轨迹人工或通过游戏真值生成一些关键事实：

- 观察到了楼梯。
- 从站台能够进入某个通道。
- 某处存在电梯。
- 两个区域之间可以通过一扇门。
- 某次回访再次经过了相同的楼梯。

然后测试长期记忆是否保留这些事实。

可以分成：

关键事实召回率：应该保留的事实，有多少能够从记忆中找到？

事实支持精确率：记忆中声称的事实，有多少有真实观察或环境证据支持？

不过这里要控制信息的重要性，不是每个细节都值得保留。

例如，一面墙的颜色未必重要；楼梯、门、出口和区域连接关系通常更重要。

因此建议将事实标注分为关键、辅助和可忽略，而不是把所有视觉对象同等计分。

特别注意：如果只是判断是否出现过楼梯，必须明确这是在评估 Perception 还是 Memory。如果事实已经由 Perception 提供，而长期记忆却丢失了，才是纯粹的记忆维护失败。

### 3. 关系与拓扑一致性

你们的地点结构允许自由划分，但不能在空间关系上完全自相矛盾。

例如，真实轨迹为：

站台

楼梯

大厅

在不同记忆结构中，站台与楼梯可以分开，也可以作为一个更大区域的子结构。

如果一个 Agent 用三个地点节点表示，另一个用两个地点节点表示，只要两者都能恢复关键连通关系，就不应该仅因节点数不同而判一个错误。

因此可以评估：

- 两处关键位置之间是否可达。
- 是否记住了必要的出入口与连接。
- 是否错误建立了实际上不存在的连接。
- 回访时空间关系是否保持一致。

这类评测比简单比较图编辑距离更合适，因为图编辑距离经常会把合理的节点合并、细分当成错误。

### 4. 在线记忆的时间有效性

First-Sight 是持续运行系统，所以还必须区分最终是否知道，与当时是否已经知道。

例如，第8帧第一次看到楼梯，Agent 由于处理延迟，在第10帧才完成相应记忆更新。

这并不一定算严重错误。但如果用户在第9帧询问前方有什么，系统却依据尚未形成的记忆回答，评测就必须检查当时实际可用的信息。

我建议采用两类结果：

- 最终重建质量：813帧结束后，长期库最终保留了多少正确空间信息。
- 在线可用质量：在每个指定检查点，Agent 已提交且可查询的记忆能支持多少正确判断。

这与你们现有的 `atMs`、状态版本、提交检查点和事件日志设计可以自然结合，不必重新实现一套评测运行时。

## 四、关于时间边界：相关视频分段研究也支持宽容的评测方式

在时间动作分割领域，研究者通常不只使用逐帧准确率，还同时使用 Segmental F1、Edit Score 等指标，分别衡量片段匹配、分段顺序，以及是否出现过度切分。

[image](https://www.google.com/s2/favicons?domain=https://link.springer.com\&sz=32)

春风出版社

2026年的在线时间分段压力测试还发现，某些指标的改善可能掩盖系统对状态转变的反应变慢，因此需要单独报告 transition delay。

[image](https://www.google.com/s2/favicons?domain=https://papers.ssrn.com\&sz=32)

SSRN

这一点正好适用于你们。

例如，楼梯在第8帧开始出现，不应该要求 Agent 必须在第8帧立即新建地点。

但如果直到第15帧已完全进入楼梯间，它仍然坚称当前处于站台，就明显值得扣分。

所以我建议允许边界容差，但明确报告重要区域变化的识别延迟。

另外，这里要区分一个容易混淆的问题：一帧里出现楼梯，不等于用户已经进入楼梯区域。视觉内容变化与实际空间位置变化不是同一事件。

这恰恰说明你们不能只按视觉类别标注空间边界。

## 五、如何真正落地到813帧样本？

我不建议第一轮就给813帧逐帧标记标准区域，更不建议立即引入一个大型 LLM 裁判对整段轨迹给分。

你们已经有一套独立的盲取证与整体评价流水线，可以保留它作为辅助质量分析，但我建议增加一个更可复现的结构化评测层。

建议的最小评测流水线

1\. 生成客观真值

从 GMod 轨迹和场景中提取区域回访、位置变化、关键连接、可见物体等事实

2\. 生成评测约束

同地点 / 不同地点 / 模糊、关键空间事实、连通关系、查询时间点

3\. 读取 First-Sight 的状态快照

按照提交版本和时间过滤，只允许使用检查点时实际可用的记忆

4\. 进行机械评分及必要的语义判定

匹配地点身份、检查事实证据、判断拓扑关系和边界延迟

5\. 输出分项报告

按地点关联、事实保留、空间关系、在线有效性和错误类型分别报告

这里还有一个实际难点：GMod 原始坐标不能直接自动生成所有语义真值。

你可能知道两帧相距多少米，但「这是否属于同一个站台」「楼梯入口究竟属于哪个区域」依然需要场景语义或人工定义。

因此我建议第一版采用少量高置信自动真值 + 少量人工验证的模糊边界，而不是追求全自动标注。

### 第一版评测集建议

| 测试项目           | 建议数量 | 主要用途             |
| ------------------ | -------- | -------------------- |
| 明确同地点观测对   | 30       | 测回访与错误拆分     |
| 明确不同地点观测对 | 30       | 测错误合并           |
| 边界模糊观测       | 15       | 测过渡容忍与变化延迟 |
| 关键空间事实       | 30       | 测信息保留与幻觉     |
| 拓扑关系问题       | 20       | 测空间结构可用性     |
| 在线时间点检查     | 20       | 测记忆更新是否及时   |

这些数量是我建议的首轮探索规模，不是文献规定。它们也不必互相独立，可以共用部分观察和标注。

特别是813帧单轨迹，如果实际上没有那么多真实回访，就不要为了凑30个正例而制造伪回访。

## 六、我建议先用多维报告，而不是一个综合分数

First-Sight 空间记忆评测报告示意

以下仅展示报告结构，数值不是系统实测结果。

地点关联 F1

明确同/不同地点观测对

—

关键事实召回率

重要可观察空间信息

—

空间关系正确率

连通性与区域关系

—

在线状态可用率

按时刻读取已提交记忆

—

边界变化识别延迟

重要空间切换的响应时间

—

一个综合分数很容易掩盖重大问题。

例如，系统可能把大部分区域分得很好，却把两个不同的地铁站错误合并。对视障辅助产品来说，这种错误比少记住几处不重要的墙面细节严重得多。

反过来，将一个站台拆成两个区域，不一定有什么实质影响。

因此错误合并、错误拆分、关键事实遗漏，应该分别观察，必要时给高风险错误更大的权重。

## 七、我的最终建议

对你们目前的 First-Sight，最值得采用的是 UCS-Bench 的任务导向评测、Hydra 的区域匹配思想，以及 SpaMEM 的分层诊断。

我不建议直接复制任何一套现有 Benchmark。因为它们有的以问答为目标，有的依赖精确空间建图，有的评估交互成功，而你们当前最需要的是检验一个弱位姿、持续更新的空间长期记忆库是否形成了合理且可靠的结构。

更具体地，我会按以下顺序推进：

1. 先建立「明确同地点 / 不同地点 / 模糊」的观测关系标注，解决分组非唯一的问题。
2. 再标注少量关键空间事实和拓扑关系，防止模型通过忽略重要信息得到看似合理的分组。
3. 最后利用现有状态快照机制，检查在线记忆在不同时间点的可用性。
4. 保留整体 LLM 裁判，但把它作为诊断工具，而不是唯一标准。

还有一个我认为非常关键的原则：

你们不应该要求 Agent 保留全部空间变化，而应该要求它对自己保留的事实负责，并且不能遗漏预先定义的关键空间信息。

「7帧站台、1帧楼梯」是否正确，不取决于地点名称，而取决于该记忆是否仍能支持重要判断。

如果未来能把这套评测做得足够严谨，它本身也可能成为论文贡献的一部分。但当前先把它作为稳定、可复现的系统验收机制，比急于做成独立 Benchmark 更有价值。
