# 已交付图片仍错认：进一步机制核查

仅复核最后两轮现有输入、输出、历史提交、图片及地图；不新增模型调用，不恢复集成。三类错误中本页分析第2类，但不将“答错”直接解释为模型固有能力上限。

## 1. 最直接的推断错误：类别相似被写成实例同一

旧后端两轮对680-front/100-front的same解释依赖“彩色三角旗、砖楼、消防梯、路牌、街道延伸”等城市共性，而没有说明唯一对应的建筑、拐角及相对布局。地图证实两者为不同路口；第二轮ULVN补440后理由同样用彩旗、店面组合确认同一具体路口，但该来源在另一街段。

这是能在可见输出中确认的过度身份推断：图像已给、能描述对象，不等于能证明同一位置。它不证明模型连物体都看不清，也不证明本输入含足够证据恢复唯一位置；即便无法分清，也不应把相似直接断言为同地。模型有new选项，未被协议强迫必须复用旧ID。

## 2. 可追溯的结构性输入问题：错误历史身份被当成已提交上下文

在test1/request0008与test2/request0011实际输入的data.messages中，上一批641–660的真实历史提交结果已写：

> 与000580历史图同一街角布局（铁丝网围栏、红色雨棚建筑、剧院招牌方向）一致。

并绑定8b1db77f，committed=true；当前previousRegion也以同ID、uncertain=false交付。第一轮ULVN最终用580确认当前661–680的同一街角，**此前相同关联早已存在于冻结历史**。这提供了错误传播/沿用的直接线索，而不是一个干净的初次图像对比能力测试。不能确定模型内部是否依赖该句，未做去历史消融。

历史10536570同时收纳东侧五金店路口、沿街、公园附近和南侧街段。给440这一ID，不意味着440可认证该ID下任何另一街角；但当前输入并未把身份的可靠范围与宽泛历史聚合清晰分开。这是历史库/范围污染，不是新matcher单独产生的。

## 3. 进一步发现的模拟器保真度限制

修正顶层Selected evidence pairs与runtimeContext.revisit后，data.messages中冻结的当前batch文本仍保留原生产批次的preloadedImageIds/preloadNote。例如661当前消息声明661/680/660/640/620/500已交付，而新实验初始实际给的是667/640/670/240等方向组合。历史消息的“已交付”本可作为历史记录，但**当前batch消息**不能与本次实际图片清单混淆。

这不会把已实际展示的100/440/580变成“未交付”，所以具体错误仍属第2类；但说明模型面对的不只是干净图对，还存在不一致交付元数据与错误历史。这限制了“模型能力不足”的因果归因。此次只登记，不再修改/重跑后突破两轮停止条件。

## 4. 什么属于结构性难题，什么属于可改的当前实现

- 真实难题：无位姿、稀疏RGB、重复街景且视角不同，会产生地点混淆；看不到独特锚点或共同表面时，单对图不保证存在唯一定位解。
- 当前实现问题：历史身份已跨范围、已提交错误进入后续Context、当前交付声明不一致，以及语义解释可以用共性特征认证具体身份。它们不是该任务必然无解的证明。
- 模型表现：能拒绝室内外等强反例，却在相近室外街景上过度肯定具体身份。128→1024未消除问题，但每种只有一次、无干净历史/换模型对照，不能给VLM整体能力判死刑。
- 评测问题：固定ID分数会把这类误认奖励为成功，反而把某些合理范围变化算失败，无法给调参提供可靠方向。

## 最有证据支持的结论

**相似室外街景触发了未经充分验证的实例身份肯定；冻结历史中的错误/宽身份关联又为这种肯定提供了现成解释。** 这是比“VLM看错”更具体的系统级失败机制。视觉混淆、历史偏置、交付矛盾各自的因果贡献尚未隔离，不能声称已证明唯一根因，更不能证明只有提高模型或增加图片才可解决。

最后两轮未建立新路线有效性的结论保持，后续实验停止。该结论不否认合法多粒度表达，也不把范围差异本身当错误。
