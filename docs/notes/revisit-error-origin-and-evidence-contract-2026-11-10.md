# 错误记忆来源与“提供证据”是否足够

只读追查原始813主线请求，不新增模型实验。这里定位的是580→641–660这条具体错误关联的产生过程，不冒称找到了整库最早的一次错误。

## 原始发生过程（可见输出与实际图片）

1. `run/unioncity-batch40-realtime813-v1/pi-requests/0048/input.json`实际给641-front、660-front、640-front、620-front、575-front、500-front，**没有580原图**。
2. 同请求可见输出直接提交known=8b1db77f，并引用580；理由说当前与581–604同一区域布局。此时先有身份结论，后补原图核验，不能说已视觉比较580成功。
3. `0049/input.json`随后补交580-front/left/right，工具结果明确只称交付、未确认身份。**该次实际图片只有580三摄，未同时保留641/660当前图。** data.messages只有文本/工具记录，模型适配器以单个用户消息序列化这些文本，再附本次input.images，不会将上轮图片自动恢复为真实视觉输入。
4. `0049`可见输出没有撤回known，而改写为“与580历史图同一街角布局（铁丝网围栏、红色雨棚建筑、剧院招牌方向）一致”。地图与原图复核不支持同一具体街角。随后成为版本57的耐久提交，供下一批previousRegion与Session引用。

因此原始错误不是简单的“同时看到两套清晰图后仍完全分不清”：先在580缺图时作了关联；补历史图后又缺当前图作同轮对照，只能结合当前文字事实/自己的先前结论。这一视觉交付时序是具体可证的结构问题，初始假设还可能产生确认偏置。不能读取内部思维或由此证明模型必然受哪一句影响。

按三类分类：本次产生源头有**第1类关键对照图在同轮不齐**；后续最终两轮100/440/580与当前图同轮交付仍出现错误，则仍有**第2类身份推断错误**。二者不矛盾，不应将整条链只归一个因素。

另一路10536570的范围扩张：v11建立路口；v12明确“沿街道远离路口”仍沿用；v13说明“整体仍属同一街道走廊”。这种范围扩张本身未必错误，问题是后来拿一个宽街道ID下的任意图片证明同一具体路口。宽聚合不能自动产生局部同一性。

## 证据要求已经存在，缺的是证据与结论之间的可核验关系

原程序已经要求reason/sourceIds，最终两轮还要求same/different及占据区域说明。0049甚至真实读回了来源。因此再加一句“请提供证据”不能被声称已经解决。

可讨论的更精确契约（提案，未实施）：

- 判定时同时交付真正比较的当前/历史方向原图，不能把历史读过、文本描述或来源ID当作本轮仍可见图像。
- 把“看见相同类别物体”与“同一实体/区域的独特对应”分开。证据需说明双方来源及方向、可对应的锚点组合和相对布局，而不是只列彩旗/红砖/路牌。
- 同一表面与同一占据区域分开核验，广泛街道与局部路口关系分开表达；不要求所有合法粒度输出相同UUID。
- 要求陈述可见冲突与证据不足；不能把缺证据解释为different，也不能在无法认证同一时强制known。具体如何表达身份未决须遵守/另行明确当前数据集输出契约，不以此擅改架构。
- 来源存在、图片hash和引用权限是机械可验证；锚点是否真正同一、是否证明占据区域，则不是填schema就能验证。几何匹配可增加独立支持，但也不能认证室内外或可通行关系。

**结论：要求提供证据是必要条件；只有“实际对照图＋具体对应关系＋范围限制＋反例检查”才比现有理由/引用更有意义。是否足以克服错误尚未验证，不保证解决，不恢复已停止实验。**
