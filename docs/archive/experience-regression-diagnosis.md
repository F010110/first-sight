# 退化诊断与序列验证版

## 根因（实测，不是推测）

重新计算的 780 对双向第二方向分数与旧 grouping-experiment 缓存逐项一致，0 项差异。退化来自决策策略，不是 SIFT 算法或图片输入改变。

1. **count=1 代替分差判断**：W40→W6=1，W40→W5=0.5；此前因为两者都超过 0.4 就全部待定。W29→W17=1、→W28=0.45；W27→W19=1、→W26=0.583，同样被卡。
2. **视角全交集过严**：W8/W9 在首次顺路经过时以 0.417 建节点；之后 W38 只直接支持 W8，W37 只直接支持 W9。要求每个视角都匹配，把不同视角之间的缺证据当作拒绝加入，挡住了正确重访。
3. **回填机制不是证据生成器**：reconsider 能重查历史，但仍用同一过严规则，W18/W28 仍不成立。声称已修复回填遗漏，必须看真实关联结果，不能只看 API 存在。

## 修复策略

保留原保守模式供消融；`--sequence` 开启新版本。

- 直接双向图像证据必须至少有一方向 >=0.8。
- 同时需要前后半径 2 个观测中至少两对**不同的**多方向强匹配；每对双向至少两方向 >=0.4。
- 支持正序或反序，但中心相邻/重叠片段不能互相验证。单 visit 中心距离必须 >4，避免 W8/W9 这样的相邻过早种子。
- 支持段不能跨超过 10 秒的观测间隔；这是当前明确的实验策略，不是推断“无间隔则无漏帧”。
- 候选分数为双向第二方向分数，按不同身份排竞争，分差 >=0.1；新种子要求互相最佳。
- 节点接纳依据具体视角及序列证据，不要求所有不兼容朝向图像都有直接匹配。
- 保存实际支持配对、版本及拒绝。缺少直接图像证据时，序列不能单独确认；时间边不能作为匹配证据。
- pending 轨迹按访问内连续片段返回，不把分散待定观测伪装成连续轨迹。

这些是启发式、未标定置信度的规则；不同配对不是统计独立，也不能阻止所有整段感知混淆。

## 使用与验收范围

```powershell
npm.cmd run test:memory
node dist/sim/experience-revisable-eval.js run/sim/multiview-val5-clean-20261007 --reuse --sequence
node dist/sim/experience-revisable-eval.js run/sim/multiview-val5-clean-20261007 --reuse --sequence --fault=wrong-loop
node dist/sim/experience-revisable-eval.js run/sim/multiview-val5-clean-20261007 --reuse --sequence --fault=dropout
node dist/sim/experience-revisable-eval.js run/sim/multiview-val5-clean-20261007 --reuse --sequence --fault=weak
```

缓存不存在时去掉 `--reuse` 重算。输出独立保存为 `experience-sequence[-扰动]-eval.json` 和 `-bundle.json`；包含具体证据及 pendingDiagnostics。图和证据实际重新加载一致。

可用范围：现有录制的离线视觉回访关联、待定经历保存、可审计修订与恢复。**不能称实时产品已经可用**：未接实时图像、首次经历仍保留 provisional 片段；全录制多对 SIFT 候选代价较高，尚无增量检索；新数据、分叉、速度变化、整段相似走廊、在线延迟及对象检索精度尚未验证。15/19 是这个已知录制上的开发诊断，不是独立测试集准确率。导航全部仍禁止由时间边授权。
