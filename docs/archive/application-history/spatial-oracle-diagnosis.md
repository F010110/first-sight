# 空间记忆补测逐题诊断

## 核心结论

87.2分说明**本学校、指定记录时刻、粗属性问答链**较顺；不能当作跨段地点关联准确率。Oracle不足是成立的，但目前证据不支持“普遍取错图片，所以算法找图更充分”：主要是回答/引用协议，另有参考证据充分性与标签宽容度问题。

本次只做离线审计，不改原题库、预测和冻结成绩，不增加付费模型调用。可复现代码`sim/diagnose_spatial_oracle_results.py`；逐题诊断`run/school-spatial-oracle-v1/diagnosis-v2.json`（含原图hash复核；v1初次诊断保留）。

## 1. 算法87.2分如何构成

90题：78题满分、1题半分、11题零分，总计78.5/90。

|主失分原因（互斥归类）|题数|丢失任务原始分|
|---|---:|---:|
|输出因引用不合法而被拒绝|2|2|
|内容正确，但没有引齐要求的证据|7|7|
|文字拒答，但abstained=false|1|1|
|场所称谓部分命中|1|0.5|
|错误断言不同楼层为同层|1|1|

原始丢分11.5，换成百分制12.78分。其中10/90=11.11分来自结构化协议和引用要求，1.5/90=1.67分为自动judge认定的内容损失。**这是诊断分解，不是修正后的正式成绩**；不能自动补引用后当作模型原本正确交付。

七道缺引用中，有些问题本来只问当前图；当前三摄已直接展示，却仍要求模型再检索、inspect并在historicalEvidenceIds中引用当前ID。对用户任务而言这混入了额外协议负担。对历史/当前对照题也应区分历史证据引文与当前已提供帧的来源，不必把当前帧再打开才算看过。下一版需要统一规则，但本轮不回改。

文字拒答案例`memq-4885f04c3e1e9c1a61b1`：回答明确说旧录像不能证明学校今天开放，但abstained=false。judge内容给1，程序按不可知题却未拒答置重大风险，最终任务0/损害1。这里既有模型协议错误，也有自动风险覆盖把**flag不一致**等同**捏造危险事实**的评分设计问题。可信97.2不是独立人审的事实安全比例。

## 2. Oracle是取错图，还是不够充分

- 90题oracle选择与题库canonical规则全部一致；78道有答案题的指定参考均实际inspect。
- 去重73组、219张原图hash全部核验匹配。没有发现路径错配、图像损坏或参考ID被换掉。
- 上述验证只证明提取符合现有题库，**不证明题库参考集合足够**，更不证明初标一定正确。
- 算法任务分高于oracle的9题中，7题两组实际查看图片集合相同。不能把这7题差异解释成oracle少拿了图；模型调用过程、记忆文字提示、引用行为、输出随机性和自动评判均不同。
- 另2题算法多看了图：一题为场所识别，一题oracle执行失败。场所题附加图来自第1段134秒，而目标为第9段20秒，并非已证实同物理地点的邻近帧，不能仅凭答对就称其为更充分的空间证据。

Oracle当前90题任务84.4、语义诊断96.7；11题语义满分却任务不满分。明细：8次引用类输出拒绝、1次JSON引号未转义、1次答案正确却abstained=true、1次对比题漏引当前帧；另有1次执行失败、2题场所称谓半分、1题跨楼层错误。**Oracle端到端上界尚未校准**，不能声称算法超过理想记忆。

## 3. 真正的空间错误：跨楼层

`memq-ed20bdf1225098a28263`，第8段26秒与80秒（P0007）：原生同路线Z差约5m，题库依据还包括楼梯经过。但oracle只给两个端点三摄；算法也只inspect同两个端点，均因相似地砖/墙裙而猜同层。

算法回答虽附“装修一致不能严格证明同层”的限定，仍先断言“很可能同层”“同一连续走廊”；故不能算已解决。两个观察在当前库的placeId不同，也没阻止回答模型把“相似”当成“同层”。不同placeId本身当然也不能证明不同楼层。

这里至少两层问题：
1. **证据链不足**：两个相似端点不能可靠推出层间关系；题库应指定支撑上楼过程的因果序列，而不只用私有pose定答案。
2. **推理与拒答**：缺垂直关系证据时应不确定，不能凭外观相同肯定楼层。

这不是扩大到全部2553张图的理由；可以另做有明确证据选择规则的楼梯过程诊断，检查正确过程证据是否让oracle改善。需保留新旧结果，不能把私有pose当答案喂入。

## 4. 标签与判分的可疑边界

源图直接查看发现需人审/可接受答案复核：

- `memq-0571a67173c9f63aa6d3`：参考“室内走廊”，图中确有储物柜、长凳和更衣区；oracle答“更衣室/储物间”得半分。算法记忆reason也写“大厅/更衣区”。不能确定这是模型认错，可能是题库粗标签过窄。
- `memq-b299e86e332ee7b577ff`：目标图是暗处砖墙、通向室外的门洞及楼梯结构；oracle场所推断不精确，但参考“走廊”和算法“底层大厅/走廊”也有边界/功能不确定性。算法“底层”还被judge扣附带风险。粗属性题不应以无任务后果的区域命名差异过度扣分。
- `memq-7907dfd3c65b14c20eae`：算法答地下通道/站厅样空间而被半分。图像确为有转角、墙面和楼梯结构的通行空间，“像地铁站”可能是过度功能推断，但仅场所同义/粗粒度差异不宜混同地点身份错误。

以上仅是本次助手图像复查，不冒称独立人审。原正式成绩不更改。

## 5. 高分究竟检验了哪些能力

实际trace显示：

- 76/90题调用公开“第N段T秒→活动时间”查询桥。
- 只有4/90题调用placeId过滤；不能据此推定多数题依赖重访/合并能力。
- 78道有答案题，参考证据都存在于模型已查看图像与直接提供当前帧的并集中；本题库主要不是找不到记录，而是输出/引用/少量推理问题。
- 题库重在室内外、场所类型、地面材质；合成长期时间包含关机空档。短长期任务93.3分，不等价于自然语言找物、空间路径或长时状态跟踪93.3。

**可以肯定**：已建空间库的原始证据保存、按记录定位、工具查看及多数简单历史属性回答工作正常。

**不能肯定**：跨路线同一地点识别、错误合并/拆分的任务影响、层间关系、自然找物、对象状态变化或跨环境泛化已达到相同水平。

## 6. 下一轮优先级（不覆盖本轮）

1. 修正下一版输入/引用协议：当前图有来源ID即可作为当前证据，不强制重新inspect；历史证据仍必须真实查看和引用。oracle逐图标签与正常检索输出的证据元数据结构对齐，避免工具提示说“先search再inspect”和“无需检索已提供”的冲突。
2. 分离内容、引用和协议flag错误；flag冲突不自动伪装成捏造事实的重大风险。保持三卡的用户任务/后果含义。
3. 审核上述场所替代表述，以及跨楼层所需楼梯过程证据；新版本真值/证据先冻结，再看新预测。
4. 补不依赖精确时间地址的地点关系/重访任务，明确目标地点、可能别名、可接受证据和楼层结构；按问题后果评算法的合并/拆分，而不是直接用分区数量打分。
5. 再比较oracle和算法；没有必要现在跑超大Full memory。
