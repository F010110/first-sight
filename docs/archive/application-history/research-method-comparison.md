# 现有算法与First-Sight逐层对照

日期：2026-10-17。比较对象是本地当前实现（冻结v1＋显式启用的v2实验），不是尚未实现的产品设想。外部方法尚未在本机运行；源码核查不等于性能复现。未检查到某项能力不意味着外部方法绝对没有该能力。

## 1. 先明确我们实际在做什么

当前学校试验：同步front/left/right三图，2秒一组→颜色布局/直方图门控→最多4组因果窗口→最多3个旧地点候选→VLM输出逐观察placeId/new/null→SQLite持久化。

- **记忆主单位是观察与地点**，不是完整物体级3D图。地点有UUID、摘要、candidate等状态及首尾代表观察；历史观察单独保留。
- **身份主要由VLM决定**。v2颜色特征只选候选，不能建立身份；new合法就可以生成新UUID。JSON/白名单校验不等于语义一致性校验。
- v2图库检索按历史观察扫描O(N)，候选和模型上下文有界，不是ANN检索；最多1近期＋2视觉候选并去重补位，不是全历史同时给VLM。
- 数据库支持merge/split/confirm/undo，能重建部分派生访问/转移关系；这不代表自动发现错误、自动纠错或所有下游审计都已完整重映射。
- 当前转移是时间序列关系，不是度量地图、通路或物理邻接。没有可靠全局坐标，也不应该据此回答米制距离和可达性。
- 门控是离线因果预处理实验，尚非默认实时服务完整质量/遮挡/运动门控；跳过帧未进入本轮身份分类库，原始图仍在源数据。
- 长期检索已有词法/时间/地点约束与证据工具，但没有EgoRAG同等完整的跨日分层摘要检索基线。

## 2. 哪些方法与我们是同层比较

| 方法 | 核心输出 | 对应我们的层 | 替代关系 |
|---|---|---|---|
| SALAD | 图像全局描述子 | 72维RGB描述子 | 可局部替换特征提取/检索，不替代身份服务 |
| AnyLoc | 通用视觉特征聚合描述子 | 同上 | 与SALAD是可比较候选，不必一起堆叠 |
| LightGlue | 两图局部特征对应 | 我们目前缺少的图像匹配证据 | 新增候选验证层；RANSAC需另外配置 |
| DirectMe关键帧选择 | 有限多视角代表帧 | 首尾代表观察策略 | 可替换/对照代表证据选择，不是调用门控 |
| DirectMe完整系统 | 物体级度量图＋检索QA | 感知→建图→查询的大部分链路 | 应先独立复现，再决定移植模块 |
| EgoRAG | 历史视频证据和QA答案 | RequestAgent历史检索/问答 | 补查询层，不替代地点ID |
| LMEE/MemoryExplorer | 探索行动及记忆问答 | 目前未做的主动导航闭环 | 任务和依赖差异大，非近期替换 |
| EgoMonth/MeMoREval | 数据、任务、评测协议 | 评测层 | 不是现成地点识别算法 |

## 3. SALAD与我们的区别

**现状**：每图4×4 RGB布局＋每通道8-bin直方图，共72维；三摄集合距离聚合，按地点取最佳历史观察。便宜、直观，但颜色/曝光/视角变化会扰动，类似墙面可能误检。

**SALAD**：DINOv2视觉编码＋学习过的聚合得到全局检索描述子。优势是利用纹理、结构和学习到的不变性；已有预训练推理入口，无需先训练我们自己的网络。需要Torch/权重，算力和索引存储高于颜色特征；本机延迟、逆向视角和相似教室效果尚未测量。

**边界**：它优化“检索相关地点图片”，不是输出语义房间边界或持久UUID。不包含unknown/new决策、SQLite修订和API预算。我们的100/116秒案例已召回正确候选，单换SALAD不能解释或消除后端new决策错误。接入后仍须分别测召回率和最终身份，不拿排名代替建模准确率。

## 4. AnyLoc与SALAD及我们的区别

AnyLoc也做全局地点检索，采用预训练视觉基础特征及VLAD等聚合，不要求先为我们场景训练监督式VPR网络。相比SALAD现成固定预训练入口，AnyLoc实验通常需明确选择骨干、特征层、聚合方式和词表；词表及缓存带来部署配置成本。不能把“无需训练骨干”说成“无任何拟合/域配置”。

对我们两者都应接在同一个描述子接口后；第一阶段分别比较，不先融合。新描述子通常不在[0,1]、也不一定72维，当前校验、版本字段、距离函数和索引必须适配，不是仅换Python命令。重建索引保留版本，不覆盖旧基线。

## 5. LightGlue与我们的区别

我们现在给VLM整张历史原图，请它直接比较，然后相信其合法格式的身份输出；没有“哪些点对应、几何内点多少”的中间视觉证据。

LightGlue在关键点/局部描述子之间匹配，配合ALIKED或DISK等提取器。可再用RANSAC验证基本矩阵/单应等适合模型；使用何种几何模型取决于标定、场景和视角，不能统一将单应成功解释为位置一致。

它提供可画出来的对应和一致性证据，而非自然语言解释。能用于少量候选重排或提示“已有强匹配，应复核新建”，不应单独强制合并。隔门看同一场景、沿同一面墙、重复窗格都可能产生匹配；朝向相反/遮挡严重也可能匹配失败。成功不等于同房间，失败不等于新房间。计算量应由候选数量、关键点上限和缓存约束。

## 6. DirectMe与我们的区别最大：几何物体记忆 vs 语义地点身份记忆

| 维度 | 当前First-Sight | 已检查的DirectMe实现 |
|---|---|---|
| 基本实体 | 三图观察、地点、访问及时间转移 | 物体实体、3D位置、属性、轨迹、地点聚类 |
| 空间基础 | 视觉证据＋VLM语义，没有可信全局坐标 | 世界坐标中的物体锚点，深度/位姿/内参适配 |
| 身份关联 | 旧候选图片→VLM选择旧/new/null | 物体级多线索关联：几何、标签、颜色、embedding、track等 |
| 地点构建 | 直接逐观察判断所在具体区域 | scene_tag分组＋世界坐标质心半径聚类物体 |
| 动态更新 | 新观察追加，人工/API可逆修订 | 位置置信加权EMA；可移动物体大位移时覆盖位置等 |
| 查询 | 时间/地点/文字检索＋原观察证据 | 意图解析、图实体筛选、相对于查询姿态计算方向等 |
| 代表证据 | 默认首尾，召回可临时用匹配历史图 | embedding最远点多样性选择，bbox面积回退 |
| 历史身份保障 | UUID＋显式修订/undo，仍有未完成派生一致性工作 | place_induction每次重建place_000序号；不能直接等同稳定修订身份 |

DirectMe不要求必须用IMU积分：Scal3R等可以从视觉估计几何。因此“我们不信IMU位移”并不是排除它的理由。真正问题是2秒稀疏三摄输入能否可靠重建、不同块/会话坐标能否对齐、模型成本能否接受。

它的动态位置融合不等于完整事件溯源；我们的数据库undo也不等于物体运动跟踪。两者各自解决不同的“更新”。源码对每物体观察列表有默认128条上限，不能未经审计就说保存完整全部历史。检索器as_of筛选里能看到按首次观察时间过滤节点；要验证过去时刻查询还需审计属性/代表帧是否也来自正确时刻，不能仅看有时间参数就认定不泄漏。

特别注意：3米半径聚类的place与我们期望的“隔墙分开的两间教室”不是同一定义。复制该函数不能保证解决房间边界，反而可能拆长走廊或合近邻物体。完整DirectMe适合作独立基线，不宜只拿聚类函数换掉VLM身份判断。

## 7. EgoRAG与我们的区别：经历检索，而非空间定位

它按视频片段生成描述并向量化，以日/小时事件摘要定位时间范围，检索片段，再从视频/文字抽取证据来回答问题。主要组织轴是时间和事件，不是稳定房间节点。

我们的地点关联能限定“同一个地方的全部访问”，但仅靠地点ID无法准确回答“上周我跟谁谈了什么”。EgoRAG的时间/语义检索更直接适配后者；它反过来也不会自动解决“100秒是否是0秒的同一通道”。

可复用分层时间检索、embedding数据库、原片段复核；仍保留我们的原图/时间戳、权限、失败记录及unknown。公开实现中的数据集日期/路径约定、外部模型调用、错误时随机选择选项不应直接照搬。生成摘要有持续写入成本，查询也有多阶段调用成本，不是免费的长期压缩。

## 8. LMEE及评测工作的区别

LMEE包含主动探索、多目标导航和强化学习：Agent行动改变未来能看到什么。我们当前是被动接收记录，没有动作策略、导航地图或探索奖励。直接采用会同时引入模拟器、资产、训练和导航评价，远超替换视觉记忆模块；适合未来有主动导航目标时再评估。

EgoMonth重点是跨天证据依赖；MeMoREval比较图像/文字/场景图的写入和读取成本。它们提供检验我们长期记忆是否有用的方法，不提供可直接替换当前身份判断器的完整算法。特别是MeMoREval完整代码尚未发布，不能列为立即可复现的算法基线。

## 9. 对当前失败分别能做什么

| 已知问题 | 有帮助的现成方法 | 不能承诺的部分 |
|---|---|---|
| 颜色近似但实际不同/跨视角难召回 | SALAD或AnyLoc | 不保证室内相似布局的最终身份 |
| 旧候选已召回却输出new | LightGlue证据＋独立的新建复核决策 | 单换检索器无效，匹配也不能强制同房间 |
| 历史参考都朝同方向 | DirectMe多样性代表选择 | 不等于在线门控，可受质量差帧影响 |
| 错误身份污染后续上下文 | 现有可逆修订＋证据复核 | 上述检索器都不提供完整自动回滚传播 |
| 跨日查经历/事件 | EgoRAG式时间层级＋向量检索 | 字幕遗漏不能靠摘要凭空恢复 |
| 要判断物体方向/位置变化 | DirectMe几何图及视觉重建 | 没有可靠坐标就不能报可靠米制关系 |
| VLM调用过多 | 明确的观察/调用门控与预算控制 | VPR的地点不变性可能忽略重要局部物体变化 |

## 10. 结论和路线

我们应保留持久证据、UUID、修订/恢复、隔离真值和预算这层工程骨架，复用成熟视觉前端与检索算法；这不是宣称我们的骨架具有科研原创性。当前视觉表示和身份决策仍是明显薄弱点。

近期路线：SALAD与颜色基线等条件离线比较→少量候选ALIKED/DISK+LightGlue验证→针对新建/复用矛盾加入受限复核→EgoRAG式历史问答。DirectMe另跑作者demo并审计几何/历史语义，再决定是否采用整套物体图路线。不同时换场景、特征、身份策略、门控和候选预算后声称某单模块有效。

验收应分开统计：候选召回、几何验证、最终身份误合并/误拆分、unknown、事件证据召回、查询正确率、延迟与调用/token成本。不能把任一单项改善替代长期记忆整体成功。
