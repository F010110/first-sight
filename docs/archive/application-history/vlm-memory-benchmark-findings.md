# EgoMonth / SuperMemory-VQA / MeMoREval：VLM角色与接入边界

核查日期：2026-10-17。本文核查原论文及官方仓库，不代表已复现或已接入外部算法。用户已认可复用方向，具体模块应分阶段独立验证，不一次性开启全部模型。

## 1. 纠正“这些研究不用VLM”的理解

- SALAD、AnyLoc是图像特征与检索模块，LightGlue是局部特征匹配模块，不依赖生成式VLM来逐观察给出语义身份。
- EgoMonth是MLLM/VLM评测数据集，不是非VLM算法。
- SuperMemory-VQA评测Video-RAG、EgoButler等VLM系统；数据构建本身也使用Gemini进行视频描述、QA生成/验证，再由人审核。
- MeMoREval明确区分writer和reader：图像可直接存档、不经过描述生成；reader仍使用视觉语言能力查看存档图。部分记忆后端writer使用语言模型，transcript后端无LLM writer。
- EgoRAG、DirectMe的问答链路也可使用语言/视觉语言模型；不能因为视觉前端使用专用模型，就称完整系统不使用VLM。

## 2. EgoMonth

原论文：https://arxiv.org/html/2608.13113v1 ，§4.1明确列出Qwen2/2.5/3-VL、其他视频MLLM及Gemini 2.5 Pro等12个模型。开放模型有固定帧预算，Gemini按1fps输入。问题为四选一，答案直接与GT比较；“不用LLM-as-judge”不是“不用VLM回答”。

数据总计约301小时、20人、跨20–120天、1443 QA；不是单一连续120天视频，更不意味着模型把全部301小时同时装入上下文。论文报告宏平均71.8%、人类94.2%，不能与我们几何重访代理或单段身份结果直接比较。

用途：跨日、跨视角、稀疏事件检索与方向/路线推理外部评价；不是现成的地点身份模块。原论文说明视频有额外审批、研究用途与禁止重分发/商业使用约束，不能把仓库/数据可见当作云端上传许可。

## 3. SuperMemory-VQA

原论文：https://arxiv.org/html/2606.00825v1 ，重点§3.4、§4.1–4.3。
官方仓库：https://github.com/AIoT-MLSys-Lab/supermemory-vqa 。当前README主要说明标注流水线和人工审核UI，不能直接把这些命令当作线上记忆助手的推理程序。

数据52.9小时、10名参与者、4853 QA；发布说明包含RGB、转写、眼动、IMU和SLAM轨迹。**有这些传感器数据不等于论文主基线把它们全部输入推理，也不等于依靠IMU积分维持地点身份。**

论文描述的Video-RAG：
1. 预计算ASR、OCR、物体检测等辅助文本库。
2. VLM把问题拆成检索需求。
3. 用Contriever embedding＋FAISS检索；30分钟shard，限制为问题之前的历史。
4. 合并检索文本，与最相关shard的32张均匀采样帧一起交给VLM回答。

EgoButler：VLM生成30秒窗口、1fps视频描述，结合WhisperX转写；再生成小时/天摘要；查询时从粗到细定位历史，取相关描述交给VLM回答。不是无VLM记忆算法。

在这些主基线描述中，未见明确用IMU/SLAM轨迹作为核心问答检索输入，因此不应称它已证明传感器融合带来提升。未来接入真实轨迹必须作为显式额外输入条件，与RGB-only分开，遵循no-oracle原则。

论文测answerability F1、四选一准确率、MRR；强调拒答校准，过度拒答也会失败。可借鉴证据不足拒答、多证据追溯、ASR/OCR检索和问题时刻因果截断。标注ledger、答案、解释和证据时间戳不得作为被测Agent的检索提示。

## 4. MeMoREval：原图不是零成本推理，场景图不是自动视觉建图保证

原论文：https://arxiv.org/html/2610.12561v1 ，重点§3、§4.2、§5.1–5.3。
仓库：https://github.com/jimwang418/MeMoREval ，完整模拟/记忆后端/Agent/评分代码仍标注评审后发布。

区分两条路径：
- 先为每帧生成描述→保存文字→读取文字。写入时已支付视觉理解成本，且细节可能被描述遗漏。
- 直接保存图片→有问题后检索图片→reader查看图片。省去逐帧描述开销，但读取时仍有图片token、推理、检索及系统存储成本。

主实验的不同模态共享文字记忆；frames条件是文字记忆＋图像，frames+graph是再加图快照，不是“纯图片完全没有文字”。主要writer输入是文字观察，sighted变体才额外给writer图像。desc条件也使用同一模型另做描述调用。

文中模拟视觉图带bbox与整数物体ID；物体检测及空间记录来自模拟器状态中已被观察的物体，图含世界坐标、支撑/包含关系。真实机器人演示使用SLAM地图及人工物体/关系标注。**它控制比较记忆模态，并未证明从普通RGB自动构图既准确又零成本。** 我们自己的同类实验如要提供这些信息，必须作为单独oracle/辅助条件，不能污染RGB-only输入。

报告的主要模型汇总结果：文字约39%、描述约56–60%、frames约70%、frames+graph约75%任务成功。其主条件中frames仍有共同文字记忆；这些数字依赖特定任务、模型、后端和运行设置，不是所有场景通用定律。论文明确不同模型的frames/desc排序可能变化。

它主要比较模型推理写入/读取成本，不能将结果直接替代端到端存储、视觉建图、传感器、带宽或我们实际端点账单。保留8–55%帧的选择性存储变体成功率下降，也不等于我们只门控VLM调用就必定丢失所有这些证据：我们原始90组仍保存，但当前身份库只对62组分类，跳过28组能否被问答检索访问仍需接通和测试。

## 5. 对First-Sight的实际调整

核心不是去掉VLM，而是区分存档、理解/索引、查询三个时机。

建议可组合但互相独立的实验分支：
1. **图像存档基线**：原图、时间、来源可查询，零逐帧描述；有问题时才给reader检索到的少量图。
2. **视觉检索/验证**：SALAD或AnyLoc＋有界LightGlue；两种全局描述子先作为替代选项而非默认双开。
3. **可修订地点记忆**：保留当前UUID/修订层，VLM语义判断与独立新建复核，不自动将图像相似当成房间身份。
4. **经历检索基线**：EgoRAG/Video-RAG式时间层级与文本/图像证据，ASR/OCR等在数据确有且许可允许时加入。
5. **几何物体图基线**：独立DirectMe，使用预测几何而非隐藏真值；对象ID、来源坐标、不确定性必须记录。
6. **模态对照**：共同文字＋frames、共同文字＋desc、共同文字＋frames＋预测graph；oracle graph仅作独立上界条件。当前地点转移图不等同物体场景图。

验收分开记录写入VLM、查询VLM、本地计算、原图存储、候选召回、问答准确性与拒答；同一数据/模型/预算下比较。不得把“只创建接口/配置”或“借鉴论文流程”写成官方方法已完成复现。外部权重、硬件依赖及许可核实后再逐阶段运行，保留冻结v1。
