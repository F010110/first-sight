# 地点分组评测流水线 v1（不依赖API、不训练）

## 要回答的问题

不是“图稳定吗/有多少节点”，而是：同一局部观察/活动范围是否保持一致，跨范围是否分开，未知有没有被诚实保留，回访和路径是否还找得到。

Place定义先固定：观察者所在的局部活动范围，容忍旋转与小范围重定位；不等于一张图片、朝向、对象类别、精确坐标或整间房。功能区标签、房间层与Place实例分开。原地看到洗手盆和马桶不能据此切两组。同一空间可能有多个合理层级，模糊样本不强行定真值。

## 两条轨道必须分开

1. **求解器轨道**：固定人工/自动证据，比较greedy、refinement、精确小图。只报告成本差、稳定性、证据撤销、错误桥接；不称地点正确率。
2. **空间正确性轨道（主评测）**：固定未参与调参的原图/真实视频/实际路径，人工先标注，再评价算法输出。API可辅助，但不能作为唯一裁判或自动覆盖人工意见。

人工证据输入试验可评机制，不能与自动证据流水线混为同一排行。

## 第0步：冻结数据、定义、算法版本

- 为每段录制保存原始帧、时间、相机参数、访问顺序、执行结果（模拟）或原始视频/人工路线记录（手机）、缺帧及失败动作。禁止用插值帧验证运动。
- 仿真坐标/room/action供评测员核验运动事实，不给识别器；手机可由人工视频回放记录转向、过门等事件，不能将计划路线当实际路线。
- 按房屋/场景/录制隔离开发与留出集，不随机拆邻近帧。不在留出集上挑阈值。版本/hash、参数、运行时间与证据来源存档。
- 最小首批建议至少6段独立录制，覆盖原地转向、小移动、门口停留/穿越、折返重访、相似不同区域、开放活动区/遮挡；这是试验覆盖建议，不是统计充分性保证。40观测val5固定为开发集。

## 第1步：先人工看完整经历，再盲标

评测员先看真实顺序的视频/全部视图和路线，不看算法组号、输出理由或置信度。标注以下关系：

- `same`：足够证据支持同一局部范围；原地旋转是明确正例。
- `different`：有真实范围变化或边界两侧证据；不能因画面不相似、距离大、对象出现/消失就标different。
- `unknown`：缺观察、遮挡、边界模糊，或细/粗层级解释不同。

每条必须含观测对、类别、原图引用、评测员和理由。类别为rotation/small-move/boundary/revisit/similar-distinct/activity-scope。纯旋转样本必须看中间真实运动；同端点只作为必要一致性检查，不替代整个Place范围标签。

推荐两名评测员独立标注；不同意见经回放讨论，未解决记unknown。单人可用，但明确标单人、非盲或开发评测，不能声称独立测试。记录原始分歧率、讨论后unknown数，不悄悄剔除难例。

## 第2步：固定抽样，不只挑容易的重访

在看输出前冻结观测对清单：

- 所有真实纯旋转片段内代表对、所有过门前后/门口停留对、所有已确认回访对。
- 每类加入小移动和同物体不同站位，以及相似但不同区域的困难负例。
- 加入非邻接对：一段平移链首尾、门两侧都能看到同一设施的对，检验链式漂移。
- 留出集样本数和类别分布写入manifest；当前某类没有标签就显示“未覆盖”，不能算0错误。

先做确定的几何/运动事实标签，再标活动范围；两者单列。不要靠固定米数或“一房间一组”强制画边界。未知不能自动当负例。细/中/粗解释分别评，不能事后选最好看的层级。

## 第3步：运行算法并冻结输出

使用同一录制、相同感知证据预算分别跑基线和新方法，保留全部观测及unknown。人工标签文件不得被识别器读取。离线全历史分组与在线前缀分组分开报告，不能用未来帧成绩冒充在线识别。

## 第4步：自动汇总人工关系评分

已实现 `src/agent/region-evaluation.ts` 与 `src/sim/region-score.ts`。输入算法组和独立标注，不调用API。

```json
{
  "protocol": "first-sight-place-pairs-v1",
  "split": "held-out-house-a",
  "blind": true,
  "judgments": [{
    "id": "rotation-1", "a": "observation-22", "b": "observation-23",
    "relation": "same", "category": "rotation", "reviewer": "reviewer-a",
    "rationale": "原始连续帧与实际路线确认只转向，无平移",
    "frameRefs": ["frames/0066.jpg", "frames/0067.jpg", "frames/0069.jpg"]
  }]
}
```

上例只是格式示意，不能把val5写成真实留出集。正式标签要有完整清单，重复对、缺预测观测会报错，不默默缩小分母。

```powershell
npm.cmd run sim:regions -- <录制目录> --refine
npm.cmd run sim:regions:score -- <录制目录>/region-partition-refined-eval.json <标签文件>.json <新评分文件>.json
```

算法不同非单例组=建议分开；同组=建议合；任一观测unresolved=拒答。评分不把建议分开当已验证事实，但会统计其与人工判断的冲突。

主指标必须一起给出：

- **误合并数**：人工different，算法same。
- **误拆分数**：人工same，算法different。
- **拒答数/覆盖率**：确定标签中算法能给归属的比例。拒答不是误拆分，但不能从报告中消失。
- **同区域恢复率**：人工same中算法same的比例；拒答计为未恢复。
- **不同区域恢复率**：人工different中算法different的比例；拒答计为未恢复。
- **有输出样本正确率**：只在非拒答样本计算，必须与覆盖率并列；不能拿低覆盖的100%当可用。
- unknown标签不计算对错，但统计算法给出建议的数量，供人工审查过度断言风险。

全部指标按六类分层、按录制逐段列出，空分母输出null，不输出100%。不同粒度的标注应分别生成评分文件。

## 第5步：逐组审图和边界时间线（不能省略）

关系分数只是必要检查，还要对每个最终组看全成员原图和实际路线，记录：合理/过粗/过碎/包含错误区域/不足以判断。对所有unknown看是否是真歧义，还是明显内部观测漏覆盖。给每个问题列具体W/tick和图片，不只写汇总数字。

对已人工标注的穿越事件，记录首次正确区域变化时间、提前切换、漏切换、反复切换和修复延迟。缺失该事件检测模块时写“未实现”，不能将分组最终正确充当及时检测成功。现评分器只实现关系评分，这一步需人工表格/时间线，后续再自动化。

对象检索另评：问题→引用历史帧→人工确认对象/时间/位置描述；历史见过不代表现在在场。时间边不授予导航许可。

## 第6步：形成验收报告

每个版本报告必须含：数据/版本、盲评及标注人数、六类样本数、误合并/误拆分/覆盖率、逐组图例、边界时延、未知原因、回访覆盖，以及辅助压力测试。

第一阶段门槛：留出集原地转向不能明确误拆；无证据不能强行合；明确通道重访不可全部拒答；关键过门事件需说明正确/延迟/漏检；人工逐组不能发现跨独立范围的明显错误合并。具体允许误差和覆盖目标需在正式评测前冻结，不从当前数字反推。门槛通过仅支持离线试验继续，不能授权安全导航或生产上线。

## 本轮已跑结果

开发标签 `docs/experiments/region-judgments-development.json`：19对同实际端点、2对已复核的不同空间、1对活动范围unknown，共22对。**非盲，同一录制，且部分布局关系也出现在输入证据中，因此不是独立精度评测。**

基线与refined均：21对可评分，16对有输出、5对拒答；覆盖76.2%，同位置/同区域恢复14/19=73.7%。选定确定样本没有误合并/误拆分，但两者都把人工unknown的W16/W22合为一个粗组；须继续逐组审图。没有small-move与similar-distinct独立标签，不能据此宣称通过全评测。

求解器refinement在200张6节点合成图上，将非最优次数19降至13、最大成本差3降至2；**真实录制仍3个粗候选/11未知，没有分组质量改善证据。** 说明这次只改善了求解，不补充证据就无法解决粒度和漏覆盖。
