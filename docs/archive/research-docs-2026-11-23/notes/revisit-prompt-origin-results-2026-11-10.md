# 从错误源头重试：提示词实验最终结论

## 明确结论

**单靠本次提示词修改，不能可靠解决当前qwen3.8-flash路线的同地认证与分组问题。** 提示词有局部效果，但没有一组满足预先冻结的两次完整通过要求。因此不采用这些提示词作为修复，不继续当前VLM单独裁决地点身份的集成路线。本结论针对当前模型、输入/执行方式与预算，不将其偷换为所有VLM/所有视觉方法都不可能。

本次不是因为跑得慢就判失败：主要负例在约20–35秒内已经产生语义误认；一项后续判断43.370秒另有处理预算问题。

## 输入控制与证据

源头为原0048、v57前历史；当前641/660与历史580三摄同轮展示。之后只接本诊断分支结果，不复制原错误v57提交；正对照380/65无历史消息。三组的图片、模型、128推理预算、3000输出相同。未交地图/坐标/参考答案，事后使用此前hash核验过的地图和原图裁决。

初次中断前有效baseline-origin复用，其余17次在修正目录完成，共18个阶段结果。中断造成另1次未知调用预留，保留不清零。原始结果：`run/unioncity-revisit-prompt-origin-v1-corrected/report.json`；输入与响应在requests；免费结构审计 `structural-audit.json`，由 `scripts/evaluation/audit-revisit-prompt-origin.py`生成。

这是冻结历史、诊断分支与临时别名测试，不是生产Pi/SQLite真实提交，不能拿protocol-valid当服务完整性通过。没有依据将整库每一个此前错误都说成已清除；本实验隔离了v57这条具体错误提交及后续传播。

## 三组具体结果

|---|---|---|---|---|

本次不按固定ID计语义成败。负例是地图上不同的具体路口/街段，不是店前人行道与附近路口的合法粒度差异。允许宽范围关系另作scopeRelation，但不能用宽关系把same具体占据区域判定偷换过去。

### 已要求证据，仍然错认的实例

反例组第0次origin看到了两边三摄，详细列举660的石柱大门/NEWS THINGS和580的铁丝网围栏/雨棚，却仍将消防栓、彩旗、LAUNDROMAT等共性说成同一街角几何，并把围栏缺失解释为朝向差异，最终same。

同组第1次相同输入能依据石柱大门/报刊亭与围栏/雨棚的差异输出different。但其successor又把680/100说成同一个路口不同朝向。**不是从来没有辨别能力，而是不能在同样条件下稳定把可见差异用于身份否定，且会用视角或范围解释消解反证。**

具体对应组能稳定区分两组后续负例，说明提示词确实有作用；但它没有稳定阻断源头错误，也没有形成合格的完整分组/引用输出，不能以局部胜利当修复。

### 口头证据正确，不代表记忆操作正确

六次380/65正对照checks都识别same，排除了“只是全部拒绝重访”的假改善。但原规则基线两次都new；强化组还出现未交付来源与字段层级错误。这一明确同店门前的正例，显示证据判断与记忆操作仍可能脱节，不是固定粗细边界不同就能解释全部问题。

原report只把三份标invalid，免费结构审计另发现correspondence第0次control的location错误放在segment顶层、assessment缺location；它应按生产schema拒绝。该事实单列，不覆盖原报告或静默修复。协议问题与语义问题分开，不能拿这四个结构失败证明看图本身不行；剩余已交图错认足以使本次提示词方案不通过。

## 为什么这次可以作工程判断

1. 原v57错误提交已不再输入，源头错认仍出现，不能只归于那条既有错误记忆。
2. 当前/历史三摄同轮交付，不能只归于本轮缺580或当前图。
3. 修改的提示词明确要求锚点对应、独立反例核查，仍出现具体路口误认及重复间相反结论。
4. 真同地对照没有全部被拒绝，局部匹配能力存在，但稳定身份认证/正确操作要求未满足。

因此当前可采纳的结论是“提示词不足以让此方案可靠”，而不是“只要再换一句就能解决”。不将它解释为数学上的提示词不可能性，不把不稳定误认自动推广至所有其他模型。
