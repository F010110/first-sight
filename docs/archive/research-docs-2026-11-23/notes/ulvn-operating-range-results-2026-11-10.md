# ULVN视觉前端：适用范围结果与混合路线提案

## 结果范围

固定18任务×2后端×2遍=72次本地请求全部成功，0付费VLM。第二遍仅作暖缓存测量，不扩大质量样本数。模型为MegaLoc＋SuperPoint/LightGlue＋基础矩阵RANSAC；**没有测试完整RAVEL图/BPL概率定位，不能称完整ULVN胜出。**

原始：`run/ulvn-operating-range-v1/report.json`、逐请求JSON；汇总`summary.json`；固定计划和地图/原图hash见plan；10组图对接触图在free-review。构建通过、5项ULVN相关Python回归通过。

## 1. 哪些场景出现收益

### 近位置重访，尤其方向变化或局部可见

评测侧使用200平面source单位、垂直差≤48的固定邻域，8个检索查询中4个有合格历史来源：220/360/378/388。它是物理锚点检索，不是语义区域准确率。

|排序指标|旧后端|ULVN前端|
|---|---:|---:|
|几何排序Top1命中|3/4|4/4|
|几何排序Top3命中|4/4|4/4|
|全局排序Top1命中|4/4|4/4|

100单位时合格查询3个，几何Top1为2/3 vs3/3、全局Top1为2/3 vs3/3；400单位仍4个，结果与200一致。不能选择一个半径冒充唯一语义标准。

最明确的排序改善为388：当前位于五金店门口内侧、朝向与历史68明显不同；旧后端几何Top1误排101、正确68在第三，ULVN把68排第一。**但旧后端全局通道本来已把68排第一**，所以这证明几何排序更可靠，未证明原双通道系统完全找不到它。

公园220/138匹配实际跨right→left；入口转头325/324跨left→front。两后端均找到了这些图对，不能因ULVN内点更多就算新增正确案例。它支持“不应只拿同方向front比对”，不代表ULVN独占此能力。

### 此前误认的不同路口：ULVN给出了有用的弱关联信号

这10个图对任务两端均完整验证9种方向组合，排除“新后端没检查负例”的解释。

|388/68|同门口附近、方向不同|113 / 0.340|

这批正负例在ULVN自身分数空间分离明显，能够为VLM此前把共性街景直接确认同地的结论提供“缺乏几何支持”的警示。旧后端的全局布局分数对这些负例仍较高（0.633–0.763），但SIFT内点也只有10–16；不能说旧后端没有任何拒绝信号。不同算法分数和内点不直接横比概率或准确率。

**不据本表选择50内点或某余弦阈值上线。** 只有4正例、3已知开发负例，不能用分离现象证明通用强匹配门槛，更不能把低分直接解释为不同地点。

## 2. 什么范围不应交给它直接决定

### 档案没有近位置来源/新环境

660/680/780/813在本次稀疏档案中没有400单位内且同高度的参考，不能算4次正例漏召回，也不代表从未到访。两个后端仍都会返回最佳候选；ULVN例如813返回581、32内点/约0.120。**Top1始终存在不等于已定位。** 开放集拒绝、未决、新锚点创建还没有被本接口解决。

### 语义边界和区域粒度

三组边界得到ULVN低关联：388/380室内外19内点/0.018；300/280店内外9/-0.014；340/320下沉楼梯/巷口12/0.108。本轮未出现边界强匹配，不能谎称已经实测了“强几何但门内外不同”的全部失败模式。

这些低关联最多提示视图变化，不自动说明进门、下楼或区域类别。即使以后共享表面强匹配，也不能自行认证同一占据区域。物理锚点、语义区域、宽街区的层级关系仍需另行表示，不能要求同一UUID切法。

## 3. 实际开销

暖检索8查询中位耗时：旧后端2.458秒，ULVN0.721秒，约3.4倍。ULVN单请求验证12图对，旧后端108–378图对；ULVN用CUDA、旧SIFT主要CPU，故这是当前适配器端到端比较，不是等算力单模型比较。

单一已指定图对的暖匹配，旧后端常更快（例如380/65约68毫秒vs503毫秒），不宣称所有操作均提速。进程首次请求为3.411秒vs37.901秒；后者含加载，权重已缓存，不能只报告暖值。

## 4. 据此建议的混合路线（提案，未实施）

**视觉前端负责“与哪些历史视图存在何种强度的可核验对应”；VLM负责“当前看到什么、边界与语义范围是什么”；两者都不单独把模糊证据变成永久身份真值。**

1. 保持原图/事实/Session/事务/独立QA主框架。先使用现有观察ID作为视觉锚点来源，不强迫为本提案新建导航图。
2. ULVN返回精确图对、方向、几何对应与局限。近位置/跨方向的强证据可成为积极身份支持，而非只有一串候选名字；这一支持只限对应观察附近，不覆盖整批。
3. VLM维护区域类别、室内外、门/路沿/楼梯、名称和来源，区分同一具体区域、同一较大范围及相邻/共同可见。物理匹配不能直接完成语义归组。
4. 弱/无匹配不作为不同地点反证。若VLM要确认旧身份，须另有实际交付的独特证据或继续检查；不能仅用彩旗/红砖泛化解释提升为强确认。未匹配也不自动new。
5. 档案无来源或证据冲突时保留未决；不强迫旧ID二选一，不让任意历史图给整个宽ID背书。具体输出/容量与数据集规则须按架构另行设计，未经批准不改。
6. 将来若需位置概率，可独立测试BPL，但必须另核因果历史图、缺口、在线新增节点及视觉节点与语义区域关系；本次没有验证它。

**当前可明确选择：继续保留ULVN作为更强的视觉关联证据模块；不继续纯VLM自由认证，也不直接改成ULVN自动语义分组。** 这是有范围的路线提案，不是混合系统已经通过。若获准实施，下一验证应只检验已知错误能否被正确证据约束且不伤正例，不再做无限提示词搜索。
