# 少量Agent的在线分工与延迟隔离设计

2026-10-31，用户要求按及时性和任务关联度合并职责。本文件是设计，不代表已接入网页或完成全部worker。

## 1. 两个常驻Agent，一个按需交互Agent

### A：即时观察Agent

只做近期原图可见事实、变化线索、已登记关注目标的出现候选。不负责全历史身份确认、路径规划或长期总结。默认最多一次VLM调用/观察片段，输出保持短且结构化。新鲜输入优先；开始时和结果提交时分别检查源时间。迟到结果保留为历史证据，不能当当前事实发布。

### B：经历与记忆Agent

合并相互依赖、非即时的任务：片段解释、空间连续/重访、对象事件、证据核查、摘要和长期索引。按源时间维护局部状态，内部逐任务串行，唯一负责语义记忆提议的提交。长任务分成有截止/预算的步骤，在步骤间接收新任务，不能持锁等待VLM。历史核查引用原版本；迟到提议需检查基础版本，再补写/重算，不能覆盖新状态。

B直接消费持久原始经历及A的可选补充，**不是必须等A返回**。否则A慢了仍会阻塞记忆。A和B不对同一片段重复做相同通用描述；任务记录判断可复用部分和仍缺少部分。

### C：按需交互Agent

只在用户提问/任务控制时启动。基于已提交快照与近期原图回答；语义未完成时可直接查原图，或请求B优先核查。不能等待B清空全部队列。停止/暂停等控制由程序立即执行，不等待任何Agent。要求证据的复杂问题允许说明核查中，不能为了快速返回编造答案。

不是每帧spawn一个Agent，不让Agent相互无限调用；C可使用现有AssistantRuntime/Planner能力契约，但适配尚待实现。当前固定方法2不是这个完整运行链。

## 2. 程序服务，不额外包装成Agent

- 采集/落盘/索引：持续记录，不等待模型。Source时间、接收时间、完成时间分别记录。
- 片段候选/视觉描述子：低成本图像变化和心跳，只生成组织线索，不宣称房间边界。
- 任务表：持久状态pending/running/done/failed、租约、幂等键、输入版本、预算、错误；进程恢复可追踪。
- 提交层：证据引用校验、版本冲突、原子提交、当前/历史状态分离。

## 3. 并发图

```text
三摄 -> 原始经历日志/近期缓冲 -> A即时观察 ----> 有时间范围的观察补充
                    |                         |
                    +----> B经历与记忆 <-------+
                    |          |
                    |        版本化记忆
                    |          |
用户问题 ----------> C交互 <---+（也可直接读取近期或历史原图）
```

## 4. 延迟、积压和资源

- A保留最新普通观察；短暂重要证据有界留存。被替换任务不删除原片。
- B持久保留未完成片段，重复任务合并，后台核查去重；不能把所有任务塞入内存。长期过载依然需要算力/采样策略调整，不能声称任意延迟下即时完整理解。
- VLM初期全局并发上限2作为实验参数；C到来时优先获得下一空闲槽，已经发出的非流式请求可能仍需等返回。给B留最小服务份额，防止饥饿。配额需要实测，非已验证最优值。
- 不把整条2秒输入周期当全部任务共同SLA；采集无模型依赖，当前问题只用新鲜证据，历史关联可迟到。
- 指标分开：采集覆盖、语义完成水位、各任务p50/p95、当前结果年龄、关键事件覆盖、重访结果、待核查数、成本。

用户提到的系统很可能是先前审计的LightMem-Ego，不是EgoLife数据集本身。重新读取本机固定commit `3c023dfec301bb2f9624f82cee76007ac3ac0646`源码副本，未运行第三方服务或新模型调用。

- `online_short_term/frame_stream_event_builder.py:37–45`：帧差驱动事件，默认1–10秒，最多8关键帧。
- 同文件`:73–85`：先写短期事件，再排异步refine任务，未等待VLM描述完成才接收后续帧。
- `online_query/query_engine.py:790–834`：识别长期记忆缺失/部分完成，优先近期本地证据；`837–857`附加原图回退；`860–870`记录provisional/partial完整性。

## 6. 实施顺序

1. 持久经历/任务表与版本化提交，先让两常驻职责可隔离运行。
2. 已有快速更新器接A，B实现核查和空间/事件联合状态；避免A/B重复caption。
3. 将C接回真实AssistantRuntime，明确未完成记忆与原图回退，不以固定方法2冒充完整系统。
4. 注入5/15/60秒延迟及重启，验证采集不停、控制即时、结果不错位、任务可恢复；再评估重访和事件漏检。
