# 交接与维护规则

## 新会话先做什么

1. 读本目录README、00状态、01决定、06待测方案。
2. 读`TODO.md`最顶最新条目，确认用户本次意图。
3. 对要操作的模块核查实际代码和原始report/usage，不只引用摘要。
4. 只读检查Git状态；有其他未提交工作时不清理、不reset、不覆盖。
5. 明确这次是文档、代码、离线测试、下载还是付费推理。文档中的命令不等于执行授权。

## 每次完成工作后怎样同步

- 目标/边界变化：更新01决定，保留被覆盖决定的历史说明。
- 能力/集成变化：更新00状态及02代码地图。
- 新样本/答案/运行：更新03工件及04结果，写路径、输入/答案hash、分母、失败、费用与局限。
- 新待办/问题：同步06与TODO，不把助手建议写成用户已批准。
- 硬件/服务变化：更新05，区分历史验证与当前在线状态。
- 更新日期和证据；不把推测补成事实，不把“候选/结构合法”升级为“确认/语义正确”。
- 可用目录清单工具更新`repository-catalog.json`，但它只同步路径/hash，不替代人工知识更新。

## 原始证据不可变

数据/答案/模型/评分规则变更要另建版本；冻结后不调答案来提高分数。保留失败、unknown、未执行与原始账本，不拼成功前缀。列表价估算不是账单；未知usage需要停，不以重试掩盖。

不能跨实验迁移成绩：337单测通过不是导航准确率；74/74是程序检查；17/24是旧架构；38/42是覆盖不是正确率；脚本gold满分不是模型能力。

## 安全/隐私边界

- 本区不放API值、Authorization、配对密钥、私有固件/备份、完整环境变量或含凭据命令行。
- 不复制`cam/local/`；不要因“同步所有信息”就把秘密公开。
- `research/`保持独立；只引用已知入口，未知结论写未审阅。
- 不改用户运行中的8884服务，不因查状态自动重启硬件或网络。
- 不移动正式tag，不自动推送/发布；不擅自创建并行Agent任务。

## 跨机器/跨人同步

本文件夹是本地交接资料，不会自动上传。共享前先检查敏感路径及数据许可。另一台机器可能没有`datasets/`、`run/`、`.venv/`或私有硬件文件；必须另行提供允许共享的工件并验证hash，不能说仅复制Markdown就能复现。

索引仅收集`src/`、`scripts/`、`tests/`、`docs/`、`cam/docs/`及少量根配置文本，不收集run/data内容、node_modules、Git对象、密钥或独立research树。文件名/哈希本身仍需按团队共享政策处理。
