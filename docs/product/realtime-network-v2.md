# 网络独立相机与持续交互

## 日常使用

电脑运行 `npm.cmd run realtime`，打开 <http://127.0.0.1:8884/realtime.html>。

- 页面自动接收网络相机画面，不调用模型，不打开COM3。
- 点击“启动交互”后，方法2单视图空间记忆Agent持续处理最新新鲜帧。没有60张或180秒限制。
- 输入问题并点击“发送问题”，才调用独立只读问题Agent。
- “暂停交互”暂停空间建模及新问题调用，不停预览；正在进行的调用仍会完成并记账。
- 相机需要供电并连接BUPT-portal；电脑必须能通过局域网访问它。“收到信号”指HTTP网络可达，不是任意无线电信号。页面断流保留最后画面但明确标为历史，不冒充当前。

模型保留每小时估算上限：空间USD0.50，问题USD0.25，未知调用占额；暂停／启动不重置额度。空间达到上限后等下一个从接收服务启动起算的小时窗口。服务重启会新建会话及预算，不是跨重启全局限额。空间协议异常会暂停建模并显示错误，可点击暂停／启动重试；不暗中修改语义冲突。

## 一次性配置与凭据边界

新固件目标 `camera-network`，`cam/pair_network_camera.py`负责一次性USB配置。随机配对密钥及校园凭据存入设备Preferences NVS，电脑密钥保存于忽略的`cam/local/network-camera.json`。用户已分别明确同意密钥持久化及校园凭据持久化。账号密码不进入源码、构建固件镜像或日志。**NVS未启用Flash加密，有物理读取风险**；禁止将配置后整片Flash备份作为公开附件。

最初试过仅在电脑保存校园凭据、网络临时发送，但校园认证前HTTP不可达，无法完成启动闭环；该方案未采用。现在设备启动时从NVS读取校园凭据，仅向原有allowlist门户认证；每10分钟检查一次、已在线不提交密码，失败不会紧密循环撞账号。

设备支持固定本地配置地址、mDNS和UDP发现重试；校园网若限制广播/mDNS或设备IP变化导致发现失败，仍需重新更新本地地址，不能声称所有网络都可无条件发现。配对密钥和图像仍使用HTTP，不是加密连接。

## 传输与存档

`network_stream.py`不访问串口、不读校园密码；逐响应Content-Length、SHA256、JPEG尺寸校验，保存错误原始字节及白名单元数据。损坏帧不写有效收据，接收器退避后重新连接。设备序号跳跃／重启／失败后恢复产生gapBefore，空间拓扑插入未知访问，不复制旧图补齐。主机有效序号独立递增，原设备序号另存。

之前持久连接使用`response.read(300001)`，可能等待超过当前正文长度的内容；新接收器严格读Content-Length并逐块保存，不能据此断言旧截断只有这一个原因。固件使用逐请求关闭连接与分块发送，最长发送20秒；超龄帧不用于当前空间输入。

原JPEG、像素等价PNG、SQLite、调用usage和问题都按接收会话保留。持续运行会增长磁盘占用，尚无自动保留策略；不会静默删除原图。内存中原图索引／问答快照也会随时间增长，尚未长期压力验收或实现跨服务重启恢复UI。

## 验证结果与限制

- 完整312项TS测试、Python断流恢复测试通过。Python模拟首响应截断→重连恢复→设备换boot，验证失败原始字节、完整原图和gap均保留。
- Chromium实际页面测试v1为测试等待实现错误、v2暴露JPEG已归档但PNG未就绪时的提问竞争；两次失败报告保留，不覆盖。修复为提问采用当时最新已就绪原图，不取未来帧。
- `run/hardware/network-realtime-ui-v3/report.json`通过：预览1→4张且空间调用数不变；点击启动、提交历史问题、得到带原图引用回答；暂停后预览继续。桌面1280宽和移动390宽截图保留，零页面脚本错误、无横向溢出。
- 重启测试在会话`70ef89b3-3371-4bae-a3e5-419399e88cbb`观察到两个不同设备boot ID，重启后自动恢复；无需重发密钥和校园凭据。测试用USB仅触发reset，之后端口关闭。**尚未由助手物理拔线切换电源；独立电源现场验证需用户完成。**
- 实拍为近处包装盒等，空间多为unknown。问答回答成功不等于空间识别精度验收，不强造地点。仍非避障、安全通行系统。
