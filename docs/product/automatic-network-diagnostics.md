# 自动诊断回传（开发调试）

原缺口：RAM日志仅提供拉取接口，无自动回传；重启后旧boot日志丢失，因此上次录像缺口无法完整追溯。

当前补齐：
- 摄像头正常上传成功后每30秒POST最近128条RAM日志；有上传失败时，首次恢复图像上传成功即尝试回传。每次仍是完整有界快照，存在重复，分析需按bootId及事件uptime/sequence去重。
- 电脑8885接收鉴权JSON，只允许诊断字段，限64KB／128事件；写入本接收会话`capture/network-diagnostics.jsonl`，含主机接收时间与设备boot/uptime。此为非图像调试元数据，默认预览也保存，不保存预览原图。
- 接收图像异常始终追加`capture/network-errors.jsonl`，含请求开始、失败时间、bootId、sequence、错误类型和已收字节；只有开启记录时才额外保留失败图像正文。
- 实时服务autoReceive模式监听后立即启动接收器，不再等网页首次轮询才接图，减少调试期间服务重启的无监听空窗。不是系统级进程守护。

固件已编译烧写Hash校验；Python回归覆盖预览时诊断保存且没有JPEG文件，既有记录／鉴权测试通过；TS构建及6项实时测试通过。

限制：仍然不能在网络完全不可达时回传；无连接持续超过环形容量可能覆盖旧事件，恢复前断电会丢失。JSON上传附加无线负载及最多短时阻塞，不宣称不影响帧率；目前日志无限追加，长期运行需另做轮转。当前不写板端Flash以免隐式持久化与磨损。没有开启图像离线补传，没有调整漫游。下一次在同位置开启记录复测，故障后保持供电、恢复网络；先从自动归档按boot/sequence匹配，再决定受控漫游或无线覆盖调整。
