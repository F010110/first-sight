# 面向视障辅助的长期记忆：产品与数据构建方案

日期：2026-10-27。状态：设计草案，未采集新数据，未开展视障用户研究，不代表已达到真实辅助使用标准。

补充设计与来源核查见`research/reports/ego4d-vcn-spamem-evonav-assistive-data-design.md`：以Ego4D最后所见证据定位、VCN历史空间上下文、SpaMEM分层诊断、EvoNav视野外局部变化为参考。主数据采用需求来源＋自然多日经历＋独立受控挑战三层；Tartan/仿真只作工程辅助。重点新增非视觉可用地标、用户已有策略、无答案自然请求、实际检查负担；不将通用第一人称或机器人轨迹冒称视障生活数据。

## 1. 目标改为用户生活，而非benchmark任务

我们的产品是一个能记住用户过往所见、在需要时提供帮助的视觉记忆助手。主要问题是：

- “最后一次看见我的钥匙在哪里？”
- “那个屋子怎么走来着？”
- “我以前来过这里吗？上次从哪里进去的？”
- “不是那个杯子，是我平时用的那个。”
- “我记得昨天放在这里，现在还在吗？”

物品记忆和地点/路径记忆都属于主线；不为了避免物体级重建而排除物品查找，也不因为需要记物品就默认建设精密3D对象地图。

**产品目标：保存有来源、可更新、能承认遗漏的长期生活记忆。不是完成预定义机器人操作链，不要求替用户移动或抓取。**

既有benchmark用于参考构建方法、做独立辅助测试，不决定我们的功能范围。不再以“必须跑完某benchmark”作为产品完成条件；旧实验保留，不改名、不删失败、不挪作产品成绩。

## 2. 两类核心记忆，共享证据层

|能力|需要记住|对用户的输出|不能承诺|
|---|---|---|---|
|物品最后所见|实例候选、外观、所见时间、承载位置、地点、原图、遮挡/采集空缺|“最后一次拍到是在今天上午，玄关柜面的托盘里；之后没有拍到它的去向。”|“它现在肯定在那里”|
|屋内路径回忆|当前地点候选、历史访问顺序、实际走过的连接、门/转角/地标、朝向及证据质量|“上次是从大厅经过餐桌旁的门进入的。现在朝向还不确定，请先确认门的位置。”|“现在一定畅通/安全，可以直接走”|

底层保留观察原件；上层组织物品出现事件、地点、到访、历史路径、用户命名和可修订关联。用户说“我把钥匙移到抽屉了”是用户陈述，应单独标来源，不伪装成系统看见。

“最后一次看见”默认指**本系统最后记录到**，不是用户一生中最后一次看见，也不是物品最后实际位置。多个相似实例无法确认时先澄清。

## 3. 数据单元：一个用户在一个环境中的多次生活经历

不把独立QA对作为最底层数据。基本单元为：

```text
匿名用户/参与者 + 环境
  ├─ session A：自然活动与经过路线
  ├─ session B：再次使用，同一地点/物品可能发生变化
  ├─ session C：较晚重访、不同光照或部分采集缺失
  └─ query events：在明确时刻发出的请求、澄清、纠正和停止
```

先做受控住宅式空间的小规模产品验证；再考虑参与者真实生活环境。不得默认已有校园片段能代表室内多日生活，也不假定新场景资产或同步IMU已就绪。

### 3.1 采集原则

1. 先记录完整经历，再设计其中可回答的查询；不只拍即将被问到的物品。
2. 活动有自然目的，例如回家、整理桌面、取物、去另一个房间；不要求处处为题目服务。
3. 既保留真实经过，也安排少量可控变化以查错；自然活动和脚本挑战分别标记。
4. 跨session保持记忆，不每个问题都清空；另外保留冷启动/记忆关闭对照。
5. 问题出现前不知道具体未来问题；不得提前按问题筛图或写摘要。
6. 缺拍、设备摘下、镜头遮挡、黑暗、网络中断都记录，不能把时间轴拼接成连续生活。
7. 真实时间与仿真/加速时间区分。几个切片人为标成“几天”不能证明跨日长期记忆。

### 3.2 RGB与IMU

- RGB是当前可用输入起点；IMU接入另设里程碑，不等输入未就绪就延期全部产品验证。
- 新采集若支持IMU，保存原始采样、时钟域、单位、设备/相机外参、标定与gap；不只保存“左转了”等事件标签。
- 暂无同步IMU的素材明确标RGB-only，不能用动作标签/GTpose补造成原始测量。
- 真实传感器轨与仿真一致轨分开；仿真主要验证接线、覆盖边界和故障，不代替真实用户使用证据。
- 路线相对朝向必须区分相机、设备和身体朝向，尤其手持镜头转动不等于用户身体转身。

## 4. 如何参考四个benchmark，而不被其任务绑架

|参考来源|借鉴构建方法|产品化改动|不沿用|
|---|---|---|---|
|FindingDory|先积累历史，后提出依赖历史的目标；变化前后状态、时间与顺序可核验|自然生活中记录最后所见、重访和路径；目标可为物品也可为地点|不以目标帧选择成功代替指路正确；不人为要求所有请求都是物体导航|
|3DMem-Bench论文|跨房间、多段经历、空间关系与布局问题；自动检查＋人工审核|围绕用户常用地点和路径组织长时经历；不限定dense 3D表示|官方核心发布未确认，只参考论文设计，不把示例视频当可用数据集|
|EMem-Bench|变化记忆、旧状态失效、失败反馈和用户纠正；线索到请求之间有其他活动|记录物品移动、地点别名修改、走错后纠正；保持来源和时间|不以抓取/开抽屉等机器人操作作为本产品必需能力；不使用房间跳转构造惯性路线|
|LMEE-Bench|探索过程中持续积累记忆，后续检索、问答与目标有联系|实际经过的路线与场景成为可问的生活记忆，不要求问所有物品属性|不固定为一组导航目标后只问这些目标，也不以QA分数代替语言路线质量|

这些是设计借鉴，不代表我们已复现或取得数据使用许可。具体来源见`research/reports/benchmark-fit-for-language-route-memory.md`。

## 5. 小规模数据构建步骤

### A：形成产品故事，先与用户需求对齐

先选两个垂直能力：最后所见查找、熟悉空间的路线回忆。每个故事包含：真实困难、历史经历、发问时刻、允许澄清、预期帮助、失败出口。

邀请视障用户及相关定向行走/无障碍专业人员参与需求和话术评审；不能用开发者闭眼体验或健视者蒙眼测试替代。首次技术验证可由知情健视测试者完成，但不得称为视障用户验证。

### B：采集一个环境的多session经历

先验证一个环境、少量经同意的参与者/采集者，不预设大规模人数。覆盖正常使用、稍晚重访、物品移动、停拍恢复。session数量、间隔、总时长根据素材可用性和资源冻结，不把未经确认的数量写成已采集。

### C：独立建立证据记录

由授权标注者记录可观察事实和独立布置日志，而非让待测VLM生成唯一真值。保存：

- 物品可见区间与可区分实例、所处表面/容器、地点、证据帧；
- 状态变化前后证据、移动是否真正被摄像头记录；
- 走过的连接、方向、可见地标、停留/折返、路径空缺；
- 当前问题时的可见范围、可回答性与必要澄清；
- 支持答案的一个或多个证据集合，以及不应说出的无依据断言。

真值应区分两层：**世界实际发生了什么**与**系统截至当时有机会知道什么**。例如钥匙在停拍时被移走，评分不能要求系统知道去向；正确回答应是“最后记录在桌上，之后无法确认”。

### D：构造查询，不只保留正例

在独立查看经历后构造请求，并保留参与者自然发问/改口；人工请求和自然请求分列。回答标准在跑系统前冻结。相关时间区间和答案只给评分侧，不给调度器泄漏未来信息。

需要包含：

|情况|验证问题|
|---|---|
|确实看见过|能否找到正确的最后所见事件|
|多次移动且被拍到|能否使用最新证据，而非第一次或最显眼一次|
|移走过程没拍到|能否保留最后所见，同时明确现在未知|
|相似物品/用户别名|能否区分实例或主动澄清|
|只看见地点没走过|能否拒绝编造连接路径|
|路线反向/当前朝向改变|能否重新解释方向，不机械复述上次左右|
|同一路线有多个合法走法|能否给出任一可验证路线，而非逐字匹配|
|物品/地点从未出现|能否明确没有记录|
|几天后再次使用/重启|能否恢复记忆并保留时间信息|
|用户纠正或删除|能否修订/清除相应记忆并影响后续检索|

### E：先工程回放，再谨慎开展真实交互

1. 离线因果回放：检验数据、记忆、引用和输出，处理流程失败。
2. 交互原型：支持自然语言澄清、打断、取消；文字回放只算工程验证。
3. 具备可访问输入输出、明确同意与安全安排后，再开展受监督的目标用户可用性研究。

现有产品以文字输出为主，不能仅因模型回答正确就宣称视障可用。语音/读屏、焦点顺序、暂停和隐私控制的具体方案需用户评审并另行验收；不在此文档中声称已实现。

## 6. 数据与评分分离

建议新数据布局（尚未创建/采集）：

```text
private-data/assistive-memory/<collection-id>/
  consent-and-access/       # 独立访问控制，不发送给模型
  source/<session-id>/      # 原始图像/音视频/IMU及hash，不覆盖
  runtime/                 # 允许发送给系统的观测和当下用户请求
  annotations/             # 可见性、变化、路线、可回答性；评测侧
  splits/                  # 开发与测试划分、素材版本
  runs/<run-id>/           # 模型输出、记忆版本、引用、usage、失败
```

实际保存路径应使用受控、默认忽略的私有数据目录；该名字仅为结构建议，不表示新目录已纳入`.gitignore`。不能提交住址、照片、人声、设备标识或同意书。

长时用户内记忆允许在同一测试环境中读取早先session，这是产品必需上下文，不是数据泄漏；但不能用测试答案调prompt/阈值。开发与测试按用户/环境划分，避免相邻帧随机拆分造成泄漏。数据不足时明确只是开发演示，不宣称泛化。

## 7. 衡量“有没有帮上忙”，不造一个总分

### 7.1 最后所见

- 正确事件/实例/位置召回；最新记录选择正确率；
- 时间表达与来源正确性；混淆历史和当前的错误率；
- 无记录/歧义时的澄清与拒答；
- 检索证据覆盖、响应耗时、用户检查负担。

“最后所见”正确但用户仍找不到，记为记忆正确/帮助未完成，不能强行算任务成功；用户自己找到也不自动归功于系统。

### 7.2 屋内路线

- 起点/朝向判断、目标地点理解、连接路径有效性；
- 每步地标/方向有无证据，无依据步骤率；
- 缺视野/路径时是否请求观察，是否遗漏已知不确定性；
- 用户是否能理解下一步、追问次数、纠错/取消是否及时；
- 在受监督条件下的实际帮助结果，单列环境和辅助人员介入。

不得将图上的历史连接当作当前通行许可。LLM裁判用于辅助语义评价，事实、证据和路径由独立标注核验；保留人工抽审与分歧，不只按回答流畅程度评分。

### 7.3 真正的长期性

同时报告实际经历跨度、session数、记忆量、查询距证据时间、跨session恢复、变化后的旧记忆误用和删除效果。不能用视频帧数多、上下文长或程序重启一次就代称长期生活使用。

## 8. 安全、隐私与产品边界

- 当前定位和语言路线仅作记忆辅助，不能替代白杖、导盲犬或定向行走技能；不承诺实时避障、过街或楼梯安全。
- 走动中的长篇解释可能增加认知负担；默认简短分步、可暂停/追问，具体方式由用户反馈验证。
- 不暗中安排视障参与者寻找被危险放置的物品或独自行走未知路线；任何真实行走试验须有合适的监督/停止机制。
- 居家录制可能包含旁人、地址、药物、财务及私密空间：先取得适当同意，限制采集区、保留期限和访问权限；参与者可暂停、撤回并删除。
- 记录云端处理的数据范围；敏感画面不自动上传，密钥不写数据包。删除需覆盖原件/索引/派生记忆/缓存，备份的处置规则须预先说明。
- 是否需要伦理审查及当地合规流程，应在招募/采集前核实，不以“项目不是科研”为由豁免。

## 9. 与现有项目的衔接

- `vlm-imu-spatial-memory-closed-loop.md`继续提供工程模块顺序，最终仍为自然语言路线，不接控制器；物品最后所见作为同一证据层上的平行产品能力。
- 复用已有“历史不等于当前”“观察与问答分离”“用户停止/取消立即生效”的约束，参考`campus-assistant-interaction-v1.md`，但校园故事不能替代本方案真实室内素材。
- 先验证RGB记忆、物品事件与地点/路径检索；并行设计IMU输入契约。没有IMU的结果明确标注，不伪造运动证据。
- 公开benchmark的辅助成绩独立报告，不作为真实用户可用率。

## 10. 下一步

1. 冻结两个产品故事模板：最后所见查找、熟悉空间路线回忆，先做需求评审。
2. 清点可合法使用的已有多session室内素材和同步IMU；不足则写明待采集，不立即大规模下载或招募。
3. 写一页采集/同意/隐私清单与最小标注schema，先审核一条经历能否支持可验证回答。
4. 建立运行输入与真值分离的因果回放，先检验正确取证、过期声明与澄清。
5. 经用户确认采集范围与预算后再实施；本次仅保存设计，不开始采集、付费调用、训练或真实用户试验。
