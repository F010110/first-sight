# RAM网络日志与弱信号处理

固件128条环形RAM事件，满后覆盖最旧条目，不写Flash，不含图像、账号、密码、密钥。上传事件含设备uptime、序号、整次取图及上传耗时、HTTP返回码（负数为HTTPClient错误）、采样RSSI/channel/BSSID；Wi-Fi关联、获取IP、断开及SDK断开reason也记录。不同kind的code含义不同，不可将Wi-Fi reason当HTTP码。无线事件异步写入，短锁保护环形缓冲，HTTP格式化在锁外。RSSI在记录时采样，不代表整个发送过程。无frame或begin失败时当前返回-1，不能仅凭-1区分摄像头和TCP错误。

鉴权GET `/v1/network-log`，返回bootId、当前uptime、累计total和最近events；不清空。`cam/read_network_log.py --host 当前摄像头IPv4`将快照保存到`run/network-diagnostics/`。上传阻塞时HTTP查询可能要等本次超时；无网络时无法取回，恢复联网后先读取再断电。约2秒一条时仅保留几分钟，不能等很久。boot变化后不能拼接为同一时钟，uint32 uptime约49.7天回绕。日志不是永久追溯系统，也不会恢复上次21:32:59的旧错误。

已编译、烧写并校验应用Hash；真实鉴权读取7条（associated、got-ip、5次upload=200），无鉴权返回401。UDP发现本次超时，使用本地配置host读取成功。快照`run/network-diagnostics/1792763228028346100.json`。未改漫游、发射功率、防火墙或模型开关；未做强制断连／环形溢出的实机验收。

## 已知方案及当前缺口

1. **射频与覆盖优先**：人体遮挡、板天线贴金属、线材／供电噪声均可影响2.4GHz；先对照板朝向、远离身体和金属、稳定供电。外置天线只能在板子射频连接和天线型号确认后用，不能随意加；提高发射功率不能修复AP下行和真实盲区，当前未改功率。
2. **受控客户端漫游**：当前autoReconnect已开、Wi-Fi省电已关，但不等于主动挑选更强AP。可在持续弱RSSI或连续上传失败后异步扫描同SSID，只有候选明显更好才切换BSSID，并设置滞回和冷却，避免乒乓。例：持续低于-75dBm、候选强8–12dB、冷却30–60秒仅为待实测起点，不是通用参数。扫描占用无线时间；先确认确有更好AP，不能每张图全信道扫描或见-80就断开。需重验证Portal认证、IP变化及TCP恢复。本轮未启用。
3. **连接选优**：SDK all-channel scan、RSSI sort／threshold可改进连接时选AP，但不是持续漫游，也不应因阈值拒绝唯一可用弱AP。Arduino包装层与当前编译SDK需核实后再修改。
4. **802.11k/v/r**：邻居报告、BSS切换建议、快速认证可降低发现／切换开销，但依赖终端SDK构建选项、AP／控制器及认证方案，不可把新SDK示例直接当当前Arduino2.0.17/IDF4.4系已启用能力。需要询问北邮网管该SSID是否支持、终端是否启用隔离或跨AP策略；不能承诺全校无缝漫游。升级框架须单独回归相机和Portal。
5. **传输退化**：弱链路自动降低JPEG大小／帧率，按失败类型调整超时与退避，减少每帧新建TCP成本（当前接收端HTTP/1.0、每帧独立连接，持久连接需两端改造和故障恢复）。这些可减负，不能补覆盖；长期卡住不能靠无限重试旧图解决。
6. **架构替代**：随身热点／路由器让摄像头保持单一近距离AP，由网关负责校园／蜂窝回传；可能需额外设备、供电和费用。无覆盖仍要依赖录制开启时的离线缓存补传；当前未实现。默认预览禁止偷偷持久缓存图像，历史补传不得冒充当前状态。

推荐顺序：先带本日志复测指定位置，恢复后立即取快照；看失败码、BSSID是否变化及disconnect reason，再单独A/B受控漫游或JPEG减负。若无更好AP，优先射频／覆盖或随身网关，不用强制切AP掩盖问题。

参考：Espressif ESP32-S3 IDF4.4.7 Wi-Fi Driver（扫描、连接配置及reason说明）：https://docs.espressif.com/projects/esp-idf/en/v4.4.7/esp32s3/api-guides/wifi.html 。校园AP支持状况尚无独立验证。
