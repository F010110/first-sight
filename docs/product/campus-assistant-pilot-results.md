## 最新试跑记录了什么

1. 用户提出“接下来看到植物提醒一次”，系统创建两分钟关注状态。
2. 第一个实际校园三视图进入，VLM判断命中，引用该观察并交付一次提醒，关注完成。
3. 当前环境问题及左右侧追问都通过当前视觉能力形成答案；回答正确性尚无独立语义审核。
4. 创建寻找任务；第二次观察出现候选并提示，但没有自动将候选记作用户确认找到。
5. 用户取消，寻找状态保持cancelled。
6. 暂停观察后询问“现在周围怎样”，任务记录failed并交付无法确认当前画面的说明。脚本完成不等于五个任务全部成功；此失败是覆盖范围控制的预期用例。

只有植物这种简单可见目标；不能据此推广到找钥匙、读标牌、变化通知、未知物体或复杂指代。未验证丢图／真实网络故障、完整长期记忆、多目标成本、实际实时延迟与真实用户行为。

试跑使用加速因果阻塞时钟：用户脚本按序等模型完成，虚拟观察时间只推进2秒，实际模型调用经历更多墙钟时间。事件日志保留实际写入时刻；不能用消息虚拟时间声称零延迟。网页可按事件墙钟间隔播放或手动逐事件。

## 网页查看

启动`npm.cmd run assistant:web`，在“观看校园助手试跑”刷新列表、选择运行、载入。可拖动事件位置或逐事件查看三图、问题、原始VLM语言及实际交付。回放不调用模型；图片按原hash检查。失败运行与修复后运行分别列出，不合成单个“成功演示”。

目前回放以同一进程的文件写入顺序为准，不提供真实用户ASR／TTS仿真，不是连续可操控的校园3D世界。现有原始校园PNG保持原画幅，不冒充160°广角重渲染。
