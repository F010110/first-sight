# 新90题失败与v1.2.0基线对照

## 结论

新运行`2026-10-21T01-33-43-330Z-questions-80e4c0cd`的4个执行失败，全部是历史取证链失败：每题7次search均无命中，0次inspect，第8次给出无取证支撑的肯定回答，被证据门禁拒收。不是HTTP失败、预算金额耗尽，也没有证据表明是空间库丢失。只读SQL确认4个目标观察均存在、pending=0且早于问题时刻。

这是新问答适配层没有完整继承v1.2.0已验证机制的回退，不能解释成空间／问答分离本身不成立。本次仅诊断，不修改算法、不重跑付费模型、不替换原始答案。

## 基线差异

核对了`git show v1.2.0:src/agent/spatial-context-vlm.ts`、`spatial-context-memory.ts`，以及冻结`run/inspect-repair-full90-v1/full/results.jsonl`与原成绩文档。

| 机制 | v1.2.0基线 | 新独立QuestionAgent |
|---|---|---|
| 时间表达 | 完整ISO时间，保留毫秒，工具用确定性calendarFilters转换 | 题集生成把毫秒截成HH:MM:SS；让模型心算afterMs／beforeMs，没有标准化秒范围 |
| 指定历史来源 | 从公开题目引用与公开观察记录解析requiredEvidenceIds；非私有答案 | 只检查引用过某张历史图，未绑定用户指定的具体时间记录 |
| search→inspect | 根据必需来源、未查看候选、已打开来源进行阶段推进 | 有通用阶段提示，但无命中时没有时间范围纠偏／重复查询阻断 |
| 错误恢复 | 部分协议／来源错误反馈进有界循环，允许纠正；非所有错误均可恢复 | 新Agent这些答案校验直接throw，本题结束 |
| 每题控制轮次 | 正式运行16轮 | 8轮；4例均7次无效搜索后第8次错误回答 |

减少轮数只是差异，不能断言加轮次能修复：重复同一错误时间范围仍不会取到图。真正缺失的是时间标准化、目标来源约束和有效的阶段反馈。

## 分数不能直接相减

- v1.2.0：90个最终答案，0执行error、0协议拒收；原模型评分87题满分／3题零分，当前／短时／长时100／93.33／96.67。已知语义错误包括正确图仍视觉误认、无依据断定同楼层、无记录期间仍在同建筑；另有附带细节幻觉。不是独立人工验证。
- 新90题：86执行完成／4拒收；题目、记忆生产条件、轮次和评分口径均不同，没有可与旧分数直接比较的语义正确率。
- 新历史60题中，短时28交付含1拒答，长时28交付含4拒答。恰好引用题集源绑定观察的数量为短时20、长时13。其余不能一律判错（可能拒答或引用相邻帧），但“已看过任意历史图”不能证明回答了指定时间问题。

## 后续修复顺序（尚未实施）

1. 恢复基线的公开时间解析与来源绑定，不把私有证据表注入Agent。对秒级用户时间定义明确秒范围；保留缺口与多候选歧义，不静默代换成其他时刻。
2. 恢复基线取证状态机：正确候选出现后inspect，无命中重复范围应明确纠偏；缺少指定历史图时拒答，不能拿当前图代替。
3. 对这4例做不调用模型的时间／来源回归测试，再做小规模独立诊断；若后续授权付费重跑，保存全新运行，不改这次失败。
4. 用原冻结90题复测新的只读问答链，并按原评分口径单独评分，才可判断相对v1.2.0的语义回归；新90题另行评审。
