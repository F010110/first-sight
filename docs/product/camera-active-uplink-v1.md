# 摄像头主动上传到现有电脑：开发试验

## 当前结果

开发板已配置主动上传，接收端为当前校园IP `10.122.241.38:8885/v1/upload`。第一次探针没有获得设备返回码，补充明确复位后电脑收到GET且开发板返回HTTP200；不能将第一次失败直接定因防火墙。本次未修改防火墙规则。

固件已编译烧写校验；一次USB配置将上传地址写NVS，正常运行不需要USB。保留校园凭据、方向校正及低光设置。每帧独立JPEG POST，bearer密钥、长度、SHA256、尺寸、boot及序号验证；发送失败丢弃该旧帧，约3秒后尝试新图，不积压或补传旧图。

真实静态试验：默认预览4帧时记录数0，开启手动记录后完整保存5张，随后关闭记录恢复内存预览；没有VLM调用。5张接收起始间隔为2662／2743／2215／2331ms，RSSI约-54至-52dBm；不能声称满足稳定2秒或已经优于拉取。原始试验目录`run/realtime-system/3cecf1d5-2ecb-4a8e-8bf4-906ae2dd4ba1`，这些测试记录保留，不当作用户实走数据。

## 运行

```powershell
$env:CAMERA_TRANSPORT='push'
$env:CAMERA_RECEIVER_HOST='10.122.241.38'
node dist/current/desktop/realtime-server.js --allow-paid
```

打开8884实时页会启动独立Python接收器8885。8884控制页面仍仅监听loopback；8885只支持鉴权JPEG上传，不提供系统启动、问答等控制接口。默认预览只在内存保留最新图；记录才保存，系统启动包含记录，原有回放自动读取记录。

`CAMERA_TRANSPORT`不设置时仍为旧pull路径，不能直接用旧命令重启后误以为主动接收还在。避免两个接收器并发。电脑地址变化需更新host并重新通过`cam/host/configure_uplink.py --host 新地址`配置设备；当前不是固定域名或全校自动发现方案。设备回退可USB发送`UPLINK_OFF`，再切回pull。

## 时间和局限

上传观察标为`host-receive-start`：主机收到请求头后的时间，不是精确曝光时间，也不是旧的host-request时刻。adapter仅复用校验逻辑，不修改原始收据。设备原始capture时间仍保存、未对齐到主机。新鲜度包含正文接收／模型准备，但无法精确计入曝光到请求头之前的延迟，不能据此提供安全实时性保证。设备新拍即传且无历史重试，仍需后续时钟／延迟测量。

HTTP明文局域网实验，密钥不是加密，长期部署需TLS。无板载离线缓存，盲区仍丢图；主动上传只能减少摄像头地址发现／入站可达性依赖，不能解决无线无覆盖和漫游认证。单线程接收器限时／限体积，适用当前单摄，不是多设备并发生产服务。
