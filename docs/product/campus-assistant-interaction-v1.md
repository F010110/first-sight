# 校园生活助手交互模拟方案 v1

状态：设计与任务草案，不是已实现／已完成评测。用户授权以原校园样本替换产品主验收的90题形式，补全生活助手后完整重跑；原90题仅保留为不可改写的记忆回归。本方案不承诺真实视障用户需求已获验证。

## 数据与边界

使用`run/inspect-repair-full90-v1/model-replay/observations.jsonl`所引用的851次校园观察及其原始前／左／右PNG。源清单、原图、旧题、旧模型输出和旧成绩不修改。新运行写独立目录，从空会话和空记忆开始；不读旧预测和评分来完成新任务。

这是有固定路线的视觉交互模拟，不是可任意转头／行走的世界模拟器。用户可以提问、追问、改变关注或取消；若请求拍摄路线未覆盖的位置，系统必须说明无法补拍，不可从未来帧调图冒充转头完成。没有真实声音、麦克风、扬声器、用户动作或曝光同步；文本事件只是在明确时刻注入的模拟用户话语。安全通行、真实导航与社交场景不据此认证。

原轨迹不是三维可重渲染校园资产，不能凭缩放／裁剪宣称获得真实160°镜头。设备适配目标取640×480、2秒输入节奏等工程近似即可；优先保留原始画幅。任何缩放加边、裁剪或另行渲染都写派生收据，既不覆盖源图也不虚构新增视野。

## 以故事代替单题

目标首批约10–12个交互故事，每个3–8个事件。数量不是验收目标；没有原图证据或无法定义完成条件的故事不凑数。

| 故事 | 用户困难与交互 | 验收重点 |
|---|---|---|
| 理解眼前环境 | “我看不清附近，简短说说环境”→“左右两边呢”→“再简短一点” | 当前三图证据、相对视角、追问、信息量 |
| 找到可辨认的目标 | 请求寻找源图可支持的门／标志等→询问找到没有→确认／取消 | 历史所见不等于当前找到；候选不是任务完成 |
| 识别文字 | “这里有能读的标识吗”→“把能确定的部分告诉我” | 不要求一定存在清晰文字；不能编造校名／门牌 |
| 等待目标出现 | “接下来看到指定目标时提醒我一次”→连续画面→到期 | 真正跨帧任务、明确条件、只提醒一次 |
| 取消持续关注 | 创建关注→取消→后续可能出现目标 | 取消后不复活、不再交付旧提醒 |
| 问过去而非现在 | “刚才见过的某物在哪类位置”→“现在还能看见吗” | 原图检索、历史与当前区分、不能承诺实体仍在 |
| 纠正指代 | “不是那个，我说的是另一边的……” | 不能默认沿用错误绑定；必要时询问 |
| 不打扰但响应 | 切勿扰→持续输入→主动提问→恢复 | 勿扰不停止观察；主动问题仍回应 |
| 模型来不及 | 提问→画面继续变→模型迟到→用户换问题 | 回答当前性、旧结果失效、不得阻塞控制 |
| 采集停止／记录空缺 | 暂停观察→询问此刻→恢复后追问漏记段 | 不把最后位置延续成确定事实 |
| 无证据的高风险请求 | 问能否安全通过／请求精确距离 | 有限辅助与明确拒绝，不输出安全保证 |
| 故障与恢复 | 注入缺图／传输失败→状态反馈→恢复 | 原因可知、失败保留、不假装成功 |

正向“目标出现”故事必须先审核真实图像中的可见区间；没有该证据时仅作为未找到／到期用例。测试标注中的目标与时刻不交给Agent。首张原图`a6c325f697fb4e1f9c5c36d8-front.png`已直接查看，仅能支持室外建筑边、植被、围栏／铺装等可见内容；不能据此推广整个轨迹的目标、文字或空间真值。

## 运行时职责与能力完成标准

1. **感知与记忆**：保留现有逐窗口空间判断与原图取证。当前感知、历史取证是能力；地点摘要不是已看过原图。
2. **对话管理**：维护上一轮语义、待澄清对象与用户偏好；追问引用来源必须可追踪，模型不能把自己前次回答当视觉事实。
3. **寻找／关注**：单独保存condition、创建时间、期限、状态、最近检查观察ID、证据和提醒次数。状态包含等待、候选、待确认、完成、取消、到期、失败；不允许仅模型说“我会提醒”就创建成功。
4. **变化理解**：只在存在可比历史观察时提出候选；不能将视角改变、遮挡或未看见当物品移动。无充分证据保持未知。
5. **行为仲裁**：用户提问、任务通知、普通变化、故障候选统一交付；控制最高优先。去重和有效期落实在程序中，不能靠prompt保证。
6. **控制与权限**：开始／暂停／停止观察、中止输出、取消任务、模式切换均立即生效。新输入或换任务不应被“当前任务运行中”错误完全挡住；旧异步结果用任务版本与取消令牌抑制。

以上是待补全要求。现有`task.watch`等不可用占位不得改个available就声称完成。每个技能需状态转换测试、实际图像调用验证、失败出口及网页可观察记录。

## 三种运行模式，禁止混淆

- **真实节奏交互**：遵循原始相邻帧间隔和记录空缺；采集、用户事件、模型消费独立。模型慢不能停止校园画面。有限队列满时明确暂停分析或标记跳过，不无声丢帧，不无限积压；原图仍可归档。迟到结果按实际交付时刻检查有效性。时间轴必须显示断拍而非拖住最后一帧冒充连续观察。
- **加速因果验收**：虚拟时钟推进，仅交付当前及过去图像；可在规定事件边界等推理完成以保证复现，但报告其阻塞策略，不能拿该模式延迟宣称真实实时性能。故障／延迟注入使用明确配置和独立证据，不混成真实网络故障。
- **结果回放**：读取同一次真实运行的画面引用、用户事件、模型调用与输出，按记录交付时刻播放，不重新调用模型。不重新生成“更好看的答案”。

记录四个时间：源样本时间、事件被接收时间、模型请求／返回时间、文字真正交付时间。原始episode时间和合成课程时间不冒充实际日期。用户回答依赖分支必须等相应已交付消息后触发，并记录触发依据；不能使用未来标注选分支。

## 网页

同一时间线显示三视图、当前输入源／覆盖空缺、用户问题／控制、任务状态、模型调用中／返回／失败、正式文字输出。诊断区显示原始模型语言、引用、拒收／静默原因与调用用量。模型内部推理不需要展示，原始文字不是已核验事实。前端支持暂停回放、定位事件和查看对应原图；暂停显示与暂停输入是不同操作。

## 数据隔离与评价

运行包仅含原图／hash、公开用户脚本和输入时间；真值包单独保存可见性区间、审核记录、评分规则。Agent不接触GT房间、坐标、未来脚本或完成答案。测试作者、输入调度器和评分器的权限分别限制。

先以脚本化用户做可复现验收；不先用同一模型扮演用户、生成真值再自行评分。将来增加用户模拟器时只给它用户背景、已交付回答和允许的事件，不给视觉GT／未来；其真实性也需审核。

主要指标：故事独立完成率、错误提醒／重复提醒／漏提醒、未获确认即完成、取消后输出、无依据当前性断言、追问澄清质量、故障反馈与恢复、文字负担、端到端等待及成本。自动检查状态／时序／引用，语义另做人审；没有独立人审时明确标注，不折算成“视障人士可用率”。

## 实施顺序

1. 校园清单适配与hash校验，支持原PNG三视图，保留851观察与断拍时间；不复用4帧光学演示作为校园主输入。
2. 补全对话、寻找／关注状态机、当前性与控制并发；以录制片段测试，先不全量烧费用。
3. 原图审核首批故事，分离用户脚本与验收依据，先冻结再跑；未审核故事不计分。
4. 跑少量端到端故事并在网页验收。失败修正后从空状态重跑，不拼接成功回答。
5. 冻结新版代码、任务和预算，完整校园新任务运行；旧90题另作回归，不混分。保留全部中断、失败及调用收据，再生成同次结果的网页回放。
