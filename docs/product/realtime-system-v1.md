# 真实相机到实时生活助手（开发版）

## 启动

```powershell
npm.cmd run build
node dist/current/desktop/realtime-server.js --allow-paid
```

打开 <http://127.0.0.1:8884/realtime.html>。原桌面首页的“实时”入口也指向该地址，实验回放继续使用8883。只打开页面不会启动采集或模型。服务默认只监听loopback；需已配置QWEN_API_KEY和QWEN_BASE_URL，沿用本机忽略目录中的校园凭据和COM3设备。页面勾选模型和每会话预算后开始；不勾选则只采集。每会话最多60张、间隔2秒，设备服务仍有180秒寿命。停止后需等在途建模／问答完成才能开新会话。

模型为qwen3.8-flash、enable_thinking=false；空间估算预算USD0.50、问答USD0.25，未知调用保守占额。每次新会话重新计预算，**不是全生命周期总额**。没有自动续费／自动恢复／付费重放。浏览器同源检查、JSON限制和loopback host检查作用于启动及提问接口。

## 数据流及隔离

1. `RealtimeSession`启动独立Python采集进程；原始JPEG、校验失败响应、收据完整保存在`run/realtime-system/<session>/capture`，采集不等模型。
2. 已提交收据经过已有cameraObservation校验，保存到本会话`memory.sqlite`的originals。`prepare_live_image.py`生成用于既有PNG模型适配器的派生PNG，验证解码RGB像素哈希相等；原始JPEG仍保留并供前端查看。这不是重新压缩JPEG，也不补左右视图。派生PNG可能比JPEG大，不宣称它降低云端上传量。
3. 容量1的最新帧队列／2500ms门限筛选模型当前输入。所有被替换／过期帧仍留归档；推理间隙以未知访问打断拓扑。模型耗时可能远超采样间隔，因此不会逐张建模。
4. `RealtimeMethod2`复用独立感知、固定组完整成员对比、冲突否决、短引用、recent2/visual2召回及最近访问序列，禁用图关系。**这是方法2的单视图适配版本，不是原三视图实验的等价复现或准确性认证。** 每观察只有一个真实72维RGB描述符；联合对比上限12张实际图像。
5. 判断按完成时间提交judgments。晚到判断是历史记录；只有它仍对应最新新鲜帧且采集活跃，才可显示为“当前地点”。否则显示“待确认”，另列历史地点时间。近物局部画面不足建立空间时保留unknown，不为了演示强造地点。
6. 提问时复制已接收原图和当时已提交判断的因果快照。问题Agent只得到值快照，不持有生产者或写空间记忆的句柄。最多8轮工具动作，search→inspect→answer；历史肯定回答要求检索并查看原图。原图不足则拒答。QA记录另存questions，不修改分组。
7. 页面每500ms读取状态，展示真实前图、缺失视图、新鲜度、空间处理进度、历史判断、用户问题／助手回答和证据原图链接；断流／断开服务器不会继续显示当前地点。回答始终附提问／返回时间，不宣称返回时仍是当前情形。

## 使用边界

链路仍有校验失败与长尾；当前服务遇到异常保留证据并停止，不自动重认证校园账号。场景在拍摄时以桌面近物为主，不能由物体识别成功推导空间识别成功。单摄、缺失方向、粗RGB召回和固定组增长成本限制继续成立。

当前记忆按会话独立；落盘可审计，服务重启不会自动恢复生产者或跨会话合并。历史独立验收工具为`node scripts/testing/check-realtime-history.mjs SESSION NEW-OUTPUT --confirm-paid`，独立上限USD0.10，显式付费，不篡改原会话。尚需后续完成长时断线恢复、会话浏览／加载UI、多场景空间质量验收和真实用户评测。
