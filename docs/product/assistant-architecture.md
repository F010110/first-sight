# 生活助手应用架构与电脑浏览器入口

本次把应用主线从“空间记忆运行器”扩展为生活助手的可运行骨架；不实现完整生活技能，不改硬件、模拟器或冻结记忆算法。浏览器为文字输出终端，无扬声器、ASR、TTS依赖。

后续更新：用户已恢复模拟器开发。桌面支持三视图录制轨迹回放；硬件仍暂停，冻结算法未改。

## 模拟器输入与文字输出

前端点击“开始／继续模拟回放”，按2秒间隔读取轨迹，显示前／左／右实际图片，送入同一个生活助手输入端。可在对话区提出问题；VLM返回的正式答案显示在对话中，原始空间判断的reason／下一步／answer单独显示在“VLM调用后的文字输出”中，明确标为未核验模型陈述。不会把模型原始输出自动提升为用户答案。

默认轨迹`run/sim/hardware-vga-nominal160-v2`只有4个位姿，主要验证接线；不是长时间演示。需要更长的已有轨迹可在启动前设置`FIRST_SIGHT_SIM_EPISODE`：目录需有`frames/数字.jpg`，可有同名`left/`、`right/`图片。不上传房间GT、坐标或任务真值给Agent。

默认画面640×480，采用160°对角等距的既有近似，未做新标定。播放时间为主机输入时刻，不是原轨迹曝光时间。每轮保留原图、hash及来源帧；不自动循环；结束后重新播放需新建服务会话。繁忙时等待，实际播放间隔可大于2秒。模型空间判断沿用窗口调度，不是每个前端刷新都调用VLM；短轨迹未满窗口时，用户问题会触发待处理图像分析。

这是录制模拟数据回放，**未实现浏览器方向键控制AI2-THOR角色／实时渲染服务**。前端画面与状态按1秒轮询，VLM原始语言按2秒轮询；不是token流式输出。模型默认关闭，不会造假语言；需`--confirm-paid`才会真实调用。新HTTP集成测试验证实际三图读取、图片服务、来源标记及暂停，无付费请求。

## 启动

```powershell
npm.cmd run assistant:web
```

打开 http://127.0.0.1:8880 。默认不调用模型，不返回模拟答案；可测试状态控制、图片导入、错误反馈。真实问答需要配置`QWEN_API_KEY`、`QWEN_BASE_URL`并明确授权：

```powershell
npm.cmd run assistant:web -- --confirm-paid
```

仅绑定本机；不是可部署的多用户服务。默认端口可通过`FIRST_SIGHT_DESKTOP_PORT`修改。普通对话使用`qwen3.8-flash`、关闭thinking、每会话64请求上限；空间能力沿用现有有界传输，256请求／估算USD1预算。对话请求数量上限不等于金额预算。取消阻止迟到结果交付，但不保证撤回已发出的云请求或费用。

## 职责

```text
web/desktop                    电脑浏览器：对话、任务、控制、原图预览
       ↓ HTTP
src/desktop/server.ts          本机传输、原图归档、大小与JPEG头检查
       ↓
src/assistant/runtime.ts       会话、任务生命周期、取消代次、观察授权
       ├── qwen-planner.ts     候选意图路由／非视觉回答；不执行控制
       ├── capabilities.ts     能力注册表与明确的未实现边界
       ├── output-policy.ts    文字交付仲裁；取消／过期／去重门禁
       ├── journal.ts          原始事件审计，不当作已核实事实
       └── spatial-capability.ts
                    ↓
src/agent/spatial-context-*    原空间Context、原图检索、SQLite（未修改）
```

`contracts.ts`定义能力、规划、观察服务和输出端口。核心运行时不直接依赖SQLite、摄像头驱动、Qwen或浏览器；未来可换输入／输出，不需要把生活任务逻辑塞进空间Context。旧`trial:web`仍是兼容原型，没有冒称完成旧链路迁移；`src/agent`暂不批量移动，以免破坏冻结引用。

## 当前闭环及边界

- 对话不要求图片；视觉图片问答与本会话历史检索由注册能力执行。
- 自动路由或显式选能力；控制按钮和准确控制短语走确定性接口，不经过模型。复杂自然语言控制意图尚未实现。
- 观察状态与文字输出状态独立；停止采集不会删除历史。取消任务不撤回已呈现消息。
- 仅手动导入1–3张真实不同JPG，不复制缺失视图；留存原始字节、SHA256和尺寸。服务检查JPEG头而非完整像素解码；不宣称图像完全有效。
- 导入时刻是主机接收时间，不是已验证拍摄时间，也没有验证多图曝光同步；所有图片答案标注非实时。
- 新鲜度门禁采用30秒原型阈值，不是经用户验证的性能指标。图片回答迟到后不作为当前观察交付。
- 空间适配器按独立窗口调度，询问时按序处理待分析图；停止时未分析图以未知归属保留，不伪造空间结论。空间推理异常后熔断，保留失败现场，需要新建服务会话。
- 持续关注、专门OCR流程、活动推断、安全提示、用户删除仅注册为不可用能力；没有定时器、导航、外部写入或自主提醒完成承诺。
- 输出仲裁已预留主动候选门禁，但当前没有自主事件生产器。模式选择不表示实现休息／交谈检测。

## 数据与验证

本地资料写入`run/assistant-desktop/<新会话>/`：原图、事件、状态快照、对话原始返回及usage、空间SQLite和调用日志。包含私人数据，不要分享审计链接或提交这些目录。重启创建新会话，不自动恢复历史Context；状态快照仅供诊断。当前未提供用户删除闭环或长期会话恢复。

构建：`npm.cmd run build`；新增单元测试：`node --test dist/current/assistant/*.test.js`。测试覆盖无图对话、取消迟到结果、观察授权与新鲜度、输出／采集独立、过期／重复抑制。它们不等同于真实模型、全链路图片解码、读屏或真实视障用户验收。

本次验证：构建、5项新增单元测试、43项空间回归、文档链接及HTTP页面／控制／跨域拒绝检查通过，零真实模型调用。浏览器工具未连接，因此尚未进行可视布局与浏览器交互实测。
