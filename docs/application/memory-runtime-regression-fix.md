## 第二个实现问题：只改Agent.state并未改变实际请求

新增mock端到端断言发现：工具inspect完成后修改`agent.state.tools=[]`，第三次实际HTTP请求仍带工具，JSON最终回答阶段没有真正启用。当前SDK在启动run时复制工具上下文，不能依靠修改外部state切换正在进行的请求。

修复在实际发送层进行，而非继续改提示词：

1. **取证阶段**：发送工具schema，不强制JSON-only；有公开明确指定且尚未查看的记录时设置`tool_choice:required`。目标来源只来自公开问题的时标和当前ID，不来自私有答案。
2. **回答阶段**：所有明确指定来源已实际查看后，从请求payload移除tools/tool_choice，再启用JSON对象格式，输出引用。oracle真实预提供图和当前图已登记来源，可直接进入回答。
3. 工具返回的图像明确携带源段号/源时标，避免把合成活动时钟当作录像秒数。
4. 保留原始图验证、权限、原图引用和最多2次反馈修复。若找不到所需来源或受限调用耗尽，留下失败/拒答，不能自动补证据或无界重试。

`qwenNonthinkingPayload`单元测试检查取证/回答实际payload；topology/archive两类RequestAgent真实mock工具循环均验证前2次工具请求不带response_format，最后一次不带tools且带JSON格式。连同来源、反馈、检索隔离共9项TS测试通过，默认不启用新运行策略，不修改冻结基线协议。

## 实际端点修复验证

同两道问题各重复3次：6/6次执行真实search→inspect→合法JSON回答，每次3个模型请求，无需重试。仅验证公开指定来源被实际取得、引用与格式；没有把答案键传入。记录`runtime-fixed-regression-v1`，18请求、公开价估算USD0.00862；小规模验证不等价于全量成绩。

## v4 oracle完成后的反证与限定探针

oracle90题完成后，三卡为78.9/72.1/82.2，当前/短/长任务分90/75/71.7。**这不满足oracle校准要求，不能据此宣布只剩空间算法问题。**工具链小样本恢复不代表整个回答协议修复完成。

检查发现多道回答引用了指定历史ID但内容描述其他画面；例如第4段0秒户外图被说成黄色瓷砖室内走廊。当前发送顺序确为当前3图再历史图，但身份映射仅放在前置长段文本中，且通用提示还说“使用当前图，按时间顺序”，与历史题冲突。不能只凭这点断言所有错误都由顺序导致。

新增**仅6题开发探针**，不自动接全量：4道已知来源混淆、2道正确拒答但flag错误。保留相同原图和顺序，每张图前紧邻放公开来源ID/源段时标/相机标签，去除“全部图按时间顺序”的冲突；mock实际HTTP断言标签后紧接的图片base64匹配。另修复拒答校验仅匹配句首的漏洞，现在“当前画面无法确定…”也反馈flag不一致，不自动改模型答案。结果单独存`memory-oracle-image-label-probe-v1`，不能替代90题正式分数。编译隔离于`dist/evidence-label-probe`，未修改在跑v4冻结产物。

探针完成：4道历史内容全部恢复正确，2道拒答flag正确；总8请求、USD0.00415估算、无未知用量。一次小样本改善支持逐图绑定有效，但不是独立泛化验证，不能把6/6作为正式成绩。新增非句首拒答单元测试及实际HTTP图片紧邻标签断言后，9项测试通过。

随后只启动`{spatial-memory,memory-oracle}-image-label-v5`各6题冒烟+判分（`dist/evidence-label-tests`独立冻结），不自动接全量。核验冒烟实际来源与协议、oracle内容后才能决定后续；不把v4低分隐藏或混合替换。

### v5冒烟结论：未通过，不启动全量

两组各6题完成，但最终结果仍各有1题缺少明确指定的来源引用（空间组比较题漏历史ID，oracle跨楼层题漏当前ID），反馈重试后仍未满足协议。原先错认的第4段0秒题两组均已正确。空间组跨楼层拒答，oracle则凭装饰相似断言同层；这同时暴露证据充分性/视觉推理与引用遵循问题，不能归为已证实的空间检索失分。
