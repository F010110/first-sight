## 第二个实现问题：只改Agent.state并未改变实际请求

新增mock端到端断言发现：工具inspect完成后修改`agent.state.tools=[]`，第三次实际HTTP请求仍带工具，JSON最终回答阶段没有真正启用。当前SDK在启动run时复制工具上下文，不能依靠修改外部state切换正在进行的请求。

修复在实际发送层进行，而非继续改提示词：

1. **取证阶段**：发送工具schema，不强制JSON-only；有公开明确指定且尚未查看的记录时设置`tool_choice:required`。目标来源只来自公开问题的时标和当前ID，不来自私有答案。
2. **回答阶段**：所有明确指定来源已实际查看后，从请求payload移除tools/tool_choice，再启用JSON对象格式，输出引用。oracle真实预提供图和当前图已登记来源，可直接进入回答。
3. 工具返回的图像明确携带源段号/源时标，避免把合成活动时钟当作录像秒数。
4. 保留原始图验证、权限、原图引用和最多2次反馈修复。若找不到所需来源或受限调用耗尽，留下失败/拒答，不能自动补证据或无界重试。

`qwenNonthinkingPayload`单元测试检查取证/回答实际payload；topology/archive两类RequestAgent真实mock工具循环均验证前2次工具请求不带response_format，最后一次不带tools且带JSON格式。连同来源、反馈、检索隔离共9项TS测试通过，默认不启用新运行策略，不修改冻结基线协议。
