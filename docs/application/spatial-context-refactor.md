# 持续空间Context重构：实现、重跑与边界

## 当前有效规则：窗口Context v2（取代下文早期逐观察版本）

- **窗口级调用**：沿用最早观察等待10秒、两次启动至少5秒、每窗最多4组观察的调度；录像边界及末尾flush。每次VLM给窗口内每组观察一个空间判断，只有带问题的窗口同时问答；检索续轮同样必须返回窗口判断。
- **短期Context不恢复**：删除自动从长期库重建近期判断的路径；新会话从空Context开始，缺背景主动查长期记忆。保留最多6个近期判断、4个地点锚点、4项已读证据、4项近期输出；观察时间跨度超过60秒的旧内容过期。单项输出超过2400字符时只给短期视图留截取标记与摘录，完整原文在长期记录。
- **任何模型输出双写**：空间判断、回答/拒答、search/inspect请求都进入Context及SQLite model_outputs；包括用户问题和状态。原始HTTP响应另存长期日志；无法解析的模型响应也进入短期输出记录。合法结构化响应在Context只保留一份，避免原始API包装和解析结果重复干扰。记录均标“未核实模型输出”，不自动升级成事实。
- **长期交互可读取**：空间查询继续使用真实SpatialRetriever；另外允许字面查询旧交互记录，返回model-output来源ID。交互记录可读但无图片、明确不是视觉证据，不能用作空间assessment来源，也不能替代“必须历史原图”的问答证据。
- **窗口新地点别名**：同窗new-1映射同一持久UUID，不同别名映射不同候选。窗口内判断按观察顺序写入长期库，再更新短期视图；已提交判断变化仍有修订记录。
- **来源校验及续轮**：要求前一窗口原图的问题，当前窗口ID不能充数。错误回答原文留存并标为拒收，剩余预算内给来源反馈继续取证，不自动补ID，也不覆盖原错答；最多4轮。历史图片读取实际发生后才允许引用。

### 本轮验证及产物

1. 旧逐观察回放在178组后停止；`run/spatial-context-refactor-full-replay-v1/superseded.json`明确标为过时，原结果未删，不计新版成绩。
2. 窗口当前问题冒烟：`run/window-context-current-smoke-v1`通过，12组观察合成3个窗口。
3. 历史窗口冒烟v1把当前图冒充历史来源，v2在反馈后仍未取图，均原样保留为失败。加入明确的窗口来源列表与历史图门禁提示、去掉Context重复的API包装后，`run/window-context-historical-smoke-v3`通过实际历史取证。
4. 新旧SQLite、实际检索、窗口覆盖/尾部flush、四观察一次调用、问答双写、短期过期和冷启动空Context共12项测试通过。
5. 新版完整851组窗口回放使用独立冻结代码和新目录，保留计划、代码/原图哈希、每轮输出、长期交互表和用量。完整观察回放仍不是90题成绩，不能把少量问答冒烟记作完整评测。

### 不能只验协议：地点全未知问题

额外SQL审计发现current-smoke-v1与historical-smoke-v3都为12条null归属、0地点。此前“通过”仅表示协议/历史取证通过，不代表空间记忆可用。`run/window-context-full-replay-v1`因此在16组入库（12组已判断）时暂停，标记superseded，保留4组pending与所有请求预留。

随后仅补充地点候选建立规则：未知建筑用途/没有旧目录不构成全部null的理由；首次正面布局足够时可以建候选，但不允许仅因匹配失败就随意新建。增加“至少建立一个地点”的回放验收门槛，不把全null当成功。`run/window-context-historical-smoke-v4`真实端点复跑结果：12组、3窗口、1个地点、12个归属、1次visit、pending=0，且实际历史取证通过。这仍然只是必要门槛，不是对所有空间边界/重访身份的准确率证明。

修正后的全量产物另存`run/window-context-full-replay-v2`，不覆盖v1。全部851组规划为217窗口；其中1个窗口带历史问题，其余调用仍作空间判断。后续90题正式评测仍单独进行，不把这一次历史问题说成90题覆盖。

下文保留早期实现与失败分析以便追溯；其中“自动恢复Context”“每观察一次调用”的描述已经失效。

## 版本范围

本次建立独立的新控制链，旧版空间库、RequestAgent、90题预测和评分保留。新链不是把旧摘要换个名字：每一次推理都必须先产生当前空间assessment，再决定完成观察、检索、取图或回答问题。

当前新入口为`src/sim/spatial-context-smoke.ts`，配套模块为`spatial-context-loop.ts`、`spatial-working-context.ts`、`spatial-context-memory.ts`、`spatial-context-vlm.ts`。它仍是实验入口，尚未将全部应用服务器/旧90题runner切换到新链，不能宣称整个产品已完成迁移。

## 六个模块怎样协作

1. **原始经历写入**：新观察先写SQLite，模型失败不删除原始经历。重复观察ID要求原始内容一致，时间倒退和ID冲突拒绝。随后将当前观察写入工作Context，当前位置暂时置为未确认。
2. **空间推理与控制**：模型输入是工作Context、当前原图、已读取的历史原图、问题及剩余预算。每轮必须返回当前观察的空间身份、理由、原图来源。地点仅允许new、未知、Context或已看图证据中的地点ID。
3. **长期写入**：new转换成持久UUID；首轮提交assignment、地点、visit、transition。后续判断变化以可撤销reassess修订写入，不重写原图；更新访次与边关系。判断中的来源ID保存在assignment原始JSON。持续判同一地点不意味着每次新建地点。
4. **Context更新**：长期写入成功后才发布新判断到工作Context。近期判断保留6条；具体地点锚点保留4条；已查看历史证据保留4条；理由最多400字符，来源ID去重限制8个。新观察清空前一观察的临时检索证据，但不清空近期经历。锚点按地点身份而非“走廊”等类别组织。
5. **读取长期记忆**：使用实际SpatialRetriever。可先字面搜索，候选不算已看图；也可凭Context中的可追溯来源ID直接请求原图，此时适配器用该记录的准确时间在真实检索器中注册候选并读取。只允许当前之前的记录，历史图预算12张；不能通过猜ID取证。
6. **回答**：证据足够时输出正文、来源与拒答标志。答案来源必须实际交付；问题为空时不允许伪装问答输出，问题存在时不能只finish。最多4轮推理，无结果明确返回预算耗尽，不自动变成成功拒答。

## “每次VLM都判断空间”的含义

即使上一轮已经判断过位置，搜索后的下一轮、原图返回后的下一轮和最终回答轮也必须重新给assessment。可以确认原判断，也可以基于新证据修正为已知地点或未知。不能把旧reason原样复制成新判断、不能把旧地点状态默认当当前事实。

判断与控制行动分离：assessment写记忆；next选择操作。答案的sourceIds与assessment.sourceIds也是独立字段，不能因为空间判断有引用就省略答案引用。

## Context压缩与恢复

这版工作Context是独立的结构化工作记忆，不是每个问题重新抽一份背景摘要。观察、推理、检索结果都按明确规则更新它；每次模型调用发送其有界快照，历史原图另以有界材料发送，不无限追加聊天历史。

压缩目前是确定性的容量约束、地点锚点保留、来源去重、理由截断；不宣称已做语义重要性学习。旧证据只从工作视图移出，原记录仍在长期库。重启时从截止前已提交的早期4条＋最近6条判断恢复有限Context，而不是复原所有历史对话；历史查询工具的临时状态不恢复，需要重新取图。

双写不是两个数据库的分布式事务：长期库提交成功后更新内存Context；中间崩溃时从已提交长期记录恢复。若磁盘失败，则不发布新Context判断。恢复是有损的有界工作视图，不能声称内存逐字节检查点。

## 实测发现与修复

- `run/spatial-context-refactor-smoke-v1`：3次实际请求，第三轮答题遗漏next.sourceIds；原失败和原始响应保留。
- 单独增加明确的答案引用协议示例后，`run/spatial-context-refactor-smoke-v2`三观察/当前问题冒烟通过。不是90题分数。
- `run/spatial-context-refactor-historical-v1`：模型直接inspect一个Context中已有的历史来源；旧控制门禁只允许search后的ID，导致失败。
- 改为允许Context来源寻址，但仍必须通过真实检索器读取原图。`run/spatial-context-refactor-historical-v2`历史取证冒烟通过，实际返回非当前来源引用。
- TypeScript编译通过；新Context/循环/SQLite与旧SQLite服务、检索、锁定协议回退共11项测试通过。

## 正在执行的完整观察回放

`run/spatial-context-refactor-full-replay-v1`使用冻结的`dist/spatial-context-refactor-replay-v1`，按顺序重建全部851个观察的新空间库，逐帧校验三视图哈希。此处每个观察都走新循环，不复用旧217窗口的空间判断。每观察最多4轮，总模型调用上限3404，公开价估算预算上限USD2，单次输出1200 token，未知调用保守预留；错误停止并保留原版本。执行文件哈希、数据哈希、计划、请求原文、用量及失败都落盘。

这一步是完整**观察回放**，不是90题完整判分。只有第3个观察带当前视图问题，不能用它宣称用户问答全量通过。后续仍需新链日历查询适配、明确来源门槛、应用入口迁移和90题统一评测；旧93.3/94.1/97.2不转记为新版本成绩。需要根据实际回放失败修复后，再运行新版本，禁止覆盖失败目录。

回放开始后另做的离线加固：明确检查answer的abstained类型、重复读取同一来源时替换本轮图片而不是重复堆积、真实发送前检查当前≤3/历史≤12张图。6项新链测试再次通过。此后续源码未修改正在运行的冻结dist；不得将后续加固效果混记到full-replay-v1。
