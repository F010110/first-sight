# 带失败反馈的有限重试诊断

按用户要求补上失败回退：`src/sim/memory-answer-repair.ts`根据公开问题、公开时标、当前ID、实际inspect集合验证JSON、引用齐备和拒答flag；`retry-memory-evaluation.ts`反馈具体原因及前次原文，最多重试2次。每次新会话重新获得同范围检索权限，仍使用原空间库或原oracle图，不把私有标准答案/评分结果送给模型。

不使用“答错了，应该是什么”作为反馈。语义错误但格式/引用合法的回答无法在运行时靠答案真值检测，因此保留，作为修复后仍待解释的失分；不据此无限重试。原因和所有attempt均保留，取**最后一次**，不取最高分，也不改写模型引用。

两组新目录`run/school-spatial-oracle-v1/{spatial-memory,memory-oracle}-repair-v1`，原始90条和原成绩不覆盖。启动后自动接判分；单组最多240新模型请求、公开价含未知用量预留上限USD1，判分另守USD1.5上限。系统请求/用量错误停止留档，仍不放开总预算。qwen3.8-flash，enable_thinking=false。

这是**已知开发题上的协议修复诊断**，不是新的独立系统成绩。选题由对全部90条原输出运行公开协议检查产生，不读取私有分数挑题，可能覆盖内容已答对但漏引用的题。为避免重复judge随机波动冒充修复收益，`sim/report_memory_repair.py`最终配对报告对未重试题沿用原始分数；重试题取最后输出的新分数，允许变差，所有来源保留。

四项TS测试通过，覆盖JSON/引用/flag检测、真实RequestAgent工具链、空间检索因果范围与oracle原图验证。两组修复及判分正在执行，完成前不宣称新分数。

空间组首次修复在已选54题、第55题第1次修复触发单次8调用限制后停机（累计91请求、估算USD0.06456）。原执行器把局部耗尽误归为系统错误；修正为局部尝试失败可进入剩余第2次尝试，总240请求/USD1不变。新增断点恢复已选前缀和pending尝试计数，已完成题不重付费、pending不会重置为新的两次；原freeze归档、续跑快照保留。不是无限增加重试次数。系统/用量异常仍停机。

**剩余错误的解释**：修复后可以更清楚地分离空间算法和工程协议问题，但残余仍可能是证据不充分、图像理解、标签歧义、判分问题，并非自动全部属于空间算法。
