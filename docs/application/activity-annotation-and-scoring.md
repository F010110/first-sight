# 源流程辅助标注与评分机制 v1

## 1. 标注不是看图猜房间

本轮直接阅读并复核：

- `sim/build_activity_samples.py`：每条路线按源索引约2秒取三向图，保留末帧；路线按编号排列；段间20分钟空档人为设定；不是原生全天活动录制。
- 固定revision的10个`metadata.zip`：`collection_config.yaml`给出相机名称/模态；`pose_lcam_front.txt`给出每帧位姿；各轨迹metadata给出`time_step`、`robot_height`、原生帧数。
- 私有source truth、episode日程、模型输入观察表和实际图片hash：逐观察核对索引、ID、位姿、源时间、合成时间和图片未改动。
- 全部15张三摄稀疏图册：98个实际查看过的语义锚点。源配置**没有房间polygon/楼层ID**，本地也没有原采集器实现/地图；不编造它不存在的GT。

重要发现：不同轨迹`robot_height`为0.53–1.69米，相同地表的原始Z并不一致。`Z + robot_height`在外部/室内锚点上近似一致，支持相机高度偏移的解释，但只是对齐假设，不能当官方坐标转换。只在同一源轨迹内用垂直差与楼梯图像联合确认不同物理层；不靠欧氏距离阈值直接判房间。

### 标注层次与冲突规则

| 层 | 来源 | 可确认内容 | 不得推断 |
|---|---|---|---|
| 来源/时间 | 生成脚本、metadata、原始位姿及hash | 原始观察、采样、先后与显式空档 | 关机期间走了哪条路/物品是否移动 |
| 几何约束 | 同源连续位姿、已见楼梯/通行 | 重访候选、不同物理层、边界候选区间 | 近距离=同房间；跨路线原始Z=楼层 |
| 可见语义 | 原始三摄图像 | 当时可见的室外/走廊/球场/教室/书架房间及事实 | 同类房间=同实例；功能标签=准确边界 |
| 任务真值 | 上述联合证据及问题截止时刻 | 可回答答案、所需证据集合、拒答理由 | 用未来画面补过去答案；用识别输出改标签 |

每个观察都落一条标注记录；未看过的观察写`source-verified-semantic-unreviewed`，不是自动复制相邻锚点。过门/楼梯允许边界待定，保留候选区间；相邻帧之间不假装知道精确越界时刻。房间实例和楼层未验证时保持null。AI初标与独立人工审阅分开保存。

## 2. 正式成绩单只有三张卡

### 实际问题解决（0–100）

问“最后在哪里见到某物”“去过哪几个地方”“当时看到什么”“两个时刻是否同一处”等实际问题，不考预测UUID是否相同。

单题：任务完成且证据有效=1；仅完成非关键子目标=0.5；错答/证据错误/可答却拒答=0。确实不可知的问题，正确拒答=1。缺失预测按未解决计，不删分母。答案猜中但引用了别处图片不满分。

固定类别权重见`activity-benchmark-design.md`，类别内平均、再按活动样本等权汇总；权重和题目在看本轮预测前冻结。不能因当前没有状态变化素材，就删掉变化类并把剩余任务重算成“全能力高分”；缺必测类别时正式整卡显示未就绪，窄能力开发测试另列。

### 长程与干扰（0–100）

用同样任务规则，但只测长间隔重访、相似地点/跨层干扰、已观察状态变化。先按挑战类型再按合格样本等权。未提供真实状态变化证据时标“未测”，不能用两张静态图假造变化任务。20分钟关机空档可以测长间隔记忆，但不能测空档中的实际活动。

### 回答可信（0–100）

逐题审核错误后果：误导行动/找错地点、跨层混淆、把旧状态断言为现在、捏造不可知内容等重大错误扣1；不影响行动的附带事实错误扣0.25；正确或明确不确定扣0。按同样固定类别/样本权重算`100 × (1 − 平均损害)`。

全部拒答可以不误导，但任务解决分低；没有一个加权总分把这种系统包装成好用。可信分必须与任务解决分并列看，不单独排名。

### 为什么不直接扣误合并/误拆分

- 两个节点实际上是同一房间，但找物答案和证据都正确：不扣。
- 门口前后节点划分不同，但用户问的地板材质答案正确：不扣。
- 将上层和下层混为一处，导致用户被指向错误楼层：任务不得分，重大可信扣分。
- 用户明确问“这两个时刻是否同一房间”，误拆分此时确实回答错；扣的是该问题，不是数据库多建了一个节点。
- 数据库有潜在误并但尚未影响测试题：留诊断，不臆造实际损害。宣称某QA错误由误合并导致，还需要反事实实验，不凭共现归因。

覆盖率、门控跳帧、误并/误拆数量、边界偏移、检索召回、延迟与账单都放审计/运行附页，不混入三张最终分卡。

## 3. 本轮实际产物与开发评分

- 全部851观察通过源索引/位姿/时间/图片hash联合核对。
- 98个锚点有AI语义初标，753个观察语义仍未审；没有声称851个房间标签已完成。
- 冻结16道源证据问题：12道可见事实、4道未知/空档拒答；另有13道地点身份后果探针。问题包公开部分不含答案、语义标签或证据ID。
- 16题还没有实际执行端到端QA，因此不报告它们的准确率。最后见到、整段过程顺序、观察到的对象变化尚未完成足量真值。
- 13道探针在旧P0000/P0007/P0009数据库上做只读身份查询，**不是VLM问答运行，也不是独立测试**。按源路线等权的开发结果：身份问题完成20.63/100，身份回答可信95.24/100。高可信伴随低完成正说明不能单看可信分。
- 探针逐项：3题正确、1题错误地断言同地点、9题无法从所问原观察取得两个确定身份。未分配不自动找最近已分配帧替换；这9题也不能等同“历史检索一定答不出来”。
- 错误为P0007的26s与80s：同一路线原始Z差**5.00197米**，旧库仍赋同一ID。来源流程与图像共同支持不同层，不是只凭墙面相似度判定。
- 没有整段851观察统一新模型回放；三份旧库不能冒充同一27分钟连续记忆库。正式系统三卡保持未发布，窄探针数值只用于开发定位。

## 4. 如何复现及下一道验收门槛

```powershell
python sim/annotate_school_activity.py <school-sample> <rgb-sources> sim/school_activity_annotation_v1.json <new-annotation-output>
python sim/build_school_activity_tasks.py <school-sample> <annotations> <new-task-output>
python sim/score_activity_identity_probes.py <identity-probes.json> <new-score-output.json> --database P0000=<db0> --database P0007=<db7> --database P0009=<db9>
```

所有输出不可覆盖，保留源revision、标注规范/输入/代码hash以及所评分数据库及WAL hash。18项activity测试通过，包含改图片/改时间必须失败、未看帧不补标签、ID重命名不影响后果评分。

下一门槛：逐观察检查边界/语义剩余项，明确实例约束；补足自然的最后见到/顺序问题；同一完整样本因果回放到统一记忆库；问题截止时刻隔离执行retrieve/inspect；独立复核答案与所有事实性附带叙述。完成前不能把开发探针或评分器夹具当正式成绩。
