# 来源协议v2与使用就绪判断

## v2新暴露的时钟映射缺陷与v3

v2 oracle完整90条及判分完成，任务83.3（当前98.3/短期75/长期76.7）。该成绩不能当算法不足的证据：逐条发现oracle预提供图仅标了合成活动atMs，没有“第N段T秒”的源时标映射，模型多次把已提供图误认为其他时刻或宣称目标记录未提供。图像选择未变，但输入元数据不足，属于评测适配缺陷。

v3每张预提供图明确id、camera、episodeNumber、sourceAtMs、sourceReference及activityAtMs，并说明两套时钟不同；trace新增实际输入来源收据。对oracle已提供却声称记录缺失的回复反馈来源错误（不反馈答案）；视觉证据不足仍允许拒答。两组以同一新规则完整重跑6冒烟＋90全量，目录`*-provenance-v3`；编译产物独立`dist/provenance-v3`，不改正在运行v2的冻结文件。原v2失败及分数保留。额外请求/费用仍有每阶段原预算，不进行无限版本搜索，完成前不宣称oracle上界已校准。

## 为什么前一次修复仍失败

1. 当前三摄已经作为模型输入，但旧校验只认工具inspect过的图；模型必须重新找当前图才能合法引用。
2. 反馈漏引当前ID后，模型可能只把ID写入引用，并没有工具inspect；旧规则继续拒绝。另一些尝试选择其他时间的相似房间图，而不是所问记录。
3. 单纯文字重试不能消除JSON错误、来源约定冲突或参考证据不足。最多2次后仍失败必须留下，不能无限重采样直至满分。

## 本次修复

- `withCurrentEvidence`仅对已经hash校验并真实输入的当前图登记来源，允许直接引用当前ID，不修改模型输出、不自动补引用；未知/未查看的历史ID仍拒绝。
- 模型提示明确当前图ID、三向相机顺序、可直接引用；历史必须检索/查看指定时刻记录。oracle补充图也有同样来源信息，当前图不重复附加。
- RequestAgent新增opt-in JSON传输约束，默认与冻结基线不变。新评测开启`response_format:json_object`，仍用qwen3.8-flash、enable_thinking=false。
- 两组统一从头运行全90题，不只反复挑错题。每题首次＋最多2次基于公开协议错误的反馈修复，保留最终尝试和所有历史。选择/反馈不读私有答案。
- 每组先6题冒烟＋判分，再90全量＋判分。新目录`run/school-spatial-oracle-v1/{spatial-memory,memory-oracle}-provenance-v2`，编译代码hash在冒烟前冻结。旧分数和失败不覆盖。
- 五项TS测试通过：当前来源允许、历史越权拒绝、JSON/引用/flag反馈、实际retrieve因果范围、RequestAgent真实mock工具链。

预算单组：冒烟问答USD0.5、全量问答USD2，另冒烟判分0.2/全量判分1.5公开价上限，两组累计名义上限USD8.4；原记忆库复用。最大问答请求单组冒烟144/全量1080，局部每尝试8。缺用量保守预留128k输入/512输出并停机，不假称实际账单。Full memory继续暂缓。

## 如何判断剩余是否来自空间算法

不能靠取消扣分或反复重试保证“只剩空间算法错误”。必须保留并单列：

1. **工程协议故障**：最终JSON/来源/flag、调用失败；不当作空间识别失误。
2. **参考证据与标签问题**：跨层题缺楼梯经过、场所命名等；需要另冻结证据审计，不偷偷用私有pose告诉模型答案。
3. **回答模型错误**：同样充分证据下仍推断错误；oracle也错时不能直接归空间库。
4. **空间算法任务失败**：有充分可用历史但未检索到/关联错，并且oracle同题在匹配协议下可答对。尚需对确切失败逐题复核，而非只看两个均值之差。

## 当前使用结论（新结果前）

**不能批准无人监督正式投入使用。** 可以在保留原图、可拒答、人工可核对的受控开发演示中测试，不能当作已经过可靠性验收的产品。

已知不足：相似装修导致跨层推断错误；时间戳查图可绕过地点身份推理；现90题仅4题曾用placeId查询，未充分测合并/拆分的用户后果；自然找物、状态变化、多环境长期稳定性未测。即使新来源协议使90题接近满分，这些验收缺口仍在，不能凭单学校开发分数宣布生产可用。

最终结论应在新两组完整结果后更新，但这些未测能力不会自动被高分补齐。
