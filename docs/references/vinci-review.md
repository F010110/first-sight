## 架构能借鉴什么

Vinci 的主线是第一人称视频流进入流媒体服务，再由后端按会话组织视频帧、模型推理和回答。公开部署示例使用 RTMP/SRS 接收手机或运动相机视频，配有前端、后端、InternVL 推理服务，以及记忆检索和语音等服务。

模型侧不是把每帧分别当成新聊天：静默观察会生成带时间戳的文字摘要，用户提问时将最近的文字历史和当前视频帧一起送入模型；服务端用有限 FIFO 缓存保存会话历史。这可以作为“连续视频输入 + 时间记忆”的参考，但它是文字摘要记忆，不是持久 3D 场景图。

## 与本项目需求的差异

- 没有发现深度图、相机位姿、SLAM、立体标定或对象世界坐标实现；因此它本身不能解决“物体在用户物理空间的哪里”。
- 模型是本地 CUDA/InternVL 路线，不是调用 Qwen API；README 的模型权重下载脚本会占用超过 100 GB。
- 公开部署并不轻：Docker Compose 会拉取预构建前后端镜像；`clone.sh` 还引用额外的 GitLab 仓库。只拿到这个 GitHub 仓库，并不能复现完整在线部署。
- Docker Compose 内有硬编码的服务凭据。此副本没有运行；不要直接启动或复用这些配置值。
- 仓库没有明确的代码许可证文件。继续研究代码结构可以，复制代码进入产品前需先确认权利人授权或许可证。

## 初步结论

不建议直接照搬整套 Vinci，也不应把它当作具备空间建图能力的“具身模型”。可借鉴的是视频流接入、按时间采样、静默观察形成记忆、用户提问时关联当前帧与历史这几种系统设计。对本项目而言，更有价值的下一步是先把这些设计转成接口和回放实验，再单独验证 Android 深度/位姿提供的 3D 场景状态。
