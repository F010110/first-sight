# 直行误判、边界停用与重访诊断

## 直行误判旋转

确定的实现错误：`recoverPose`恢复出的旋转角>3°被直接当旋转证据，任一个方向报告旋转就否决全组。单目本质矩阵在平面、重复纹理、有限匹配下可能产生错误旋转解；这不证明相机真的转动，也没有通过纯旋转模型检验。val5第49、90步甚至有两个方向支持平移，仍被单侧否决。

修正：未经纯旋转验证的本质矩阵大角度解降为unknown；至少两个方向通过校准纯旋转模型、且没有平移支持才跳过；互相矛盾时unknown而非断言旋转。没有把高角度解强改成平移，没有降低视差阈值。

重跑 `run/sim/visual-functional-v2-val5/vo-rotation-fix-v2.json`：移动44→46/97，误跳过直行11→0/97；23个转动仍全部unknown且无移动误报。其余51次直行未确认，说明三视图利用不足仍存在，不能说移动检测已修好。下一步需要跨视图统一旋转约束和连续轨迹，而不是三个独立单目结果投票。

## 不可靠自动边界退出默认

`run_visual_memory_pipeline.py`默认不执行门框/开放区启发式，需 `--experimental-boundaries` 显式启用。弱视觉变化提案在核心pipeline只保留诊断，不再自动切段。保留明确外部边界证据的状态机、时间断档分段、人工修订、旧关联和失败结果，不做破坏性代码回退。

原因：两套实际样本0/11确认切换，当前模型没有资格作为默认区域判断。保留实验代码便于对照，不意味着继续采用其身份判断。未来重做时必须以接近/退回/穿越/透门看物的正负事件验收。

## val4 Oracle重访0/3的直接原因

固定人工边界和相同视觉证据，检查第5→3、第6→2、第7→1片段：

|回访|正确历史候选视觉链接≥0.4|独立几何链接|匹配锚点|
|---|---:|---:|---:|
|5→3|33|0|7|
|6→2|36|1|7|
|7→1|8|0|3|

正确候选已经被检索到，全部停在proposed，并非候选漏召回。当前确认规则要求两端至少两个独立结构锚点；0/1条几何链接不足，因此三个候选都没进入eligible，未进入最终历史竞争。

这暴露新matcher实质上仍依赖稀疏旋转几何支持：普通重访图像存在平移/遮挡，纯旋转验证不应成为唯一确认渠道。但不能直接取消验证，因为错误区域也有大量视觉链接，原基线仍有严重错绑。

建议增加双向、分布良好、多个时刻和多朝向的局部几何验证，适配平移视差；逐对原图审查正确与错误候选，测误绑/召回后再接入。不是提高相似度或取消结构门槛。以上是证据/规则诊断，不声称已经修复重访或完成全部原图盲审。
