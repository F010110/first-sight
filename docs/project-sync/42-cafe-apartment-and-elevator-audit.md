# 用户审核修订：CAFÉ、公寓楼与电梯黑帧

用户反馈：CAFÉ、酒吧及台球厅应是同一个地方；最后建筑像酒店/公寓；约第181帧的近黑画面不符合原游玩印象。本轮只读离线核查，没有启动游戏、重渲染、付费模型调用或改动原图片。

## 1. CAFÉ是同一场所

用户确认，加上第124显示帧（observation-000247-front）可清晰读取CAFÉ招牌；地图附近门实体名为cafedr1/cafedr2（约642,-3827及562,-3907）。因此将原“酒吧外走廊”和“酒吧/台球厅内部”改标为CAFÉ外侧走廊、CAFÉ内部（吧台/台球区）；后面的CAFÉ路口不是经过另一家咖啡店。外部和内部仍可作为同一场所的不同区域，不误合并整段街道。

## 2. 最后建筑更明确支持公寓楼

路线电梯XY约(-2532,984)，实际相邻实体：

- func_tracktrain `aptbld2ele`，model *131，origin(-2532,984,5500)。
- 电梯门/按钮`aptbld2eled*`、`aptbld2eleb*`。
- path_track `aptbld2elep1/2`，位置分别(-2532,984,5491)和(-2532,984,6341)。
- 随轿厢移动的light_dynamic父实体为`aptbld2ele`。

这比装修猜测更有依据，标为“公寓楼（地图内部aptbld2命名）”。未发现此入口可读的酒店品牌名。地图另有hotelele，但位于(2456,7540)，不是本路线最后这处电梯，不能因搜到hotel字符串就套用。aptbld2是内部代码，不当作官方楼名、街道门牌或准确房号。

## 3. 黑帧是样本生成问题的强证据，不是PNG损坏

显示第180/181/182帧，对应render frame359/361/363，源时间380.105/382.252/384.350秒。三摄亮度均接近全黑，第181帧各图平均灰度约1/255。

离线检查显示：

- 原JPEG与用于模型的PNG，解码后的RGB像素完全一致，排除JPEG→PNG转换损坏。
- 渲染summary是completed，未记录写文件/捕获异常；这不代表每张图的场景状态正确。
- 原始行走轨迹当时持续上升，脚底Z约5723→5985→6190，之后到达6272附近；处于与该公寓电梯停靠点一致的竖向运动区间。
- `first_sight_route_render.lua`只SetPos玩家并用记录眼睛坐标RenderView，没有恢复按钮动作、轿厢、门及移动灯的位置。
- 第180—182帧记录眼睛位置高于BSP初始轿厢顶约203/465/670 Source单位；静态世界叶节点contents为0（不在静态实心墙内）。

因此高度符合：原视点跟随真实电梯上升，而新渲染的轿厢/门/灯没有同步，视点进入暗井道，而非重建原始轿厢内画面。**缺少原始影像和重渲染每帧动态实体遥测，不能声称直接测得当时每个实体的确切状态**；也不能把这些图当作用户原来经历过黑暗环境的真值。

原件不删、不替换。标注将电梯区间注明重渲染动态状态异常，180—182逐帧加注样本生成异常；正常视觉/乘梯语义评测应隔离该区间，不静默缩小旧实验分母。将来要修复，应录原始三摄，或同步记录并恢复动态实体状态，不是仅靠位姿重渲染。
