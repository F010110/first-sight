## 已实现的并行：3个逻辑Agent，不是每窗口新建Agent

### B内分阶段

1. **独立提取**：不同窗口真正并行发起VLM请求，不读取全局记忆、不做最终历史身份判断。每窗口最多4观察/12图，允许乱序完成。
2. **持久证据层**：extracted_evidence单独保存，extraction_windows/members记录窗口、租约和状态。先完成后批不会越过未完成前批的语义关联；即使关联失败，直接证据仍保留。
3. **有序关联**：仅按窗口顺序领取，读取最新可用记忆版本，重用提取事实，不重新描述整批。首窗口无历史时无需额外关联VLM；其余窗口以末观察及少量历史原图作候选关联，不冒充确定地点身份。
4. 同步版本提交、证据截止时间及未来门禁仍生效。提取完成数量、水位和语义关联完成数量、水位分开报告。

### 调度参数

- 自适应提取默认1，积压至少4观察且最老等待≥8秒时可增到2；最终版15秒切换冷却。429/503/timeout异常回退1并保持30秒。参数为应用实验策略，不是供应商配额。
- 预备结果缓冲有界：ready窗口＋本地在途提取窗口最多3。原件及未启动任务仍在持久队列，有限算力不可能保证任意输入无限时间不积压。
- 总请求槽最终为5：A1＋提取2＋关联1＋C保留1。初轮4槽会让关联和第二提取争抢，因此单独调整。C的Planner和问答均经过保留槽的调度，不等待后台清空；其自身推理仍有延迟。
- 两个提取槽分别使用独立持久账本，避免并发改写同一provider计数。B总预算仍拆分为提取槽各32调用/USD0.10、关联64调用/USD0.10，总计128调用/USD0.30；A/C预算不变。停止/重启不清空账本。
- root持久标记parallel/serial模式，禁止混用两类writer；租约过期可恢复，旧token不能覆盖新结果。主要面向单协调进程恢复，不宣称多实例供应商全局限流已实现。
