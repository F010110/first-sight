## 实测失败，不能放行大测

- 正常仅**9/15交付**，6题执行失败；37分支仅9个交付，非正常22分支均未得到回答。
- 计划分母下开发效用19/60＝**31.67%**，仅5题效用≥3。此数包含执行/预算失败，不能称“模型语义准确率”，也不能只保留9个完成答案计算漂亮均分。原通过门槛失败。
- L03核验拒绝反复耗尽答题轮数，交付失败；核验对店外/进入关系提出了问题，但没有形成可执行的证据补齐路径。
- L07仍误认第二家店；核验器对错误的店铺序数和身份解释给出通过。没有实际事件覆盖，增加核验请求也无法凭空证明第几次进入。
- L09目标计划自行认定“最早店铺＝自助洗衣店”，核验器把计划当权威，反而拒绝早期另一店铺候选、接受当前洗衣店回答。**计划猜测→定向检索→核验接受同一猜测**形成闭环确认偏误，不是可靠核验。
- S27/S30核验也接受了后来被开发评分判错的历史目标。不能把核验器approved当正确性证明。
- S20核验反对澄清并促使改答近期设备，开发分为3；但原问题确有指代歧义，不将这一案例解释为核验器已掌握唯一正确指代。
- 请求体变大、重复核验增加费用和延迟；费用保守预留使后续请求在实际消耗未到子帽时提前拒绝。不能据此认证实时或大规模吞吐能力。

## 预算拒绝后暴露的基础设施错误

已在预算预检阶段先拒绝，并追加独立`budget-denials.jsonl`收据；不创建或占用下一个付费目录、不调用网络、不改变账本。新增重复拒绝/重开回归断言，完整469测试通过。该修复发生在第三轮之后，**没有把旧执行失败改成成功或付费重跑**。
