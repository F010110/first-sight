# 用记忆调查Agent替代直接locate答题路径

用户指出：寻找“出地铁后的第二家店”应翻阅记忆、确认离开锚点、沿后续经历数候选进入，再取属性；普通词项检索函数没有这种智能，不能直接作为目标已找到的记忆来源。接受该纠正，不再把失败主要描述为模型不肯正确使用locate。

## 运行路径已更改

`src/assistant/causal-context-question-v2.ts`的组织模式入口现在调用新增`memory-investigation-question.ts`，不再进入直接locate/facts或失败的目标计划/核验器路径。`verifyTarget`旧试验组合在新入口显式拒绝，不会偷偷复用locate。非组织化旧默认路径不变。

- **最终答题Agent**：仅有当前图/近期上下文，需旧经历时委托`memory.investigate`。不能直接调用locate/search/browse获取一组词项匹配后当答案。
- **记忆调查Agent**：独立的模型会话，接收原问题及标为未验证建议的调查需求，不接收最终答案草稿、私有答案/题号/参考图或未来事实。由模型主动选择翻阅与核查动作。
- 调查工具是明确的机械接口：`timeline`按时间分页抽样预览，`read`按时间范围完整读取连续原记录，`inspect`查看已返回记录的原图。没有任何工具声称理解“第二家”、店名、重复访问或跨经历身份。
- 候选片段只作时间导航元数据，不提供片段序号当进店计数；不按地图/离线标注构建访问清单。
- 对序数问题，调查报告需列锚点及有来源的候选过程、请求序数、属性来源和未决点。运行时检查引用完整读取、锚点不同且按时间排列、锚点至目标间是否还有未读已存事实。不能用抽样预览直接认证顺序。
- 报告是**本题模型解释**，不是已认证访问或物理身份；即使已读完已存描述，也不宣称采集/事件覆盖完整。真实漏采集和提取失败仍可能存在，未写回持久库以免污染历史。
- 最终答题Agent只接收报告及报告实际引用的原事实；调查Agent看过原图不等于答题Agent看过，若要作为直接视觉引用需在答题环节inspect。

例如“出某处后的第二家店”现在的职责划分是：调查Agent查离开锚点→读取后续记录→排除仅见店面/连续多帧→核查候选进入过程→读目标内景→交付带来源与未知项的报告。这个过程由Agent推理，不由一个改名的词项函数伪装完成。

## 边界与保存

- 每题最多一次调查（失败也占次数），调查最多20轮、答题最多6轮，共最多26次模型请求，仍共用原调用/费用账本。没有自动授权新增费用。
- 工具读页最多24条，预览每48条抽取少量真实描述，原图窗口最多3份旧观察；调查请求历史按字符预算滑窗，并明确已退出多少动作，可用有界notes记录可修订工作假设。完整成功/失败工具轨迹另存audit，不把失败轨迹内容偷偷交给答题Agent当证据。
- 发生时间与知识可用时间双过滤，原事实与不可变快照逐项校验，时间排序独立于提交完成顺序。
- 旧locate函数/失败试验代码留作历史工具与回归测试，不是当前组织模式Agent可调用的直接来源。旧测试显式调用历史入口；新测试使用真实运行入口，防止测试仍走旧路。
- 没有修改旧库、旧运行或旧评分；没有新增付费调用、启动游戏、改服务或提交代码。

## 验证与不能宣称的结论

最新完整`npm test`：**474/474通过**。新增5项本地测试验证：

1. 真正运行入口拒绝直接locate，转交独立调查会话；先预览/细读，再报告候选顺序与属性。
2. 仅有预览不得当完整证据，序数锚点至目标间有漏读记录时不能标supported。
3. 晚到及未来事实不进入实际模型请求。
4. 旧核验模式不能绕回locate；调查失败不能反复重启，预算/提供者错误明确保留。
5. 持续无效动作被20轮边界截断，不无限调用。

这些测试使用脚本化模型响应，只证明接口、来源、流程与预算约束正确，**不证明真实VLM已经会可靠翻阅、计数或识别身份**。尚未为新架构执行云端语义评测，不借用旧分数声明改进。后续小样本应首先检查真实调查轨迹是否确实定位锚点、连续翻阅并核对候选进入，而非只检查最终答案和引用。
