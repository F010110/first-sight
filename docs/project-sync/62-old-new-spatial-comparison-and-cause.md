# 旧版与Pi迁移版空间记忆对照

用户要求始终与上一版对照，先厘清架构与提示词责任。本次直接对照同一批原图、旧版冻结L01快照、Pi完整v1、仅提示修改prefix90-v2、独立当前观察prefix90-v3。不是不同素材的分数比较。

## 数据流差异

旧版`three-agent-factory.ts`的batchMax=1路径独立检查本次三摄，不传历史，生成sourceBoundDescription；关联解释不决定原始观察事实。Pi首次迁移将全历史session、当前图和observations/hypotheses/unresolved一起交给一个持续调用生成。迁移保留了来源ID限制，却没有保留“历史不能参与改写当前直接观察”的语义隔离。

因此当前主要是迁移数据流边界回归，并非Pi会话机制天然错误；提示词不能代替原有隔离。提示词对过期状态维护也有影响，但只改提示实测未稳定修好。尚无只改一个变量、重复多次的受控消融，不能将“模型内部注意力被历史压过”当成已证明的内部机制。

## 旧版也存在的问题

旧版问答端已出现熟食店等错误身份、店面与进入经历混淆、用当前场景代替过去、漏查证据。它不是金标准。旧版主要保存独立观察，没有同款逐帧hypotheses/unresolved字段，不能用“旧版没有重复字段”冒充旧版全局空间推理更好。

新迁移明显新增的风险是持续生成的状态/假设反过来影响当前观察，及旧未决事项跨场景原样保留。恢复独立观察是在恢复已有架构约束，不应描述成harness迁移带来的新能力。

## 后续比较要求

- 每个候选版本继续保留同源旧版、上版、候选版的对应记录，核查变好与变坏两类案例。
- 分开检查当前直接观察、空间/身份关联、活跃状态更新、压缩、问答检索，不合并成一个成功率。
- 单元测试与结构审计通过不意味着语义改善；短测改善也不替代完整重跑审查。
- 现有v2全量任务继续完成，完成后对照旧版再判断；有空间缺陷先修空间Agent，不启动问题评分或90题扩大测试。
