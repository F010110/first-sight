# 冻结空间输出后的跨模型评审与争议仲裁

用户要求先改进裁判，不再用旧Qwen同家族单次评分直接指导空间修改。本轮只读取已完成continuous60的固定预测和原图，绝不重跑记忆、修改原始输出或把评审反馈送进空间agent。

入口：`node dist/current/sim/evaluation/review-spatial-ensemble.js FROZEN-RUN NEW-OUTPUT --confirm-paid`。
首次执行输出：`run/unioncity-spatial-ensemble-review-v1/`。

## 机制

1. 从已校验hash的检查点提取固定事实ID；观察保留摄像头标签，三个摘要仅在确有三段时绑定front/left/right。不让裁判自由生成原文quote。
2. 第一轮由`openai/gpt-6.1-terra`与`google/gemini-3.1-pro-preview`分别盲审，同一原图、同一固定事实，互不可见意见，也不看旧Qwen评分。
3. 分歧事实或≥2分评级差距交`openai/gpt-6.1-sol-pro`看原图仲裁。仲裁时能看两份意见，但明确它们不是事实，不能机械多数投票。记录初始两模型一致确认与仲裁确认的区别。
4. 输出supported、contradicted、unverifiable。只有contradicted才构成确定负面候选；遮挡/暗处和无法核实的用途推断不按明确相反事实处理。微小黑灰、灰白、网格近义差异不应扣分。
5. 所有事实必须在checkedClaimIds中出现，issue只能引用实际ID，必须有摄像头和可定位图像依据。格式最多重试一次，所有失败保留。缺失评审、未解决争议和不可核实项单列，不强行变零或判正确。
6. 正式评分前，两个模型各做6个原图明确正反例：71的绿桌/货架，89的门开/关，101的街道/室内。expected不传给裁判。这只是必要的sanity check；若失败，不启动全量60项复评，不偷偷退回弱模型。

## 审计与限制

- OpenRouter模型目录实时验证模型存在且接收图片，保存模型目录、价格字段、requested/returned model、provider、原始响应和用量；不硬编码一个看似更强但无法确认的模型名。
- 专用只读评分适配器，独立密钥与调用账本，每张PNG原图校验hash，最多24张，不改空间生成或答题适配器。未知网络请求预留保留。
- 并行独立模型有独立请求目录，账本写入串行化，防止覆盖或误计。
- 新报告保留逐模型评级范围、争议项和确认依据；旧v2/v3报告不改写。归一化有序评分不叫准确率。协议通过不等于事实正确，多模型一致也可能共同误读。
- 两个局部连续正例仍不是长期召回测试；本轮不添加新用户题，不运行90题，不生成813帧全量。

针对性测试覆盖：真实ID与证据校验、缺少一份意见不能确认失分、单模型指控不能确认、仲裁可撤销误判、并行请求来源/账本隔离。首次针对性测试3/3通过。

## 结果报告应回答的问题

运行完成后先列有图像证据的已确认失分点，再列分歧/无法核实，不以之前的单模型指控代替确认。未测能力至少包括：远距离重访、长干扰序列后召回、完整路线压缩与恢复、全局地图/几何定位/路径连通与导航安全、真实用户问题及原15题/37分支门槛。

未来两片段方案：第一段完整连续积累，保存来源状态；第二段在时间上相隔较远且包含可人工确认重访。是否省略中间经历必须明确：省略只能测试跨时间稀疏记忆；验证真实长程干扰和遗忘则必须保留完整中间前缀，不能用“两段相隔很远”冒充经历了长干扰。验证单元应为冻结完整前缀+第二段连续后缀，标注建立在原图而非agent输出上。
