# 为什么没有定位到：采样、吞吐、检索与数据适配核查

## 核查范围

仅分析已有源视频、2033张采样图、原生baseline的SQLite/993次建忆调用及v3问答记录。额外提取3个源片的6秒、每秒4张原分辨率诊断图，不调用模型、不训练、不新增下载、不修改原始分数。

先前将“归档每2秒一帧”直接理解为系统的有效观察密度，不够准确。**用户关于慢模式可能跟不上短事件的怀疑有直接证据，但瓶颈主要发生在建忆吞吐，而非所有2秒归档图都不存在目标。**

## 1. 三种密度必须分开

|层级|实测|
|---|---|
|原片|20fps，1408×1408，带AAC音轨|
|归档/模型准备|约每2秒1张，共2033张；640×480 VGA，方形有效画面约480×480|
|实际建忆|90张，约占归档4.43%；相邻被建忆图像的源时间间隔中位44秒、P90 64秒、最大142秒|

从被选中图像的采集时刻到判断完成，中位46.65秒、最大142.16秒；前/中/后各30次观察的中位延迟约20.49/46.65/61.51秒。

实际建忆使用993次模型调用：92次perception（含协议重试）、887次全组成员页面比较、14次其他建忆调用。**约89.3%的建忆调用用于历史组页面比较**。`FixedScopePlaceGroup.plan`每页最多3个成员，已有候选组成员增加会增加单次观察的比较页数。

与此同时，真实`LiveFramePolicy`是容量1最新帧队列，模型忙时覆盖旧待处理帧，原图仍归档。用于“最新状态”的机制导致短事件无法保证进入可检索记忆，不能把有2033张原图说成已经理解了2033张。

## 2. 一个可直接观察的失败链：二楼短暂到访

第2/3题的官方目标在11:24:44附近。

本地2秒采样对照可见：

- 11:24:34–40：上楼过程；
- 11:24:42：进入楼上房间，能看到桌面；
- 11:24:44：红色桌面及场记板清晰进入视野；
- 11:24:46：手持场记板；
- 11:24:48–50：转身离开房间；
- 11:24:52：下楼梯。

**2秒采样并没有把整个到访漏掉**。但baseline在11:24:00处理了一张纸箱遮挡图，直到约11:24:52.57才完成；随后的最新可处理帧已是11:24:52的楼梯。11:24:42–50的到访没有逐帧进入建忆。

楼梯图的空间perception确实提到了手边场记板，但明确无法确定楼层；它不能回答物品此前在二楼桌面。上楼房间的短暂事件没有进入结构化索引。后续Agent搜索clapperboard命中了楼梯，随后用后来会议桌画面回答此前位置。

因此这不是纯粹猜测“快速移动也许有影响”，而是可追踪的链条：**短暂到访 → 原图已采到 → 空间比较仍忙 → 最新帧队列跳过到访 → 只记录楼梯上的物品 → 历史位置检索失焦**。

仍不能据此断言2秒对所有动作足够：原片到2秒采样降了40倍，亚秒拿放/遮挡可能丢失；本次未做全题密集帧语义oracle实验，不编造采样上限分数。

## 3. 慢建忆不是唯一原因：Agent浏览也没有推进

v3 10题中，只有第3题实际看过距标注时刻10秒内的图，其余9题连30秒范围内都没有看过。即使原图已归档，最终取证也没有补回建忆漏掉的时段。

两个具体行为：

- **第2题**：第一次全局uniform浏览760帧，只返回11:09:42、11:18:08、11:26:34、11:35:00四个时刻。约8秒的楼上到访处在这些大间隔之间。模型之后转去11:33:50–11:35:00，没有沿“离开桌子/上下楼”细化到目标事件。
- **第10题**：多次用同一早期时间范围、chronological、默认cursor=0浏览，反复拿到范围开头4帧，没有遍历后续。工具未建立可靠分页进度/已查看时段闭环；现有防重复主要覆盖search，并没有解决重复browse。于是它没有推进到11:26的书写过程。
- **第9题**：模型把“just helped”局限为发问前几分钟，实际官方目标比问题早约35分钟；它浏览最近窗口后便猜人物组合。EgoLife是长记忆题，不能把自然语言中的just机械等同于最近一分钟。

所以“有自由浏览工具”不等于已具备有效长历史定位能力。固定4张全局抽样、稀疏地点摘要和反复首页，不足以找到短暂事件；更换提示词或增加最终审查不能补回这一缺口。

## 4. 记忆内容与题目目标不匹配

`groundFirstSpatialPrompt`主要要求地面、墙门、边界、区域、布局及不确定性。90次空间判断没有可靠维护“物品身份—此前位置—人物动作—对话—时间”的事件索引。第9题标注时刻附近的帧确实完成过建忆，但输出仍是房间、相框、三脚架等布局，不是整理花事件。

即使提高空间建忆帧率，若仍只输出空间边界，也不能自动获得谁帮谁、谁先写、谁计划做什么的记忆。**空间识别的吞吐问题和生活事件表征缺口是两个不同问题。**

## 5. 这批题是否适合当前模式？

官方前10题中3题标注需要音频、9题标注需要名字；按官方字段，没有一题同时满足“不需音频且不需名字”。这不表示每题都绝对不可能视觉作答，但证明它不是当前仅RGB、无额外身份映射模式的合适首批代表集。

原片确实带音轨，而模型只收到图像；原片顶部A1_JAKE是佩戴者标识，并非所有参与者的人名映射。不能让人看有声原片后的理解，替代模型实际接收的输入。

EgoLife全部500题中，官方标为无需音频和名字的有102题（EntityLog50、EventRecall33、HabitInsight15、TaskMaster4）；DAY1有10题，首题ID19发问在13:19，超出本次已下载前缀。未来可以预先按能力条件冻结官方子集，但必须补齐历史输入并明确新协议，不能事后只挑已答对题，也不能超出现有下载授权自动扩数据。

结论：**这10题不适合代表当前纯RGB低吞吐模式；不能由此宣布整个EgoLife不适合。**其短动作/短到访暴露的吞吐问题，也会发生在真实日常拿放物品场景，不能都归咎于数据集。

## 6. 分辨率、视角和时间精度的边界

- 单摄不是本轮新增的输入不匹配：被测实时系统本来只建模前摄。单摄遮挡和快速转头是真实限制，多摄也不会自动补上事件索引或缺少的音频。
- 方形1408原图压到有效480方形视野，约损失8.6倍像素面积；小马克笔/板书和打码人脸更难识别。这是实际输入损失，但未做独立消融，不能给出它导致多少错题的百分比。
- 源片画面有HH:MM:SS:FF样式时间，QA末两位也存在不统一取值。本轮沿用先前冻结的亚秒换算，没有在诊断中改分数；其格式需要单独核实，不能把此前80ms等数值当作已认证的绝对亚秒精度。上文11:24:42–52、44秒建忆间隔和分钟级检索错位不依赖该亚秒解释。

## 7. 能下什么结论、不能下什么结论

**已证实**：建忆有效观察远慢于2秒；短暂二楼到访被最新帧队列跳过；全历史盲浏览及分页没有可靠推进；空间表征不包含所需事件；首10题有明显音频/身份输入缺口。

**尚未证实**：2秒采样理论上最多能答对多少题；给完备正确序列后当前VLM能答对多少；仅增加摄像头/提高分辨率是否能显著提升。这些需要控制变量实验，不能凭猜测报结论。

合理下一步是先冻结输入适配的官方题，并分别测“证据片段能否定位”和“定位后能否回答”；建忆应将最新状态处理与不可丢弃的历史事件索引分开，避免让昂贵空间全组比较阻塞生活记忆。不再先堆最终审查掩盖检索/输入缺陷。本次未实施新算法或新的付费运行。
