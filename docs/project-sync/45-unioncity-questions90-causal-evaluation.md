## 本轮实际测什么

- 原有fact-first单源描述提取、两worker、持久SQLite存储继续使用。
- 新增显式opt-in `causal-context-v1`问答策略，默认生产行为不变。现有旧问答会全历史预检索，不能据此验证context/长期memory分层，因此本轮换成明确隔离的新问答策略，不把它说成未修改旧产品的端到端验收。
- 每次回答初始只给当前三摄与过去60展示秒的、独立于题目生成的事实context；不提供全历史摘要。固定窗口最多61条，不由评分器按题挑事实。旧事实仍在持久库，仅模型主动memory.search/browse后才交付；memory.inspect必须针对工具已返回的记忆引用。
- 答案分别引用当前已看原图、已交付context、已检索memory。发起查询、返回条目、真正交付、最终引用分别留痕。引用本身不是因果依赖的证明。
- 同时刻问题串行、独立问答分支，不继承前题答案，也不把题目答案写进共享视觉记忆。分支共享当时自然观察形成的同一持久状态。
- `questionForReplay`要求尚未输入任何未来观察，按源/播放时间调用，不用墙钟新鲜度把离线问题误判过期。每个问题前等待已输入观察完成，不填未来批次。本轮为暂停式语义验收，不是实时压测。
- Planner、语音、UI交付和真实连续行走安全不在本轮验收范围；模型家族固定qwen3.8-flash、thinking关闭。

## 报告规则

当前/短期/长期各30题质量分分别保留，不只报总平均。短期额外报告核心事实实际context覆盖与是否另查持久库；长期额外报告初始context污染、真实检索返回/交付/引用与支持程度。context未覆盖是提取/截断缺口，不能私自填标准答案；长期知识仍在context时不能算长期成功。

单独记录执行失败、评分失败、严重误导、一般实质幻觉、证据覆盖不足和时延。正式题目不因失败移出分母。初始context污染由语义审查判断，不能仅查源帧时间；重访可能将同一知识重新放回context。

### 机制归因补充（日志已核查）

- `input-audit-v2.json`额外记录最终引用通道。S题24题引用context，另5个交付题（S02/S07/S15/S25/S29）仅引用原图、未引用context或memory；即使近期context包含答案，也不能把这5题直接宣称为已证明使用短期context。S26还发起过持久工具调用，需和context-only路径分开。
- L03确实从近期375—377秒的再次经过店面描述读到了五金店招牌，未查持久库；它有重访带来的实际context再暴露，不能按长期题答对计长期路径成功。
- L13引用的旧memory是29/33/34秒站内图，回答却复用了677—695秒近期熟食店描述；存在“查过库但证据无关＋近期场景替代历史”的具体证据，不是仅推测。

- 新问答prompt的JSON工具示例含固定`beforeMs:123000`。L07/L13/L21/L23等多次照抄该边界，可能把目标时段排除在检索范围外；L23实际只检索到113/118秒街景。此为本轮检索策略/提示实现局限，不能据低长期成绩断言持久存储本身完全无能力。下轮应移除可照抄的时间示例、由工具公开合法边界，但本轮不修改代码/提示后拼接重跑。
- 评分器的`contextOnlyQualified`字段表示“context覆盖且未查持久库、语义得分达标”的兼容路径判据，不是因果证明，也未强制最终contextRefs非空；最终报告必须同时展示实际context引用通道，避免将其误称已认证context使用率。

### 为什么不将自动分数当最终结论

- C30：实际答复附加“可以直接走进去”。原图只支持右侧敞开入口，不证明通行条件安全；助手按冻结门禁认定至少1次无依据直接通行建议，而自动裁判给4分/harm=none。原评分不覆盖，复核单独记载。
- L03：自动理由明确承认近期context已包含店面信息，却将initialContextLeaksCore置false；至少该题存在重访再暴露，不能接受“长期污染0题”的自动结论。
- S14/S24等：自动理由说context存在核心信息，却给context覆盖false。S27/S30的context也保留了正确旧信息，错误回答不等于context未覆盖。因此自动22/30覆盖数不能认证。
- S20只重复问题却得1分；S28未明确比较关→开，裁判理由却说它已比较；L05/L16等的错误额外身份信息被忽略。
- 反向也有不合理扣分：C01未附长免责声明、S07只给一个正确地标（公开题干并未要求两个）、C15未主动对比车库，不能因为私有参考多写了要求就苛扣。
