# 160°广角采集的软件准备

采购暂称OV2460/160°；准确模块型号、镜头投影、分辨率以及160°是水平/垂直/对角视场尚未确认。不能从传感器名称推断镜头内参或畸变系数。

## 已实现的模拟入口

`sim/render_side_views.py`保留默认90°针孔渲染，新增：

```text
python sim/render_side_views.py EPISODE --house HOUSE --output NEW_OUTPUT --fov 160 --projection pinhole
python sim/render_side_views.py EPISODE --house HOUSE --output NEW_OUTPUT --fov 160 --projection equidistant-fisheye
```

实际AI2-THOR渲染仍需原WSL模拟器环境。160参数是正方形针孔图像的水平/垂直视场，鱼眼输出是圆形有效区直径对应的视场；不是对真实160°对角镜头的校准复现。

鱼眼模式从广角针孔渲染进行等距投影重采样，圆外黑边附带`valid-pixels.png`；所有配置写入`camera-model.json`。它改变投影，不能从旧90°图片补出不存在的侧面。大视场源图中心像素密度低，重采样可能导致中心细节不足；需高分辨率/多面渲染改进后才适合严肃数值对照。

本轮仅提供可运行软件入口及投影单测，**未实际运行新的THOR路线，未得到广角算法成绩**。原录制、评测及90°默认输入不变；仿真相机仍同光心，不能模拟头盔三摄的基线、曝光同步、动态场景或真实镜头像差。

## 边缘影响与处理原则

- 广角边缘的几何畸变可使直线弯曲，破坏当前针孔VO/单应性拟合；边缘模糊、暗角和色差会进一步降低关键点匹配。广视野也可能提供更多关联，收益必须实测。
- 当前`three_view_vo.py`对带新模型声明的非90°针孔数据要求显式内参；对原始鱼眼拒绝执行针孔VO。避免把畸变造成的残差误判为移动。
- 到货后每个相机独立拍标定板，确认针孔径向模型还是鱼眼模型，保存原图及模型/分辨率/有效区。指南针不解决光学畸变。
- 几何处理建议先校正或按标定射线转换，再使用受支持的模型。校正后的图须使用新内参；不能沿用原焦距。
- 160°全幅一次拉成透视图会强烈拉伸边缘，可比较保守中心视场与多个较窄的虚拟透视视图。虚拟视图来自同一实体相机，不能冒充独立相机证据。
- 黑边/无效区需要显式遮罩，不能作为稳定视觉特征；只裁掉边缘是一种对照，不是完成镜头校准。
