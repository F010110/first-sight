# 头盔数据接入预留（schema 1）

当前硬件方向：头盔前/左/右三摄，可选后摄及方向传感器。头盔只采集；图像处理、空间算法、记忆和其他功能全部在电脑端执行。传输接口和具体硬件尚未确定，本阶段不实现驱动或实时接入。

`src/agent/helmet-capture.ts`提供独立类型与纯校验适配器，未来采集程序可按此结构写JSONL，每行一个观察，图像单独保存。保留recordingId、observation id、统一clockId、各相机ID、方向、帧路径及采集时间。接入程序必须保证ID在目标记忆中唯一，并保持录制顺序；适配器仅校验单观察，不验证文件存在或跨观察时钟连续性。

时间使用录制统一时钟的毫秒，不要求UTC。每帧标明曝光/估计曝光/电脑接收时间来源。只有明确曝光时间且满足调用者同步预算时才标为可用于三视图回放；预算尚不是设备验收指标。多设备时钟必须先对齐，字段相同不能证明真正同步。

输出`observation`兼容已有SegmentObservation，按front/left/right排序；必须先检查`eligibleForThreeViewReplay`再接入回放。原数据完整保留；第四摄目前只保存、不参与现有算法。未自动接入默认pipeline，不新增运动或边界证据。

方向信息可缺省，须说明磁北/真北、时间、可信性、不确定度与标定标识。`headingUsable`仅表示元数据满足时效与标定声明条件，不认证传感器质量，也不提供三维姿态。下一步需定义姿态坐标系、相机到传感器旋转标定和磁异常策略后才能连接已有旋转模块。指南针不直接生成位置、跨区域或历史身份判断。

检查：`npm.cmd run test:helmet-capture`。真实驱动、落盘/导入工具、跨观察同步、图像校准与硬件实验均未完成。参见[硬件鸿沟](research-application-gap.md)。
