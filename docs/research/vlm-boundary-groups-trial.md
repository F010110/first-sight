# 边界组/边界观察协议试验（test.3后续，2026-10-12）

用户授权单列边界组。新增独立`sim/vlm_boundary_group_trial.py`，不改冻结test.3默认算法/旧模型回答。复用此前Flash18张输入拼图的原始字节并检查hash，仍为18组、36代表三视图。输出接口及提示改变，不能声称是只改变一句提示的因果消融。

## 新协议

- `regions`：按主体证据聚合同区域组，每个主体组至少有一个实际非边界代表引用。
- `boundaryGroups`：纯过渡组单列，保存观察、原组及邻接区域索引。
- `boundaryObservations`：普通组中的具体边界代表单列，不把一张图的不确定性扩散到全组。
- `uncertainGroupIds`：主体仍不可判时保留未知，不强迫归类。

所有原组恰好一次归入主体/边界/未知。单图边界只能引用已提供代表，不能凭空给未显示图片分类。原图和原组日志不改；未显示成员暂时继承主体绑定，这不是逐图VLM确认。邻接只是关系说明，不授予导航许可。

固定44核心查询的计分中，边界输出转为null，算未正确识别，**不会把模型新称边界的核心图从分母删除**。另按旧13边界标签单独统计识别效果。

## 真实执行与结果

单次`qwen3.8-flash`、temperature=0、无自动重试，API返回模型同名，约112.4秒。标签只在模型完成后评分侧读取，未提供真实区域数；提示明确采用用户认可的开放生活区粒度。

|同44粗粒度核心查询|旧Flash整组协议|边界协议|
|---|---:|---:|
|正确|32/44，72.7%|44/44，100%|
|未知|12|0|
|错区域/重复新组|0/0|0/0|
|同区域聚合|78.4%|100%|
|跨区域错合并对|0/640|0/640|

三个主体区域：开放生活区16核心图、卧室12核心图、浴室16核心图。两纯边界组G13/G14分别为观察36/37（卧室—浴室门口）；两组内边界观察9/46（生活区—卧室过渡）。其他组主体恢复，不再因为9/46整组拒答。

边界单独评测：预测4张，旧开发边界标签匹配4/4，召回4/13=30.8%，误标核心0；漏边界3/10/11/18/19/44/45/51/52。部分漏例不在代表输入中，18/19等虽被显示仍直接绑定卧室，不能将低召回全归因抽样。9/46理由较偏生活区侧，不保证精确门槛位置。

因此100%只指44粗粒度开发核心查询，不是57观察全部正确，不是完整边界检出、独立位置概率或头盔可靠性。单次运行无重复性，代表选取和提示/接口共同改变的效果仍需独立验证。
