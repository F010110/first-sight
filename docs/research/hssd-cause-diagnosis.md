# HSSD结果原因诊断：输入、分组和代表压缩分开

诊断使用原数据/中间结果，不改test.5 prompt、分组阈值或既有预测；collector标签仅作事后诊断，不进入推理，不当物理区域真值。

## 已确认的链路原因

`src/agent/coherent-context-changes.ts`用当前段最早两点作old cohort，必须oldSupport/newSupport都≥0.4、四个跨cohort比较均≤0.1才切组；未切组则旧锚点不替换。这是**弱启动锚点使后续切组路径长期无法触发**的问题，不是几张照片不好看就能解释的。

第三例特征数并不少、后面有4个强相邻pair，但首对仍不合格，切组路径不恢复。独立boundaryEvidence及automaticBoundaryProposals此次都未提供；历史正锚点变化也依赖足够的双向多bearing证据，因此不能替代这条失败路径。没有切组证据时当前membership保留整段，物理scope并未确认；这个默认在复杂多空间路线中可能造成过度合并，不能当“记忆已正确建立”。

`sim/diagnose_hssd_evidence.py`重算所有query方向的相邻3×3 SIFT矩阵，保存`run/hssd-six-v1/evidence-diagnostic.json`。另发现matcher每个candidate只返回最佳query，而组输入builder按query方向累积，可能丢弃其他有效方向；但相邻pair的完整方向诊断仍为0/0/4个强pair，首对仍全部不足。这是额外接口风险，不是本次三例切组失败已验证的主因，也未改变原cache。

## 输入和采集因素确实在加重问题

原HSSD三例灰度均值53.6/31.9/48.2；旧THOR val5的120原panel均值136.7、SIFT中位数111。HSSD第三例SIFT反而182，故不能简单说所有HSSD图都没有信息。320px、大片弱纹理暗墙、部分转向仅看到墙面/近物体，降低了双向多bearing证据的可用性。

观察间隔2秒，首对实际转向分别−84°/−96°/−90°，相邻观察最大转向132°/132°/123°。虽然视频确实24fps逐帧渲染，VO只用2fps原三视图，分组观察约0.5Hz；平滑视频不等于推理拿到密集可关联证据。转动及低纹理叠加，使VO大多保守未知。VO未知不是不同区域证据，不能为了切组把未知强判成移动/跨门。

Habitat0.3.3配置默认`scene_light_setup=no_lights`、`override_scene_light_defaults=False`，我们的采集器未明确设灯光；HSSD初始化还报缺省lighting layout fallback。它是接入配置风险，不能把画面质量直接归因于HSSD原始资产低质。独立同机位原配置/显式Habitat default灯光对照已完成（`sim/diagnose_hssd_lighting.py`，`run/hssd-lighting-diagnostic-v2/`）：办公候选前两观察灰度31.1/29.3→35.2/33.0，仅有限提高；原配置重渲染与原JPEG平均像素差0.79/0.84，验证机位重建基本一致。SIFT正面53→74、75→100，但整对双向多bearing置信度**两种配置都为0.117，仍不过0.4**。这排除了“只显式打开default灯光即可修复首锚点”的简单解释；没有验证HSSD官方参考光照、材质或更高分辨率，不能断言它们不重要。v1诊断超过120秒超时，保留产物。不是重采或增强当前测试集，原输入/预测未覆盖。

## 组压缩让VLM无法完整发现混组

每组只给首/中/末最多3张代表，主体协议禁止拆组。当整段38–40点已合为一个大组，VLM只看3点而非整个视频，证据预算不足以排查中间发生的全部变化。

- 教室候选：原回答明确写“厨房与走廊/卧室等不同独立房间，属于混组”，G01未知，是对输入混组的弃权，不是请求失败。
- 办公候选：首点和末点为同一办公区回访，中间代表为走廊；它未看到中间另一个办公区、休息区、厨房的示例。模型却写“观察者始终位于该办公室内部”，这个全组范围断言超出了3张图的证据，需要人工核查，不能计为成功。
- 会议候选：模型认为同棋盘格地面/开放连通生活区；有功能区标签不同并不能自动否决这个合并，开放功能区可能确属同一具体空间，仍需物理scope审核。

上述差别解释为何同样1个局部组，有的全未知，有的全部绑定1区域。不能用“不未知”替代正确，也不能直接把每个模拟功能polygon当独立房间。

## 应修什么（本轮尚未实施）

1. 先验证渲染照明/纹理/机位，采用明确的环境配置和分离的画质验收；保留原版本与失败。
2. 改局部组初始化/正锚点更新，使失败的开头两帧不会永久阻断后续候选切组，同时保持缺失证据不是负证据、可撤回、原时间戳/历史检索不破坏。不能只盲降匹配阈值。
3. 对大组增加内部异质性检测与更多分布代表/原观察审查；不能只用首中末推断整组，也不能让附注直接改主体身份。
4. 在独立新版本做固定输入对照，先以人工确认的具体空间/连续房间与边界评估，再测修复效果。不覆盖本轮原预测、丢弃未知/失败或改分母。

结论：**输入/渲染接入问题＋局部分组在弱证据下的失败策略＋大组代表压缩盲区共同作用**。已有充分证据说明不是单纯HSSD场景复杂或数据源质量差；也不具备断言HSSD原始资产本身坏了的证据。
