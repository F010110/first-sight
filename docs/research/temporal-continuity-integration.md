# 时间连续归类实际接入与失败验收

## 本轮修复的实现问题

旧实现用时间邻居佐证单张视觉关联，而`effective()`仅返回旧视觉节点。结果是历史匹配失败即当前归属null，时间片段没有进入实际归类输出。

现在`VisualExperienceMemory.observe()`返回的`grouping`是主时间归类结果，`memory.grouping()`查询此结果；每个连续前缀先有临时组，不需要先认出历史身份。`effective()`明确保留为旧视觉身份兼容接口，不用它冒充新归类评测。

流程：观察追加→保留原视觉证据→形成当前连续候选组→有上下文变化证据时修订分段→整个候选段做历史匹配→记录归属、历史状态及实际输出修订。当前组身份为`unrecognized`时仍保有观察归属；历史匹配到一组时合并经过支持的经历段，不让其中多张帧各自作为不同身份竞争。

## 不依赖完整穿越的变化路径

1. 已支持的双向多方向视觉锚点变化：支持局部上下文变化，不能证明物理区域改变；单方向旧促成不能作为正锚点。
2. 持续上下文队列：旧两观察有正向多方向重合，新两观察也有重合，四个跨队列实际比较都弱才提出可撤回切点。缺比较、孤立失败、不够队列支持均不切。这是弱上下文证据，不冒充几何穿越；固定沿用视觉支持0.4/弱0.1，未针对留出集调参。
3. 正面的同组矛盾可产生候选切点；缺匹配不是矛盾。历史身份拒绝只否决历史关联，不自动证明一个空间切换。
4. 断档隔离时间上下文；转动/未知运动不丢当前归属，不自动算静止/不同地点。没有VO支持仍可判断上下文候选，不能据此宣称移动或穿越。

每组标明provisional=true、physicalScopeVerified=false、navigationAllowed=false。缺变化证据仍可能过度连续，必须由正式评分揭露；禁止覆盖100%就宣称地区正确。

## 完整保留与修订

原视觉关联、图像、时刻、对象查询、拒绝与修订不删改。`searchGroupObjects`按新当前组过滤真实有日期的历史观察，不声称物体当前在场。`groupingRevisions`保存实际输出历史，不用最终基线重算旧前缀；加载校验唯一归属/前缀/未来图像/安全状态，坏包不改变内存。旧包缺新历史时允许导入；原包仍保留原策略。

在线追加错误会原子恢复原关联、解释与新分组输出。显式历史拒绝会重新解释并撤回错误历史合并，但不会删除当前观察归属。

## 实际测试与不足

`src/sim/temporal-grouping-replay.ts`是新的实际prefix归类回放，从空记忆逐观察运行，仅读window终点、缓存图像匹配与已有局部几何，不读取人工label/动作/坐标。当前输出`run/sim/temporal-current-val4-v3.json`与`temporal-current-val5-v3.json`。不是重新提取特征的手机在线性能实验。

val4已有44图标签，正式结果`docs/experiments/temporal-current-val4-formal-v3.json`：

|正式指标|严格视觉关联原输出|当前时间归类输出|
|---|---:|---:|
|未归类|68.2%|0%|
|同区域聚合|2.1%|24.7%|
|跨区域错合并图像对|0/703|13/703|
|混合组|0|2|
|到达时旧组正确归类|0/16|17/40|
|到达时新组正确建立|2/28|1/4|

场景分母依赖历史组形成，必须同时报告分子/分母。候选归属完整不等于正确，两个混合组及18次旧场景错误归类意味着**正式判定不符合**。第一次仅连续+锚点变化的中间版本产生49个跨区域错合并对，补上下文队列后降至13；中间失败报告保留，不覆盖。

两套各57/40观察均形成当前归属，最终18/23个候选组；真实历史假设仍0个supported，不能用即时当前归属替代“认出历史地点”验收。两个旧视觉关联包和严格策略控制回放逐项相同。val5缺同规格全量标注，不发布伪正式分数。

测试：`test:visual-pipeline`61项、`test:memory`75项、正式标准8项通过（有重叠，不相加）。覆盖连续默认、历史拒答不丢归属、旋转/断档、正证据变化、候选集合历史匹配、拒绝撤回、前缀保存和坏包原子性。

结论：修正了“时间层只是旁路”和“历史unknown等于当前无归属”的架构缺陷；**尚未修好真实区域分组**。上下文变化过晚/遗漏仍导致混组，历史段的多锚点结构不足仍影响重访。不得把本轮实现验收说成算法可靠性通过。
