# 硬件与实测记录

> 本页保留首次验机结论。后续已完成[单摄空间记忆接入](./serial-integration.md)与[230400／460800串口提速验证](./serial-baud-validation.md)，不将下方原“未验证”清单视为最新状态。Wi-Fi、三摄、长期稳定性仍未验收。

## 设备识别

- 主板丝印：`ESP32-S3-CAM`；模组屏蔽罩标注 `S3-N16R8`。
- esptool 实读：ESP32-S3 QFN56 revision v0.2，40 MHz 晶振，16 MB Flash、内嵌 8 MB PSRAM。
- 摄像头排线标有 `2640`，用户提供规格为 OV2640 异面 160 度。视角未作标定，未记录传感器 PID 作为独立型号证据。
- 底座照片：`ESP32-CAM-MB V809`、MicroUSB，具有 `IO0` 与 `RST` 按键。
- 用户购买描述为 CH340 底座，但 Windows 实际枚举为 **FTDI**：`VID_0403&PID_6001`，串口 COM3。拔掉后设备和 COM3 消失，插回后恢复，已确认对应关系；不能仅按商品描述选择驱动。
- 供电和传输：电脑 USB → 底座 USB 转串口 → ESP32-S3 → 摄像头。未验证原生 USB 摄像头功能。

## 操作和结果

1. 115200、8N1 串口读到原程序 `led_strip`，为彩灯/USB 示例，无摄像头初始化服务。原程序不出图不等于摄像头损坏。
2. esptool 成功自动进入下载模式，读取芯片及 Flash 信息，无需人工按键。
3. 第一次 460800 全量备份因命令 120 秒超时中断；921600 重试在约 79% 时串口数据损坏失败。这两次均不能作为完整备份。
4. 460800 再次完整读取成功，长度 **16777216 字节**，耗时约 405 秒。
5. 测试固件编译成功，烧录区段均通过 esptool 写入哈希校验。
6. 首次显式以 QIO 启动参数烧录后发生 `ets_loader.c 78` 启动循环，尚未运行到摄像头测试。随后仅将 bootloader 头参数改为 **DIO / 40 MHz / 16 MB**，成功启动并采图。该现象是本次固件启动配置兼容问题，不是摄像头损坏证据。
7. 115200 串口连续接收三张 JPEG：18068、18017、18131 字节，均为 640×480。脚本检查长度及 JPEG 起止标记；第三张经图像工具打开查看。未声称三张都经过完整解码测试。

高分辨率、连续视频、实际帧率/端到端延迟、长时间稳定性、Wi-Fi、SD 卡、原生 USB、供电余量、镜头畸变/160 度视角、移动场景、模型效果、业务接入均未验证。不得将本次结果解读为这些功能已经通过验收。
