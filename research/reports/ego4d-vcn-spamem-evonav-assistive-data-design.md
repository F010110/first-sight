# 从记忆benchmark到视障生活记忆数据：补充核查与设计

2026-10-27。论文/官方文档/发布页静态核查；未下载数据、未跑模型。本文补充而非替代`docs/product/assistive-long-term-memory-data-plan.md`。设计建议不是已验证用户需求或已采集数据。

## 1. 四个来源：该借鉴什么

|---|---|---|---|

### 身份和发布边界

- Ego4D：[官方EM定义](https://ego4d-data.org/docs/benchmarks/episodic-memory/)、[官方实现](https://github.com/EGO4D/episodic-memory)。原生输出是视频定位，不是自然语言答案。优先借鉴证据标注与最后出现的定义，而非直接当产品验收全集。
- VCN：[全文v1](https://arxiv.org/html/2609.34687v1)、[官方仓库](https://github.com/siqiZ805/VCN-Bench)、[HF](https://huggingface.co/datasets/qqqqi/VSI-NavBench)。README可见数据采集/评测入口`run_collect_data.py`、`frontier_to_pixel.py`、`run_eval_mvdualvln.py`。本文未追完源码或本机运行。仓库标CC-BY-NC-SA 4.0，**商业产品不可默认直接使用**，MP3D与衍生数据许可也应单独核查。§3.1允许当前深度/位置/heading，不能因prior是RGB-only就说全系统无几何权限。
- SpaMEM：[全文v3](https://arxiv.org/html/2604.22409v3)、[公开subset](https://huggingface.co/datasets/mill-ct-liao/SpaMEM)。依前轮核查未确认官方核心生成/评测仓库；本文只参考论文构建法，不改变开源判定。
- EvoNav：[全文v2](https://arxiv.org/html/2609.08292v2)。本轮未建立官方核心仓库/完整数据发布关系，故只作论文层设计参考；不要混用EvoWorld-Bench/EvolvingNav同名近邻。

## 2. 为什么Tartan一类轨迹仍不合适

不是画面不真实就不能用，而是**轨迹真实性、生活真实性、需求真实性是三件不同的事**。机器人连续穿行可测定位/时间对齐，却未必有找东西、放下又拿起、返回熟悉地点、别名、停拍、纠正或多日重复。

本仓库已验的TartanGround ModernCity/P0001：1129帧、112.8秒首末跨度、约387.3米、平均3.43m/s；不适合作视障步行生活主样本。这里只针对已核查轨迹，不推断整个Tartan系列都相同。详见`docs/research/tartanground-trajectory-screening-2026-10-27.md`。慢放仅改变观看节奏，不改变原始空间采样、物理速度或生活行为。

建议停止把“再筛一条更长、更像住宅的视频”当主路径。保留现有素材作工程回归，主数据改为有重复生活、真实需求和可核验证据的采集；未授权任何删除或新下载。

## 3. 数据应有三层，不能拿仿真代替产品证据

### 层A：需求来源——先收集记忆困难，不先设题

以可访问访谈/语音日记收集“最近一次本来想问什么”：什么场合、已有何种定位/找物策略、哪些信息真能省事、是否愿意长期记录。记录成功的自助方式与根本不想使用AI的情况。

邀请盲与低视力参与者共同设计并补偿时间；记录参与者同意提供的经验、残余视觉、出行辅助及偏好，不收集无关诊断。不能假定视障等于记忆差，也不能假定所有人需要“蓝色门旁边”的提示。

参考[ASSETS 2024研究](https://arxiv.org/html/2408.13175v1)：先分析真实相关视频，再由盲/低视力及相关专业人士反馈修订需求。其六人focus group发现信息优先级和白杖能补足的信息存在分歧，**不能把一个小研究的偏好当普遍定律**；这里借鉴参与式构建，不复制90类检测任务。

### 层B：自然经历——同一人、同一环境、多次真实使用

以生活活动为采集指引，而非每步行为脚本，例如“回家后按自己的方式整理/准备出门”；不要求全屋巡检，不安排每个关键点停留正对相机。保留站立、坐下、回头、找错、途中中断、物品离开视野等普通片段。

允许同宅多日；首轮可试采3–5个实际日期、每天2–3个20–30分钟自选窗口，**仅为待确认的工程规模，不是统计样本量或全天覆盖**。是否现实/负担可接受先由小试采决定；未采到的时间作为空缺而不是合成连续流。

同时收集自然发问与事后提出的真实需求。自然请求不因无答案而删除；事后补充题单独标来源，不能篡改成当时真实提问。保证运行时只看到截止请求的历史，未来段只给评测侧。

### 层C：受控挑战——只补自然数据难以覆盖的失败

在同意下，增加同款物品、视野外移动、开关柜门、换朝向重访、路径变化等可复现案例。不给参与者制造危险、不为了测试让用户丢失重要物品。与自然请求分开报告，不能把人工“每天打乱房间”当真实生活。

自然需求轨负责“有用吗”，受控挑战轨负责“为何出错”；模拟器和Tartan负责时间/坐标/异常工程验证。三者不混成一个有效性分数。

## 4. 标注“可获得的帮助”，不只标物体坐标

每个query包含：

1. **请求与背景**：原话/时间、当前可见画面、允许使用的用户别名/陈述、自然或构造来源；
2. **证据**：截至当时的最后可见事件/实例候选、位置层级、路径实际经过序列、摄像空缺；
3. **世界与可知性分离**：有合法独立记录时才填世界当前位置；否则unknown。另一台标注相机/布置日志只在受控子集使用，不发送给模型；
4. **答案边界**：必要信息、可选信息、可接受多条路径、必须澄清之处、禁止断言；不追求唯一参考句；
5. **非视觉可用性**：该用户能使用的地标、身体/相机朝向、可触达位置、无需看屏幕的理解方式；
6. **实际交互结果**：是否找到/是否理解、追问/检查负担、是否被打断或取消、协助者是否介入。

物品位置层级可为“家→客厅→进门一侧矮柜→上层抽屉”；实际采用用户认可的名称，不强制所有环境有统一房间粒度。视觉地标不是绝对禁用，但不能只告诉全盲用户“去那边的红色东西”；系统应提供位置关系、可核验结构或请求观察，并标信息来源。未采音频/触觉时不得生成听觉/触觉真值。

抽屉关闭≠物品消失，走出镜头≠被移走，未检出≠不存在，用户说法≠视觉确认；最后一次可见、最后一次有证据的位置、当前仍在此处的可信程度分别保存。

## 5. 采集硬件的务实选择

先固定一种可获得且参与者愿意使用的佩戴方式；不预设必须三摄/深度/高精度地图。保存原始视频时间，分析帧率由预算另定。摄像机和IMU应有明确安装/外参与时间对齐；融合orientation、raw IMU和VIO分列。录音仅在同意且有需要时采集，不能因路线需求默认全天录音。

IMU是可检验的辅助输入，不是数据“像视障生活”的充分条件。先采到真实多日经历比先堆传感器更重要；有条件时从第一轮保留同步原始IMU以免之后无法补采。缺IMU的历史数据可以保留为RGB轨，不能造测量。

## 6. 评测先问“比现在少了多少负担”

- 记忆事实：实例/最后所见/来源时间/地点/路径正确；缺记录与歧义的拒答质量；历史当当前的错误率。
- 帮助质量：用户能否理解、检查了几个位置、需要几次追问、错误线索浪费多少时间、能否及时取消、不需要看屏幕。
- 长期：实际日期跨度、重复到访、距证据时间、变化率、跨session恢复、存储与检索成本；几分钟重复不能冒称多日。
- 诊断：当前图-only、近期窗口、简单图像/事件检索、长期记忆、长期记忆＋惯性。所有方法同一历史前缀与预算，模型版本固定；不故意削弱强VLM对照。
- 用用户现有做法作可选实用对照，按同意记录“找到结果/检查负担”，不能要求停用白杖或其他辅助设备。重复同一找物会有学习效应，采用匹配案例/平衡顺序，不能把第二遍更快全算系统收益。
- 数据回放先验收事实，真实可用性之后在合适监督、可访问接口和隐私措施下评价；“LLM裁判喜欢”不能替代用户受益。高风险错误单列，不被平均QA分数掩盖。

## 7. 最小可落地下一步

1. 先做需求访谈/可访问日记方案，确认找物与路线回忆中最有价值的具体情境；未获确认不扩功能。
2. 制作一个经同意的住宅式空间多日技术试采包，验证佩戴、自然行为、断拍、可核验最后所见和往返路径。健视采集只能称技术试采，不冒称视障行为分布。
3. 在采集前只规定覆盖维度，不透露未来具体题；收集后提出和审核请求，不删无答案请求。按时间隔离运行与真值。
4. 把“像生活吗、该用户能用这个回答吗、是否存在独立证据”设为收录门槛，而非画质/帧数门槛。
5. 参与者数据默认私有；公开脱敏benchmark是另一项授权。公开视频不自动有商业训练/再分发或隐私同意。原始住宅记录、派生索引、缓存、备份和删除规则都需预先明确。

当前推荐：**不再把寻找另一个现成大数据集作为前置条件；先做一个小而真实、多日、可审计、由用户需求驱动的数据包。** 本文仅作方案，未启动招募、采集、下载或付费调用。
