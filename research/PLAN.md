# 空间记忆、多摄与惯性误差鲁棒性实验计划

状态：2026-10-25 更新；当前执行流程见 [EXPERIMENT-PROTOCOL.md](EXPERIMENT-PROTOCOL.md)，其优先级高于早期讨论记录。以下为待验证计划，不是实验成绩。

用户最新决定：VLM 使用环境变量 QWEN_API_KEY / QWEN_BASE_URL 指向的 API，首选模型 ID `qwen3.8-flash`（已通过 /models 核实）。不部署本地 VLM；统一后端结果属于 API 适配配置，不宣称原论文模型分数复现。允许小规模接口验证；批量实验先固定调用数／token预算，无自动无限重试或自动切换模型。GPU 保留用于仿真、低层导航及其他必要计算。密钥不复制进仓库，不输出端点地址或错误响应体。

## 1. 研究问题与边界

1. 相同运动估计下，前／左／右观察是否比前摄提高记忆目标选择、证据召回及重访鲁棒性？
2. 视觉退化与 IMU 误差叠加时，多摄参与定位是否提供额外收益？
3. 收益来自覆盖、图像预算、定位质量，还是记忆组织？

不预设三摄一定胜出；“必要性”仅限给定视野、朝向、观察时间和资源预算的条件性结论。设置普通场景、侧摄无帮助场景、单摄主动扫描与等预算对照。

优先使用 3D-Mem 原生 A-EQA／GOAT-Bench（HM3D）做误差试验；FindingDory 保留为后续历史任务外部验证，不再是首轮前置条件。任何增加传感器、连续轨迹或改变任务的版本均明确标为扩展协议，不直接与原排行榜比较。

## 3. 阶段门槛

- S0 环境：记录 OS、Python、GPU／CUDA、磁盘、WSL／容器、现有 Habitat 环境；不改系统配置。
- S1 源码：保存上游 URL、精确 commit、许可、依赖和模型／数据需求；只读检查并做 Python 静态语法检查，不运行未知安装脚本。
- S2 环境冒烟：优先利用隔离 Linux 环境；先加载仿真器、渲染测试图、检查坐标／时间／深度，再运行官方数据加载与单 episode。
- S3 原生基线：保留原生模型、配置、题目范围和指标；若替换模型，只称替代配置运行，不宣称复现论文分数。
- S4 统一适配：输入契约、目标／证据输出、预算和低层执行器固定；每种适配保存差异清单。先少量空间检索／重访任务，再扩事件顺序类。
- S5 扩展实验：完成多摄采集、连续运动与误差模型单独验证后，进行配对试验。

任何阶段未通过均保留失败，不拼接不同版本前缀为完整运行。S0/S1 通过不等于 S2/S3 通过。

## 4. 统一输入与时间契约

- 每张图有真实相机 ID、采集时刻、内参与设备外参；不复制前摄冒充左右摄，不将拼图当几何全景。
- 初轮前摄 VIO 生成共享位姿；左右图按各自曝光时刻和外参关联。共享的设备位姿误差映射到三个相机，不能独立给三相机随机坐标。
- 位姿记录局部坐标系 ID、质量／失效状态、产生时间及版本；未完成重定位不得跨重置比较 XYZ。
- 真值仅用于传感器生成、oracle 对照和评测，不能进入一般方法检索／推理；检查 simulator metadata、GT object ID、navmesh 等旁路。
- 未来回环修正不得回填过去问题的可见信息。离线重建与因果在线实验分列。
- 第一轮固定真值深度以隔离位姿误差，明确这不是 RGB-only 实机成绩；第二轮统一估计深度。

## 6. 误差实验

分开两层：

1. 记忆压力测试：相对运动的相关漂移、尺度误差、丢失、重置；只能称“位姿误差鲁棒性”。
2. 原始 IMU 实验：连续 SE(3) 轨迹生成角速度与比力，加入测量白噪声、启动零偏、零偏随机游走、相机—IMU时间偏移／抖动与标定误差，运行真实 VIO。

IMU 与图像必须来自同一物理连续轨迹。离散跳步／瞬时转向不可直接求二阶导；平滑后检查速度、角速度、加速度及图像一致性。现有同光心三视图不能冒充真实三摄立体基线。

设置理想／预期／压力三级，最终参数由实际设备日志、标定与噪声分析确定；未标定参数仅为敏感性扫描。白噪声密度与采样率单位正确换算，随机游走按时间步缩放。固定并记录噪声种子，多个种子复测。

视觉退化：原地转头、相似走廊、低纹理、前摄遮挡／低光／模糊、侧面短暂地标、间断重访；单独因素与组合因素分别测。

## 7. 指标与统计

- 主指标：高层目标选择正确率、完整任务成功率（另列）、官方适用指标。
- 记忆：证据 recall／precision、错关联、错误肯定、拒答、历史污染和恢复时间。
- 定位：RPE／ATE（说明对齐方式及是否保留尺度误差）、跟踪失效与初始化失败率。
- 资源：像素／token、模型调用、运行时、显存、观察／转向成本。
- 配对单位是 episode／scene，不把帧当独立实验；记录噪声种子，按场景配对报告差值和置信区间。
- 先开发场景诊断，再冻结配置在未见场景评测；不得按是否有利于三摄选择测试样本。

## 8. 运行与证据管理

每轮保存 manifest：上游及适配 commit/hash、数据版本／许可、传感器配置、噪声参数／seed、模型 ID、命令、时间、预算、原始输出和失败原因。密钥只放忽略配置，不输出到报告。

使用用户授权的 API 小样调用，批量运行前固定预算；大型模型／数据下载及额外服务在明确资源需求后再启动。所有新增环境、下载和实验产物限制在本目录；不停止现有实时服务，不改冻结证据，不提交用户已有改动。
